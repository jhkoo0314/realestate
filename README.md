# 부동산 매물관리 도구

사무실 직원이 원룸·투룸 등의 매물을 엑셀보다 빠르고 안전하게 관리하기 위한 **사무실 내부용 프로그램**입니다.

고객에게 공개하는 매물 사이트가 아닙니다. 건물, 호실, 이번 매물 조건을 기록하고, 같은 매물을 실수로 중복 등록하지 않도록 돕는 도구입니다.

## 현재 구현된 기능

현재 **13단계: 데이터 저장 코드 기능별 분리**와 이후 계약 일정·오늘 할 일·광고관리의 코드 구현 및 기본 자동 확인을 마쳤습니다. 10단계의 전체 백업·복구·사무실 운영 검증은 사용자 요청으로 보류 중입니다. 각 단계의 실제 브라우저 업무 확인은 아직 남아 있습니다.

- 오늘 할 일, 매물 현황 리스트, 매물 등록·수정, 건물·호실 관리, 계약관리, 상담관리, 광고관리의 7개 메뉴
- 새 건물·새 호실·첫 매물을 한 번에 등록
- 건물명, 지번, 호수, 보증금, 월세 등 입력값 확인(건물명·보증금·월세는 비운 채 저장 가능)
- 저장 전 입력 내용 요약 확인
- 건물 → 호실 → 매물 기록 순서로 데이터 저장
- 기존 건물명 또는 지번 검색
- 기존 건물을 선택한 뒤, 건물 공통정보를 다시 입력하지 않고 새 호실 등록
- 같은 건물 안에서 같은 호수 중복 등록 차단
- `302`와 `302호`를 같은 호실로 판단
- 현재 매물의 조회·필터, 사진 보유 여부와 확인 업무 표시
- 사진 보유 여부가 `없음`이면 사진 촬영 필요, `확인 필요`이면 사진 확인 필요로 자동 표시
- 건물·호실 기본정보 수정과 매물 이력 확인
- 기존 호실의 최신 매물 정보를 같은 매물 회차에 수정하고, 연결된 계약·상담·광고 현황 기록 유지
- 현재 매물·계약·상담·광고 현황 기록의 명시적 확인 후 완전 삭제(영향받는 연결 기록 수 안내)
- 공동현관·방문 비밀번호의 별도 확인·수정·삭제
- 매물 회차별 일반·단기 계약의 계약 진행일·정식 계약일·임대차 기간·상태 누적 관리와 계약 일정 조회
- 계약금 전체·가계약금 수령액·추가 수령 예정일·잔금 예정일 및 미수령액 표시
- 매물 상담·일반 상담의 이력·희망 조건·유입 경로·다음 연락일 누적 관리
- 매물·계약·상담 업무를 오늘·지연·상시 확인 필요로 통합 조회하고 엑셀로 내보내기
- 매물 회차별 당근·직방·네이버·직접입력 광고 채널 복수 연결, 상태·마지막 확인일 빠른 수정·삭제
- 매물 회차별 크린주택관리·삼성주택관리·한빛주택관리·국제주택관리·개인매물 또는 직접입력 보유처 관리
- 계약자·상담 고객 연락처는 목록에 표시하지 않고 상세에서만 확인
- 데이터 저장 코드를 업무별 파일로 분리하고, 실제 데이터 파일은 하나로 유지
- 매물·계약·상담 저장·수정·삭제 성공 뒤 OneDrive 날짜별 SQLite 자동 백업 및 무결성 검사

매물 현황 리스트·계약관리·상담관리·오늘 할 일에서 조회 결과를 엑셀로 내보낼 수 있습니다. 현재 매물 내부 업무용 엑셀에는 공동현관·방문 비밀번호와 내부 메모가 포함될 수 있으며, 개인 연락처는 포함하지 않습니다. 계약·상담·오늘 할 일 엑셀에는 연락처·비밀번호·내부 메모를 포함하지 않습니다.

메인 PC와 서브 PC의 Tailscale 연동, `127.0.0.1:8501` Streamlit 실행, Windows 예약 작업을 통한 자동 시작 설정은 마쳤습니다. 메인 PC 재부팅 뒤 자동 로그인·30초 지연 실행과 서브 PC HTTPS 접속은 실제 확인이 남아 있습니다. 사용자 PC에는 데이터 파일을 복사하지 않고, 메인 PC의 데이터 파일 한 곳만 사용합니다.

자세한 단계별 진행 상황은 [현재 구현 진행 상황](docs/current_implementation_status.md)에서 확인할 수 있습니다.

## 실행 방법

### 1. 처음 한 번만: Python 3.12 가상환경 준비

메인 PC에서 PowerShell을 열고 프로젝트 폴더로 이동합니다.

```powershell
cd C:\realestate-main
```

Python 3.12로 가상환경을 만들고 필요한 패키지를 설치합니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`streamlit`만 입력하면 Windows가 명령을 찾지 못할 수 있으므로, 아래 실행 방법처럼 항상 `.venv`의 Python을 사용합니다.

### 2. 프로그램 실행

프로젝트 폴더에서 아래 명령을 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

실행 후 브라우저에서 아래 주소를 엽니다.

```text
http://127.0.0.1:8501
```

프로그램을 멈추려면 명령 창에서 `Ctrl + C`를 누릅니다.

### 3. 허가된 사용자 PC 연결: Tailscale Serve

메인 PC와 사용자 PC에 Tailscale을 설치하고, 각 직원은 자신의 계정으로 로그인합니다. Tailscale 관리자는 허가된 사용자·기기만 승인합니다.

메인 PC와 서브 PC의 Tailscale 연동 및 Serve 설정은 완료됐습니다. 연결 상태를 다시 확인하거나 재설정해야 할 때는, 먼저 메인 PC에서 위의 프로그램 실행 명령으로 `http://127.0.0.1:8501`이 열리는지 확인한 뒤 별도 PowerShell 창에 아래 명령을 실행합니다.

```powershell
tailscale serve --bg http://127.0.0.1:8501
tailscale serve status
```

`tailscale serve status`가 알려 주는 `https://...` 주소를 허가된 사용자 PC의 브라우저에서 엽니다. Streamlit은 메인 PC의 `127.0.0.1`에만 열려 있으므로, 사용자 PC에는 SQLite 파일이나 프로그램을 설치하지 않습니다.

Tailscale Funnel, 공유기 포트 포워딩, `0.0.0.0` 공개 바인딩은 사용하지 않습니다. 상세한 작업 순서와 접근정책 예시는 [메인 PC Tailscale 연결 실행 계획서](docs/tailscale_main_pc_connection_plan.md)를 확인합니다.

## 데이터가 저장되는 곳

등록한 데이터는 아래 파일에 저장됩니다.

```text
C:\realestate-main\storage\real_estate.db
```

이 파일에는 매물 정보와 내부정보가 포함될 수 있으므로, 임의로 삭제·이동·공유하면 안 됩니다.

## 중요한 사용 주의사항

- 이 도구는 사무실 내부에서만 사용합니다. 인터넷에 공개하지 않습니다.
- 두 PC 운영 시에는 메인 PC에서 프로그램과 데이터 파일을 실행하고, 허용된 두 사용자만 Tailscale Serve 전용 HTTPS 주소로 접속합니다.
- `tailscale funnel`, 공유기 포트 포워딩, `0.0.0.0` 공개 바인딩은 사용하지 않습니다.
- 공동현관 비밀번호, 방문 비밀번호, 내부 메모는 외부에 공유하지 않습니다.
- 내부 업무용 엑셀에는 비밀번호·내부 메모가 포함될 수 있으므로 외부에 공유하지 않습니다. 개인 연락처와 상담 고객 이름·연락처는 엑셀에 포함하지 않습니다.
- 현재 데이터 파일을 Google Drive, OneDrive 같은 동기화 폴더에서 직접 실행하지 않습니다.
- 프로그램을 업데이트하기 전에는 데이터 파일을 별도로 복사해 백업합니다.
- 매물·계약·상담·광고 현황을 저장·수정·삭제하면 무결성 검사를 통과한 날짜별 SQLite 사본을 OneDrive `Documents\매물관리백업\daily`에 자동 저장하며, 최근 10일만 유지합니다.
- 매물 현황 리스트는 조회·필터·내보내기용이며, 선택한 현재 매물은 같은 화면에서 종료 처리할 수 있습니다. 새 등록·최신 정보 수정은 `매물 등록·수정` 메뉴에서 처리합니다.

## 폴더 구성

```text
realestate/
├─ app.py                         프로그램 실행 파일
├─ .venv/                          메인 PC의 Python 3.12 가상환경
├─ ui/                            사용자가 보는 화면
├─ services/                      입력값 확인과 저장 규칙
├─ storage/                       공통 연결·업무별 저장 기능과 실제 데이터 파일
└─ docs/                          기획, 작업 계획, 진행 기록 문서
```
