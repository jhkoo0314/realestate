# 부동산 매물관리 도구 화면 명세·와이어프레임 v1.0

> 적용 범위: 사무실 내부 PC에서 사용하는 Streamlit + SQLite 기반 1차 버전
>
> 화면 원칙: SaaS형 대시보드가 아니라 엑셀보다 빠르고 덜 헷갈리는 내부 매물장으로 설계한다.

## 1. 화면 설계 목표

사용자는 이 화면에서 다음 세 가지 일을 빠르게 처리해야 한다.

1. 오늘 확인할 매물을 찾는다.
2. 신규 매물을 입력하거나 기존 호실의 최신 정보를 수정한다.
3. 건물·호실의 고정정보와 과거 매물 이력을 확인한다.

### 판단 기준

- 장식보다 표의 가독성과 입력속도를 우선한다.
- 화면 이동을 최소화한다.
- 기본 화면에는 자주 쓰는 항목만 표시한다.
- 내부 비밀번호는 목록에 노출하지 않는다.
- 같은 정보의 반복 입력을 막는다.
- 기존 `구재현` 시트는 가져오지 않으며 새 도구 사용 시점부터 직접 등록한다.

## 2. 전체 화면 구조

### 2.1 기본 레이아웃

| 영역 | 위치 | 역할 |
|---|---|---|
| 상단 제목 | 좌측 상단 | `매물관리`와 현재 실행 상태 표시 |
| 주요 메뉴 | 상단 | 오늘 할 일 / 매물 현황 리스트 / 매물 등록·수정 / 건물·호실 관리 / 계약관리 / 상담관리 / 광고관리 |
| 주요 행동 | 우측 상단 | `새 매물 등록` 버튼 |
| 본문 | 중앙 | 선택한 메뉴의 표 또는 입력폼 |
| 알림 영역 | 화면 하단 또는 입력영역 상단 | 저장 성공·오류 안내 |

### 2.2 메뉴 구성

| 메뉴 | 기본 진입 | 핵심 행동 |
|---|---|---|
| 매물 현황 리스트 | 프로그램 실행 시 | 현재 매물 조회·필터·확인 업무·엑셀 내보내기 |
| 매물 등록·수정 | `새 매물 등록` 클릭 | 건물·호실 검색 후 매물 저장·최신 정보 수정·종료 |
| 건물·호실 관리 | 건물 상세 확인 시 | 고정정보 수정·과거 이력 확인 |
| 계약관리 | 계약 업무 선택 시 | 가계약 진행·정식 계약·임대차 기간·상태 등록과 계약 이력 확인 |
| 상담관리 | 상담 업무 선택 시 | 매물별 상담 이력과 다음 연락일 확인 |

좌측 사이드바는 사용하지 않는다. 메뉴는 상단 탭으로 두어 화면 폭을 표에 사용한다.

## 3. 공통 UI 규칙

### 3.1 크기와 밀도

- PC 화면을 기본으로 설계한다.
- 표는 한 화면에서 12~18행 정도 보이도록 한다.
- 행 높이는 엑셀보다 조금 넓게 하되 카드형 목록처럼 커지지 않게 한다.
- 긴 메모는 한 줄로 줄여 표시하고, 행 선택 시 전체 내용을 보여준다.
- 숫자는 오른쪽 정렬하고 상태와 날짜는 중앙 정렬한다.

### 3.2 색상 사용

색상은 상태 구분에만 제한적으로 사용한다.

| 상태 | 표현 원칙 |
|---|---|
| 공실·광고 가능 | 기본 강조색 또는 옅은 배경 |
| 퇴실 예정 | 주의색 |
| 확인 필요 | 경고색 |
| 계약 진행 중 | 진행색 |
| 계약 완료·종료 | 회색 또는 낮은 대비 |

행 전체를 강한 색으로 채우지 않고 상태 글자 또는 작은 상태 표시만 사용한다.

### 3.3 버튼 우선순위

| 버튼 종류 | 예시 | 표현 |
|---|---|---|
| 주요 행동 | 새 매물 등록, 최신 정보 저장 | 한 화면에 한 개만 강조 |
| 일반 행동 | 저장, 수정, 상세보기 | 기본 버튼 |
| 보조 행동 | 취소, 다시 검색 | 낮은 강조 |
| 위험 행동 | 종료 처리, 매물 완전 삭제 | 확인 후 실행 |

매물 완전 삭제는 매물 현황 리스트와 매물 등록·수정 화면에서 제공한다. 삭제 전에는 연결된 계약·상담 기록도 함께 삭제됨을 알리고, 확인 체크 후에만 실행한다. 건물·호실의 완전 삭제 버튼은 제공하지 않는다.

### 3.4 내부정보 표시

- 공동현관·방문 비밀번호는 현재 매물 표에서 숨긴다.
- 사무실 내부 전용인 `매물 등록·수정`과 `건물·호실 관리` 화면에서는 기본으로 표시한다. 그 밖의 화면에는 표시하지 않는다.
- 광고 관련 영역에는 내부정보를 전달하지 않는다.

## 4. 화면 1 — 매물 현황 리스트

### 4.1 화면 목적

현재 매물을 조회·필터하는 목록 화면이다. 종료된 매물도 별도 필터로 조회할 수 있다. 오늘 행동이 필요한 매물도 이 목록에서 필터로 찾는다. 엑셀 내보내기는 현재 매물 조회 결과를 기준으로 한다.

지번은 `지번 지역`과 `번지 번호`의 독립 열로 표시한다. 등록·건물정보 수정 화면도 같은 두 입력칸을 사용하며, 저장·통합검색은 기존처럼 합친 지번값을 사용한다.

### 4.2 상단 구성

상단 요약은 다섯 개의 숫자를 표시한다.

| 항목 | 클릭 결과 |
|---|---|
| 오늘 새 접수 | 오늘 접수된 매물만 필터 |
| 퇴실 예정 | 상태가 퇴실 예정인 매물만 필터 |
| 재확인 관리 | 오늘·지연 재확인과 오늘 다음 날부터 7일째까지의 예정 재확인을 합산한다. 아래에 도래·지연 / 7일 이내 건수를 구분해 표시한다. |
| 사진 촬영 필요 | 사진 보유 여부가 없음인 매물만 필터 |
| 사진 확인 필요 | 사진 보유 여부가 확인 필요인 매물만 필터 |
| 광고 준비 필요 | 광고 상태가 준비 중·확인 필요인 매물만 필터 |

숫자 카드를 크게 만들지 않고, 표 위의 한 줄 요약 버튼으로 배치한다.

### 4.3 검색·필터 영역

| 순서 | 항목 | 기본값 |
|---:|---|---|
| 1 | 건물명·지번·호수 검색 | 비어 있음 |
| 2 | 표시할 매물 | 현재 매물만 |
| 3 | 매물 상태 | 활성 상태 전체 |
| 4 | 룸 형태 | 전체 |
| 5 | 사진 보유 여부 | 전체 |
| 6 | 확인 업무 | 전체 |
| 7 | 초기화 | 필요 시 클릭 |

필터를 변경하면 `조회` 버튼을 눌렀을 때 한 번에 목록을 갱신한다. 선택할 때마다 전체 화면을 다시 불러오지 않는다.

### 4.4 기본 표 열

| 순서 | 열 | 정렬 | 빠른 수정 | 비고 |
|---:|---|---|---:|---|
| 1 | 상태 | 중앙 | 예 | 선택값 변경 |
| 2 | 건물명 | 왼쪽 | 아니오 | 클릭 시 상세 열기 |
| 3 | 지번 | 왼쪽 | 아니오 | 건물명과 분리한 독립 열로 표시 |
| 4 | 호수 | 중앙 | 아니오 | 건물명과 함께 식별 |
| 5 | 형태 | 중앙 | 아니오 | 원룸·투룸 등 |
| 6 | 보증금 | 오른쪽 | 예 | 단위 만원 |
| 7 | 월세 | 오른쪽 | 예 | 단위 만원 |
| 8 | 관리비 | 오른쪽 | 예 | 값이 있을 때 표시 |
| 9 | 입주 가능 | 중앙 | 예 | 즉시·날짜·확인 필요 |
| 10 | 퇴실 예정일 | 중앙 | 아니오 | 이번 매물에 입력한 퇴실 예정일 |
| 11 | 재확인일 | 중앙 | 예 | 이번 매물의 재확인 예정일 |
| 12 | 다음 연락일 | 중앙 | 아니오 | 연결된 진행 중 상담의 가장 이른 다음 연락일. 고객 정보·상담 내용은 표시하지 않음 |
| 13 | 세대 비밀번호 | 왼쪽 | 아니오 | 사무실 내부용 매물 조회 결과 표에서 해당 호실의 방문 비밀번호를 바로 표시 |
| 14 | 사진 보유 여부 | 중앙 | 예 | 있음 / 없음 / 확인 필요. `없음`이면 `없음 · 사진 촬영 필요`, `확인 필요`면 `확인 필요 · 사진 확인 필요`로 표시 |
| 15 | 종료일 | 중앙 | 아니오 | `종료된 매물만` 또는 `전체` 조회에서만 표시 |
| 16 | 종료 사유 | 왼쪽 | 아니오 | `종료된 매물만` 또는 `전체` 조회에서만 표시 |
| 17 | 메모 | 왼쪽 | 예 | 한 줄 표시 |

확인 업무는 현황 리스트에서 따로 입력하지 않는다. 매물 등록·수정의 `확인·관리 사항`에서 사진 보유 여부, 청소·도배·수리 상태, 재확인 예정일을 저장하면 자동 계산해 상단 현황과 `확인 업무` 필터에 사용한다. 현황 리스트의 빠른 수정도 같은 항목을 수정한다. 다음 연락일은 연결된 진행 중 상담을 조회해 자동 표시한다.

검색 영역에는 매물 보유처 바로 오른쪽의 `엘리베이터 여부` 복수 선택 필터(`있음 / 없음 / 확인 필요 / 미입력`)와 보증금 최소·최대, 월세 최소·최대 입력칸을 둔다. 각 금액은 만원 단위이며, 최소·최대가 모두 입력된 경우 최대값이 더 작으면 조회하지 않고 안내한다.
| 16 | 수정일 | 중앙 | 아니오 | 마지막 수정일 |
| 15 | 행 작업 | 중앙 | 아니오 | 현재 매물만 빠른 수정·종료 처리 |

### 4.5 행 선택 동작

행 또는 건물명을 누르면 오른쪽에 별도 패널을 계속 두지 않고, 표 아래에 선택한 매물의 상세정보를 펼친다.

펼침 영역 탭:

- 이번 매물
- 건물·호실 정보
- 과거 매물 이력

표를 계속 보면서 내용을 확인할 수 있도록 새 페이지로 강제 이동하지 않는다.

### 4.6 빠른 수정 규칙

- 상태·가격·관리비·입주일·메모를 수정한 뒤 `변경사항 저장`을 누른다.
- 셀을 바꿀 때마다 바로 저장하지 않는다.
- 수정된 행에만 `변경됨` 표시를 한다.
- 저장 실패 시 입력값을 유지한다.
- 현재 매물을 선택하면 빠른 수정 아래에서 `이 매물 종료 처리`를 펼칠 수 있다. 대상 건물·호실·현재 상태·가격, 종료 사유, 종료일, 확인 체크와 `종료 처리` 버튼을 표시한다.
- 종료 처리에 성공하면 해당 매물은 현재 목록에서 제외하고, 종료일·종료 사유와 함께 종료된 매물 조회에서만 확인한다.
- 종료된 매물은 종료일·종료 사유를 보여 주며, 이 화면에서는 조회만 한다.

## 5. 화면 2 — 매물 등록·수정

### 5.1 화면 목적

건물과 호실을 먼저 찾고, 시스템이 신규·기존 호실 상황을 판단해 필요한 입력만 같은 화면에서 바로 보여준다.

### 5.2 1단계: 건물 검색

화면 상단에 가장 먼저 표시한다.

| 요소 | 동작 |
|---|---|
| 건물명·지번 검색창 | 2글자 이상 입력 후 검색 |
| 검색 결과 | 건물명, 지번, 등록 호실 수 표시 |
| 새 건물 등록 | 결과가 없거나 사용자가 명시적으로 선택할 때 |

검색 결과 선택 후 다음 단계로 이동하되, 선택한 건물 요약은 화면 상단에 계속 표시한다.

### 5.3 2단계: 호실 선택

기존 건물 선택 시 등록된 호실을 짧은 표로 보여준다.

| 호실 | 형태 | 최근 조건 | 최근 상태 | 선택 |
|---|---|---|---|---|

하단에 `새 호실 등록` 버튼을 둔다.

### 5.4 상황별 화면 변화

| 상황 | 자동 표시 | 사용자가 입력할 내용 | 최종 버튼 |
|---|---|---|---|
| 신규 건물 | 빈 건물 입력폼 | 건물·호실·첫 매물 | 건물·호실·첫 매물 등록 |
| 기존 건물·신규 호실 | 건물 공통정보 | 호실·첫 매물 | 새 호실·첫 매물 등록 |
| 기존 호실 최신 정보 수정 | 건물·호실·현재 조건 | 바뀐 가격·상태·입주일 등 | 최신 정보 저장 |

기존 호실을 선택하면 `최신 매물 정보` 입력칸을 바로 펼친다. 저장하면 새 회차를 만들지 않고 같은 최신 매물 기록을 갱신하며, 연결된 계약·상담 기록은 유지한다.

### 5.5 기본 입력 영역

기본 화면에는 다음 항목만 표시한다.

| 구분 | 항목 |
|---|---|
| 대상 | 건물명, 지번, 호수, 룸 형태 |
| 현재 조건 | 매물 상태, 보증금, 월세, 입주 가능 유형·날짜 |
| 메모 | 이번 매물 메모 |

### 5.6 상세정보 접기·펼치기

상세정보는 세 묶음으로 나눈다.

1. 가격·계약 조건: 관리비, 계약기간, 단기계약 조건
2. 확인·관리: 사진 보유 여부, 재확인 예정일

## 6.6 화면 4 — 계약관리

계약관리는 별도 탭으로 둔다. 계약관리 안에서는 `계약 등록`과 `계약 조회·수정`을 분리한다. 건물·호실 관리 화면에서는 계약 이력을 조회만 한다.

- `계약 등록`: 매물 회차를 찾고 선택한 뒤, 새 계약만 추가한다. 계약으로 이어진 출처 상담은 선택 사항이며, 선택하면 고객 이름·연락처를 계약자 정보의 초기값으로 채운다.
- `계약 조회·수정`: 저장된 계약을 검색·필터한다. 조회 뒤 사용자가 계약을 선택하고 `선택한 계약 수정 열기`를 눌렀을 때만 진행 시작일·정식 계약일·임대차 기간·잔금 예정일·상태·출처 상담·계약자 연락처·계약금·잔금 수정 영역을 표시한다. 기존 계약에 상담을 새로 연결한 경우에는 `현재 계약 상태를 연결 상담에 반영`을 명시적으로 선택할 수 있다.
- 두 화면은 같은 계약 기록을 사용하며, 조회·수정 화면에서 새 계약을 만들지 않는다.
- `계약 조회·수정`: 현재 검색·필터 결과를 내부 업무용 엑셀로 내보낸다. 계약자 연락처는 포함하지 않는다.

`계약 조회·수정` 상단에는 건물명·지번·호수·계약 상태·계약 종료일 기간 검색을 둔다.

`계약 만료 30일 전만 보기`를 선택하면 오늘부터 30일 이내에 종료되는 계약만 보여 준다. 이미 해지·만료된 계약과 종료일이 없는 계약은 제외하며, 목록에는 `D-day` 또는 남은 일수를 표시한다.

기본 목록 열:

| 계약번호 | 매물번호 | 건물명 | 지번주소 | 호수 | 연결된 매물 접수일 | 계약 유형 | 진행 시작일 | 정식 계약일 | 임대차 시작일 | 임대차 종료일 | 기간 | 계약금 | 가계약금 | 계약금 미수령 | 추가 수령 예정일 | 잔금 | 잔금 예정일 | 계약 상태 | 메모 |
|---|---|---|---|---|---|---|---|---|---:|---:|---:|---:|---|---:|---|---|

`계약 등록`에서는 먼저 기존 매물 회차를 선택한다. 가계약 단계에서는 계약 진행 시작일·상태·계약금 전체·가계약금 수령액·추가 수령 예정일을 기록하고 계약금 미수령액을 자동으로 확인한다. 정식 계약 뒤에는 정식 계약일과 임대차 시작일·종료일 또는 기간(개월), 잔금 예정일을 이어서 입력한다. 여러 입금 내역·결제·계약서 파일 입력칸은 제공하지 않는다.

계약 상세의 `계약 단계 이력`은 실제 처리일의 가계약·정식계약·잔금 예정·계약 완료·해지를 누적한다. 단계별 계약 상태는 자동으로 정하며, 미래 잔금 예정일은 이력이 아니라 위 계약 기본정보에 입력한다. 잔금 납부·입주가 실제로 완료된 날에는 `계약 완료` 이력을 기록한다.

계약관리 안의 `계약 일정` 화면은 기준일 이전 미처리 일정과 이후 30일 이내의 정식 계약·계약금 추가 수령·잔금·임대차 종료 일정을 보여 준다. 계약 진행 시작일은 가계약·구두 합의 이력으로만 관리한다. 임대차 종료는 7·15·30일 구간과 당일·지연을 구분한다. 기본 표에는 계약자 연락처·금액·메모를 표시하지 않는다.

## 6.8 화면 6 — 오늘 할 일

상단 첫 메뉴 `오늘 할 일`은 기준일을 선택해 매물 재확인·퇴실 예정, 계약 일정, 상담 다음 연락을 계산해 보여 준다. 건물 정보 재확인은 포함하지 않는다. 재확인·계약·상담의 날짜 업무는 기준일과 같으면 `오늘`, 지나면 `지연`으로 나눈다. 퇴실 예정은 퇴실일 7일 전 `퇴실 예정 확인 (D-7 알림)`과 퇴실일 당일 `퇴실 예정`을 각각 오늘 목록에 표시하고 완료 체크도 분리하며, 지난 날짜는 표시하지 않는다. 사진·현장·상태처럼 날짜가 없는 업무는 `상시 확인 필요`로 분리한다. 오늘·지연은 각각 매물·계약·상담 표로 나눈다. 매물 표에는 퇴실 예정일을 함께 표시하고 완료만 수정할 수 있게 하며, 계약 표는 `계약 열기`·현재 계약 상태·상태 변경·완료를 표시한다. 상담 표는 다음 연락일·상담 내용 보기·상담 상태·완료를 표시하며, 다음 연락일은 직접 수정·취소할 수 있고 종료 상태 선택 시 자동 취소된다. 선택한 상담의 내용·연락처는 표 바로 아래에만 보인다. 계약 상태 `계약 진행/잔금 예정`·`계약 완료`·`해지/만료`는 연결 매물을 각각 `계약 진행 중`·계약 완료 종료·`공실`으로 자동 반영한다. 상담 상태는 해당 상담 기록만 바꾼다. 완료 체크는 원본 일정·상태를 바꾸지 않는다. 상시 확인 필요는 매물 표만 표시하며 기본으로 접어 둔다. 선택한 기준일의 세 업무 구분은 완료 여부와 함께 한 엑셀 파일로 내보낼 수 있으며, 연락처·비밀번호·내부 메모는 제외한다.

매물 등록·수정의 이번 매물 조건에는 `매물 보유처`를 둔다. 크린주택관리·삼성주택관리·한빛주택관리·국제주택관리·개인매물 중 하나를 선택하거나 직접 입력한다. 현황 리스트에는 보유처 열과 기본 선택값 필터·직접 입력 보유처 검색을 제공하며, 현재 매물 엑셀에도 같은 열을 넣는다.

## 6.9 화면 7 — 광고관리

광고관리는 `현재 광고 현황`, `매물에 광고 채널 연결`, `광고 문구 만들기`로 나눈다. 현황·연결 화면은 현재 매물 회차의 광고 채널과 현재 상태만 빠르게 바꾸는 표 중심 화면이다. 기본 목록에는 건물명·지번·호실·매물 상태·광고 채널·현재 광고 상태·마지막 광고 확인일을 표시한다. 검색과 채널·상태 필터, 조회 결과 행 선택 뒤 상태·확인일 수정과 확인 후 삭제를 제공한다.

`광고 문구 만들기`는 기존 매물·광고 현황과 연결하지 않는 직접입력 화면이다. 지역·방 형태·거래 방식·보증금·월세·관리비·입주 가능일을 입력하고, 기존 방 형태별 제목 템플릿은 그대로 선택해 제목으로 사용한다. 광고문 최상단에는 `찾으시는 조건에 맞춰 다양한 매물을 비교해드립니다.`와 구분선을 표시한다. 광고 상단은 지역별 고정 핵심요약 대신 사용자가 직접 고른 `신축급 / 구축`과 강조유형 1개로 만든다. 신축급은 `컨디션 / 공간 / 특별매물`, 구축은 `가격 / 공간 / 계약조건 / 특별매물` 중 하나를 고르며, 특별매물은 한 줄 특징 입력이 필수다. 일반 매물도 확인된 특별포인트를 한 줄만 선택적으로 추가할 수 있다. 옵션 문구를 입력하지 않으면 생활 기본 옵션 문구를 표시하며, 입력한 경우에만 그 값으로 바꾼다. 본문은 `① 이 매물의 포인트`, `② 조건`, `③ 위치`, `④ 옵션`, `⑤ 비교 상담`, `📌 안내사항` 순서로 생성한다. 실매물·실제 호실 사진 안내는 각각의 확인 체크를 한 경우에만 넣는다. 생성 결과는 수정 후 복사하며 SQLite에는 저장하지 않는다. 광고 링크·비용·광고 사이트 자동 등록·외부 연동은 제공하지 않는다.

## 6.7 화면 5 — 상담관리

상담관리는 계약관리와 분리한 가벼운 CRM 화면이다. 고객을 중심으로 관리하지 않고, 특정 매물에 대한 업무 기록을 남기는 용도다. 매물·계약·상담은 각각 `M-000001`·`C-000001`·`S-000001` 형식의 표시번호를 사용한다.

기본 목록 열:

| 상담번호 | 고객 연락처 | 건물명 | 호수 | 연결된 매물 접수일 | 상담일 | 상담 종류 | 상담 상태 | 다음 연락일 | 상담 내용 |
|---:|---|---|---|---|---|---|---|---|---|

상담 등록 시 매물 회차를 선택한 뒤 고객 이름 없이 연락처, 상담일, 상담 종류, 내용, 다음 연락일, 상태를 필요할 때만 입력한다. 일반·매물 상담 모두 희망 지역·방 형태·보증금·월세·입주 가능일을 선택 입력한다. 상담 상세·수정에서는 `다음 연락일 지정 취소`를 선택해 이미 지정한 날짜를 비울 수 있다. 비어 있는 항목도 저장할 수 있으며, 별도 확인 체크 없이 등록 버튼을 바로 사용할 수 있다. 연락처는 기본 목록에 표시하지 않고, 상담 상세에서 `연락처 보기`를 눌렀을 때만 표시한다. 자동 문자, 방문 예약 달력, 주민번호 등 민감 개인정보 입력은 제공하지 않는다.

`상담 조회·수정`의 검색 영역에는 건물명·지번·호수·희망 지역 검색, 상담 구분(일반 상담 / 매물 상담), 상담 상태, 상담일 시작·종료일, 다음 연락 필요 필터를 둔다. 상담일 종료일이 시작일보다 빠르면 조회하지 않고 안내한다.

`상담 조회·수정`에서는 현재 검색·필터 결과를 내부 업무용 엑셀로 내보낸다. 상담번호와 고객 연락처는 팔로업을 위해 포함하고, 고객 이름·자유 입력 상담 내용은 제외한다. 연락처가 포함된 파일임을 내려받기 전에 경고하며, 외부 공유·개인 기기 보관을 금지한다.

## 7. 공통 보조 화면

### 7.1 종료 확인창

필수 요소:

- 대상 건물·호실
- 현재 상태·가격
- 종료 사유 선택
- 종료일
- `종료 처리`와 `취소`

`계약 완료`와 단순 `종료`를 명확히 구분한다.

### 7.2 저장 성공 안내

화면 상단에 짧게 표시한다.

> 저장되었습니다: 대성빌 302호 · 500/45

사용자가 닫지 않아도 일정 시간 뒤 사라지되, 저장 결과는 목록에 즉시 반영한다.

### 7.3 저장 오류 안내

> 저장하지 못했습니다. 입력값은 유지됩니다. 표시된 항목을 확인해 주세요.

오류가 난 항목 바로 아래에 이유를 표시한다. 사용자가 입력한 내용은 지우지 않는다.

### 7.4 빈 화면

등록된 데이터가 없을 때 빈 표만 보여주지 않는다.

> 아직 등록된 매물이 없습니다. 현재 운영할 매물부터 등록해 주세요.

주요 버튼:

> `첫 매물 등록`

기존 엑셀 가져오기 버튼은 제공하지 않는다.

## 8. 화면 상태와 반응

| 상태 | 화면 동작 |
|---|---|
| 조회 중 | 표 영역에 짧은 로딩 표시 |
| 결과 없음 | 검색어 수정 또는 신규 등록 안내 |
| 수정 중 | 변경된 행·필드 표시 |
| 저장 성공 | 성공 문구와 최신 데이터 반영 |
| 저장 실패 | 입력값 유지, 오류 위치 표시 |
| 중복 호실 | 기존 호실 선택 안내, 신규 저장 차단 |
| 기존 호실 선택 | 최신 정보 입력칸을 바로 표시하고 같은 매물 기록을 수정 |

## 9. 입력 편의 기능

- 숫자 입력에는 `만원` 단위를 입력창 옆에 고정 표시한다.
- 날짜는 달력 선택을 기본으로 하고 `즉시입주`, `확인 필요`를 별도 선택한다.
- 호수는 `302호`와 `302`를 같은 값으로 인식한다.
- 신규 등록에서 숫자 호수 `302`·`1001`을 입력하면 층수를 각각 `3`·`10`으로 자동 입력한다. 직접 수정한 층수와 해석이 모호한 호수 형식은 자동으로 바꾸지 않는다.
- 저장 후 같은 건물의 다른 호실을 이어서 등록할 수 있다.
- Tab 키로 주요 입력항목을 순서대로 이동할 수 있게 한다.
- Enter 키가 예기치 않게 바로 저장을 실행하지 않도록 한다.

## 10. 1차 버전에서 만들지 않는 화면

- 로그인·회원관리
- 고객용 공개 페이지
- 방문 예약, 자동 문자 발송, 주민번호 등 민감 개인정보, 계약금·잔금의 납부·결제 관리 화면
- 기존 `구재현` 시트 가져오기
- 복잡한 통계·차트 대시보드
- 사용자별 권한 설정
- 모바일 전용 화면
- 사진 원본 업로드·편집 화면

## 11. 화면별 수용 기준

| 번호 | 화면 | 완료 조건 |
|---:|---|---|
| UI-01 | 오늘의 현황 | 사용자가 10초 안에 확인 필요 매물을 찾을 수 있음 |
| UI-02 | 현재 매물 표 | 상태·가격·입주일을 목록에서 빠르게 수정 가능 |
| UI-03 | 신규 등록 | 필수정보만으로 건물·호실·첫 매물을 등록 가능 |
| UI-04 | 기존 호실 최신 정보 수정 | 기존 호실정보를 다시 입력하지 않고 같은 매물 기록을 수정 가능 |
| UI-05 | 상세정보 | 내부 비밀번호가 기본 표에 노출되지 않음 |
| UI-06 | 건물·호실 관리 | 선택 호실의 고정정보와 과거 이력을 한 화면에서 확인 가능 |
| UI-07 | 오류 상태 | 저장 실패 시 입력값이 유지됨 |
| UI-08 | 빈 상태 | 엑셀 이전 없이 첫 매물 등록으로 자연스럽게 연결됨 |

## 12. 구현 우선순위

### 우선순위 1

- 상단 3개 메뉴
- 오늘의 매물 표와 필터
- 신규 건물·호실·첫 매물 등록
- 기존 호실 최신 정보 수정

### 우선순위 2

- 표 빠른 수정
- 건물·호실 상세
- 과거 매물 이력
- 종료 처리

### 우선순위 3

- 상세 조건·옵션 보완
- 엑셀 내보내기
- 백업 상태 표시

이 순서로 구현해 등록과 기존 호실 최신 정보 수정 흐름을 먼저 검증한 뒤 관리기능을 확장한다.
