# 상담 진행관리 구현 계획서

> 목적: 기존 상담관리의 기록 기능을 유지하면서, 고객별 상담 진행 단계·재상담 이력·방문 결과·희망조건 기록을 추가한다. 후보 매물 연결은 상담 이력 기능 안정화 뒤 후속 단계로 진행한다.  
> 적용 대상: 원룸·투룸 임대 중개 상담  
> 작성일: 2026-08-08
> 구현 상태: 2026-08-10 기준 1차 코드 구현·임시 DB 자동 확인 완료, 실제 브라우저 업무 확인 필요

---

## 1. 구현 배경

현재 상담관리는 매물 또는 일반 상담을 등록하고, 유입 경로·상담 내용·다음 연락일을 기록할 수 있다. 그러나 같은 고객과 다시 상담했을 때 기존 메모에 내용을 덧붙이는 방식이라 다음 문제가 있다.

- 고객이 현재 어느 단계에 있는지 빠르게 알기 어렵다.
- 전화·문자·방문 등 재상담 과정과 결과가 시간순으로 남지 않는다.
- 방문 후 계약으로 이어지지 않은 이유를 분석할 수 없다.
- 고객 조건에 맞는 현재 매물을 다시 찾는 과정이 수동이다.

이번 기능은 별도 CRM이나 자동 예약 시스템을 만드는 것이 아니라, **기존 상담관리 안에서 상담 한 건을 끝까지 관리할 수 있게 보완**하는 것이 목표다.

---

## 2. 목표와 제외 범위

### 2.1 목표

1. 상담 건마다 현재 진행 단계와 다음 행동을 명확히 표시한다.
2. 재상담할 때 기존 메모를 덮어쓰지 않고 이력을 누적한다.
3. 방문 완료·종료 사유를 남겨 상담 이탈 원인을 확인한다.
4. 고객 희망조건은 상담 기록에 남기되, 후보 매물 찾기는 상담 이력 기능이 안정된 뒤 후속 단계로 진행한다.

### 2.2 이번에 만들지 않는 범위

- 방문 예약 캘린더, 자동 문자 발송, 카카오톡 연동
- 고객용 로그인·매물 추천 링크·공개 홈페이지
- AI 자동 추천, 복잡한 점수 모델
- 희망조건 기반 후보 매물 자동 조회·추천(상담 이력 기능 안정화 뒤 별도 단계로 검토)
- 광고 플랫폼 자동 연동 또는 자동 광고 등록
- 고객 주민번호·신분증·계약서 파일 저장

## 3. 핵심 업무 구조

```text
상담 건 1개
├─ 고객 기본정보·희망조건
├─ 연결 매물 또는 일반 상담 구분
├─ 현재 상담 단계
├─ 다음 연락일
├─ 희망조건 기록
└─ 후속 상담 이력 여러 건
   ├─ 전화 / 문자 / 방문 / 기타
   ├─ 상담 내용
   ├─ 이번 결과
   ├─ 종료 사유(필요 시)
   └─ 다음 연락일(필요 시)
```

상담 건은 고객과의 한 흐름을 의미한다. 후속 상담 이력은 그 상담 건 안에서 발생한 개별 연락·방문 기록이다.

---

## 4. 상담 진행 단계

### 4.1 표준 단계

| 순서 | 단계 | 의미 | 다음 행동 예시 |
|---:|---|---|---|
| 1 | 신규 문의 | 첫 문의를 받은 상태 | 희망조건 확인 |
| 2 | 조건 확인 | 지역·가격·입주 시점 등 확인 중 | 희망조건 정리·후속 연락 |
| 3 | 방문 예정 | 실제 방문 가능성을 확인한 상태 | 방문 결과 입력 |
| 4 | 방문 완료 | 현장 안내가 끝난 상태 | 검토·재연락 관리 |
| 5 | 검토 중 | 고객 또는 임대인 확인을 기다리는 상태 | 다음 연락일 관리 |
| 6 | 계약 진행 | 계약 가능성이 확인된 상태 | 계약관리 연결 |
| 7 | 계약 완료 | 계약이 확정된 상태 | 상담 종료 |
| 8 | 종료 | 더 이상 후속 관리하지 않는 상태 | 종료 사유 기록 |

### 4.2 상태 규칙

- `계약 완료`와 `종료` 상태의 상담은 기본 후속 연락 목록에서 제외한다.
- `계약 진행`은 계약관리 화면에서 실제 계약 기록을 등록했을 때 선택할 수 있다.
- `종료`를 선택해도 종료 사유는 선택 입력이다. 미입력 경고나 저장 차단을 하지 않는다.
- 후속 상담을 새로 저장하면 해당 상담 건의 현재 단계·최근 상담일·다음 연락일을 함께 갱신한다.
- 기존 상담 내용과 과거 단계는 수정하거나 지우지 않는다.

## 5. 데이터 설계

### 5.1 기존 상담 기록에 추가할 항목

현재 상담 테이블은 상담 건의 기본정보와 현재 상태를 계속 담당한다.

| 화면명 | 저장 항목 예시 | 형식 | 필수 | 설명 |
|---|---|---|---:|---|
| 현재 상담 단계 | `progress_stage` | 선택 | 예 | 신규 문의부터 종료까지의 현재 단계 |
| 최근 상담일 | `last_contacted_date` | 날짜 | 자동 | 후속 상담 저장 시 자동 갱신 |
| 방문 결과 요약 | `latest_visit_result` | 선택 | 아니오 | 가장 최근 방문 결과 요약 |
| 종료 사유 | `closed_reason` | 선택 | 아니오 | 필요할 때만 선택하며 종료 처리의 조건이 아님 |
| 희망 보증금 상한 | `desired_deposit_max_manwon` | 숫자 | 아니오 | 만원 단위 |
| 희망 월세 상한 | `desired_rent_max_manwon` | 숫자 | 아니오 | 만원 단위 |
| 희망 룸 형태 | `desired_room_types` | 복수 선택 | 아니오 | 원룸·투룸 등 |
| 필수 조건 | `required_features_note` | 짧은 텍스트 | 아니오 | 엘리베이터·주차·반려동물 등 |

기존 `desired_area`, `desired_move_in_date`, `consultation_source`, `next_contact_date` 등은 그대로 사용한다.

### 5.2 새 후속 상담 이력 테이블

새 테이블 이름 예시: `consultation_activities`

| 항목 | 저장 항목 예시 | 설명 |
|---|---|---|
| 이력 번호 | `id` | 자동 증가 번호 |
| 상담 건 번호 | `consultation_id` | 기존 상담 기록과 연결 |
| 상담일 | `activity_date` | 실제 연락·방문한 날짜 |
| 방식 | `activity_type` | 전화 / 문자 / 방문 / 기타 |
| 내용 | `activity_note` | 이번 상담의 핵심 내용 |
| 결과 단계 | `stage_after_activity` | 이력 저장 뒤의 현재 상담 단계 |
| 방문 결과 | `visit_result` | 방문 시 선택, 아니면 비움 |
| 종료 사유 | `closed_reason` | 종료 시 선택 |
| 다음 연락일 | `next_contact_date` | 필요할 때만 입력 |
| 생성일시 | `created_at` | 자동 기록 |

### 5.3 방문 결과와 종료 사유 값

| 구분 | 권장 값 |
|---|---|
| 방문 결과 | 만족 / 추가 매물 요청 / 가격 부담 / 조건 불일치 / 방문 취소 / 기타 |
| 종료 사유 | 가격 / 위치 / 입주일 / 옵션·구조 / 타 매물 계약 / 연락 두절 / 단순 변심 / 기타 |

## 6. 화면 설계

### 6.1 상담 등록 화면

기존 상담 등록 화면에 아래 영역을 추가한다.

```text
[기본 상담 정보]
상담 구분 / 연결 매물 / 유입 경로 / 상담일

[고객 희망조건]
희망 지역 / 룸 형태 / 보증금 상한 / 월세 상한 / 희망 입주 시점 / 필수 조건

[현재 진행 상태]
상담 단계: 신규 문의
다음 연락일: 선택

[첫 상담 내용]
상담 내용
```

- 새 상담은 기본 단계가 `신규 문의`다.
- 일반 상담은 연결 매물 없이도 희망조건을 저장할 수 있다.
- 고객 이름·연락처 노출 규칙은 기존 상담관리의 내부정보 보호 기준을 유지한다.

### 6.2 상담 조회·수정 화면

기존 목록에 다음 열 또는 필터를 추가한다.

| 항목 | 목적 |
|---|---|
| 현재 상담 단계 | 지금 어디까지 진행됐는지 확인 |
| 최근 상담일 | 오래 연락하지 않은 상담 확인 |
| 다음 연락일 | 후속 연락 대상 찾기 |
| 종료 사유 | 이탈 원인 확인 |

필터:

- 진행 중 상담만 보기
- 방문 완료·검토 중 상담만 보기
- 계약 진행 상담만 보기
- 종료 사유별 보기

### 6.3 상담 상세 화면

상담 상세는 아래 순서로 구성한다.

```text
상담 요약
현재 단계 / 연결 매물 / 희망조건 / 다음 연락일

후속 상담 이력 타임라인
- 8/12 전화 · 조건 확인 · 월세 45 이하 희망
- 8/14 방문 · 가격 부담 · 검토 중

[후속 상담 기록 추가]
```

### 6.4 후속 상담 기록 입력

기존 상담 상세에서 `후속 상담 기록 추가`를 누르면 아래 항목만 보여 준다.

| 항목 | 필수 | 비고 |
|---|---:|---|
| 상담일 | 예 | 기본값 오늘 |
| 상담 방식 | 예 | 전화 / 문자 / 방문 / 기타 |
| 이번 내용 | 아니오 | 짧은 핵심 메모 |
| 결과 단계 | 예 | 현재 상담 단계를 갱신 |
| 방문 결과 | 선택 | 후속 상담 입력 화면에서 항상 표시하며, 방문 외 방식이면 `미입력`으로 둠 |
| 종료 사유 | 아니오 | 후속 상담 입력·수정에서 항상 선택할 수 있으며, 비워도 종료 저장 가능 |
| 다음 연락일 | 아니오 | 계약 완료·종료면 자동 비움 |

## 7. 보류: 희망조건 기반 후보 매물 연결

> 이 기능은 이번 구현 범위에 포함하지 않는다. 상담 진행 단계·후속 상담 이력·오늘 할 일 연동을 실제 업무에서 안정적으로 사용하고, 기존 상담 데이터와 신규 상담 흐름에 문제가 없음을 확인한 뒤 별도 단계로 착수한다.

### 7.1 첫 구현 원칙

복잡한 추천 점수나 AI 기능을 만들지 않는다. 아래 조건이 맞는 **현재 운영 매물 필터 결과**를 보여 준다.

| 조건 | 매칭 규칙 |
|---|---|
| 지역 | 희망 지역과 매물 지번 지역이 일치 |
| 룸 형태 | 희망 룸 형태 중 하나와 일치 |
| 보증금 | 매물 보증금이 고객 상한 이하 |
| 월세 | 매물 월세가 고객 상한 이하 |
| 입주 시점 | 즉시입주 또는 고객 희망일 이전·근접 매물 우선 표시 |

### 7.2 표시 규칙

- 종료된 매물과 광고 중단 매물은 후보에서 제외한다.
- 가격·입주일이 `확인 필요`인 매물은 별도 표시한다.
- 후보 매물은 “실시간 계약 가능 보장”이 아니라는 안내를 표시한다.
- 사용자가 실제 안내한 후보 매물만 상담 이력에 선택적으로 연결한다.

### 7.3 화면 문구 예시

> 조건에 맞는 현재 매물입니다. 가격·입주 가능 여부는 안내 전 다시 확인하세요.

## 8. 저장·삭제·보안 규칙

1. 후속 상담 이력은 수정 전 확인이 필요한 경우를 제외하고 과거 기록을 삭제하지 않는다.
2. 상담 건을 완전 삭제하면 연결된 후속 상담 이력도 함께 삭제된다는 건수를 먼저 안내한다.
3. 후속 상담 이력 삭제는 명시적 확인 후에만 가능하다.
4. 고객 연락처는 기존 기준대로 기본 매물 목록과 외부 공유용 엑셀에 표시하지 않는다.
5. 상담 조회용 내부 엑셀의 연락처 포함 정책은 기존 기준을 유지하고, 후속 상담 내용은 내부 업무용으로만 다룬다.
6. 후속 단계의 후보 매물 화면을 만들 때도 공동현관·방문 비밀번호·내부 메모를 표시하지 않는다.

## 9. 구현 순서

| 단계 | 작업 | 완료 기준 |
|---:|---|---|
| 1 | 기존 상담 데이터·화면·엑셀 구조 점검 | 현재 저장 규칙과 연결 화면 확인 |
| 2 | 상담 테이블 호환 마이그레이션 | 기존 상담 데이터가 그대로 열림 |
| 3 | 후속 상담 이력 테이블·저장소 추가 | 한 상담에 이력 여러 건 저장 가능 |
| 4 | 상담 상세 타임라인·후속 기록 입력 화면 | 메모 덮어쓰기 없이 이력 누적 |
| 5 | 상담 단계·방문 결과·종료 사유 필터 | 진행 중·방문 완료·종료 상담 구분 가능 |
| 6 | 오늘 할 일·엑셀 영향 점검 | 다음 연락일·개인정보 규칙 유지 |
| 7 | 브라우저 수용 테스트와 운영 DB 백업 | 실제 상담 2~3건으로 흐름 검증 |
| 후속 | 희망조건 기반 후보 매물 필터 | 상담 이력 기능 안정화 뒤 별도 계획·테스트로 진행 |

| CP-03 | 방문 완료 기록 | 방문 결과와 단계가 저장됨 |

| CP-05 | 계약 진행 처리 | 상담 단계와 계약관리 연결 확인 |
| CP-06 | 희망조건 입력 | 지역·룸 형태·희망 금액이 상담 기록에 저장됨 |

## 11. 수용 기준

다음이 모두 가능하면 이번 기능의 목적을 달성한 것으로 본다.

1. 같은 고객과 세 번 상담해도 상담 내용이 덮어써지지 않고 시간순으로 남는다.
2. 상담 목록만 보고 고객이 문의·방문·검토·계약 중 어디에 있는지 알 수 있다.
3. 방문 후 계약으로 이어지지 않은 이유를 짧게 기록하고 조회할 수 있다.
4. 후보 매물 찾기는 상담 이력 기능 안정화 뒤 별도 단계에서 구현한다.
5. 다음 연락일은 기존 오늘 할 일 흐름에 계속 반영된다.
6. 기존 상담·계약·매물 데이터가 손상되거나 연결이 끊기지 않는다.

## 12. 구현 전 확인할 결정 사항

구현 착수 전 아래 두 가지만 현재 화면 흐름에 맞춰 확정한다.

1. `방문 예정` 단계를 실제 방문 약속이 잡힌 경우에만 사용할지, 고객이 방문 의향을 보인 경우에도 사용할지
2. 기존 상담 상태값을 새 상담 단계로 일괄 옮길지, 기존 상담은 `기존 상담`으로 보존하고 새 상담부터 단계 관리를 시작할지

권장안은 다음과 같다.

- `방문 예정`: 실제 방문 시간 또는 방문 의사가 명확히 확인된 경우 사용
- 기존 상담: 데이터는 유지하고, 단계가 없는 과거 상담은 `기존 기록` 또는 `확인 필요`로 표시. 임의로 새 단계값을 채우지 않음

## 13. 1차 구현 기록 (2026-08-10)

- 기존 상담 행은 변경하지 않고, 단계값이 비어 있으면 화면에서 `기존 기록`으로 표시한다. 새 상담은 진행 단계를 메뉴에서 직접 선택하며 기본값은 `신규 문의`다.
- `consultation_activities`에 후속 상담을 누적하고, 저장 시 상담의 진행 단계·최근 상담일·다음 연락일을 함께 갱신한다. 기존 첫 상담 내용은 수정하지 않는다.
- `종료` 사유는 선택 입력이며, `종료`·`계약 완료`는 다음 연락일을 자동 해제한다. 진행 단계와 종료 사유 필터를 제공한다.
- 임시 DB에서 기존 상담 보존, 신규 상담 단계 저장, 후속 방문 이력 누적, 종료 처리, 상담 삭제 시 연결 이력 삭제를 확인했다.
- 후속 상담 이력은 선택한 한 건만 수정하거나 명시적 확인 뒤 삭제할 수 있게 보완한다. 수정·삭제 뒤 남아 있는 가장 최근 이력의 단계·최근 상담일·다음 연락일을 상담 요약에 다시 반영한다.
- 후보 매물 찾기는 보류 상태를 유지한다. 실제 브라우저에서 신규 상담·후속 상담·오늘 할 일 연동을 확인한 뒤 안정화 여부를 판단한다.
