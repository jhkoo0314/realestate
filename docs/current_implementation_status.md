## 현재 상태 요약

현재는 **13단계: 데이터 저장 코드 기능별 분리**까지 코드 구현을 마쳤습니다. 10단계는 사용자 요청으로 보류했습니다.

- 완료: 1~9단계, 11~13단계의 코드 구현과 기본 자동 확인
- 남음: 각 단계의 실제 브라우저 화면 확인
- 보류: 10단계 — 백업·복구·사무실 운영 준비
- 다음 계획: 백업·복구와 실제 브라우저 업무 흐름 확인
- 최근 완료: 계약 일정(잔금 예정일·7/15/30일 만료 구간)과 날짜별 통합 오늘 할 일의 코드 구현·기본 자동 확인
- 최근 완료: 매물 회차별 현재 광고 채널·광고 상태를 빠르게 바꾸는 광고관리 탭의 코드 구현·기본 자동 확인

### 광고관리 구현 (2026-08-07)

- 상단 `광고관리` 탭에서 현재 매물 회차에 당근·직방·네이버 또는 직접 입력 채널을 복수로 연결한다.
- 같은 매물 회차의 같은 채널은 중복 등록하지 않으며, 상태·마지막 광고 확인일은 기존 행에서 빠르게 수정한다.
- 현재 광고 현황 검색·채널·상태 필터와 직접 입력 채널 이름 검색을 제공한다. 종료된 매물은 기본 목록에서 제외한다.
- 광고 현황은 오늘 할 일과 분리해 광고관리 탭에서만 확인한다.
- 임시 DB로 복수 채널·직접 입력·중복 차단·상태 수정·오늘 할 일 연결을 확인했다. 실제 브라우저 확인은 남아 있다.

### 매물 보유처 구현 (2026-08-07)

- 매물 회차에 `listing_holder`를 추가했다. 기존 매물은 빈값으로 보존하며, 운영 DB에 새 열을 추가하기 전 `backups` 폴더에 보호 사본을 만든다.
- 신규 등록·기존 호실의 현재 매물 등록·최신 정보 수정에서 크린주택관리·삼성주택관리·한빛주택관리·국제주택관리·개인매물을 선택하거나 직접 입력할 수 있다.
- 매물 현황 리스트의 보유처 열·필터·직접 입력 검색과 현재 매물 엑셀 보유처 열을 추가했다.
- 임시 DB로 직접입력·저장·현황 필터·엑셀 열을 확인했다. 실제 브라우저 확인은 남아 있다.

### 계약 일정·통합 오늘 할 일 구현 (2026-08-07)

- `contracts.balance_due_date`를 호환 마이그레이션으로 추가했다. 실제 운영 DB에 새 열을 더하기 전 `backups` 폴더에 보호 사본을 만들며, 기존 계약의 잔금 예정일은 비워 둔다.
- 계약 등록·조회·수정에 잔금 예정일을 추가했고, 계약 진행 시작일 또는 정식 계약일보다 빠른 날짜는 저장하지 않는다. 계약 조회 엑셀에도 잔금 예정일을 포함한다.
- 계약관리의 `계약 일정`에서 정식 계약·계약금 추가 수령·잔금·임대차 종료의 기준일 이전 미처리 일정과 30일 이내 일정을 표시한다. 계약 진행 시작일은 가계약·구두 합의 이력으로만 관리한다. 임대차 만료는 당일·지남/7일/8~15일/16~30일로 분류하고, 30·15·7일 누적 수치를 제공한다.
- 첫 메뉴 `오늘 할 일`에서 매물 재확인·퇴실 예정, 계약 일정, 상담 다음 연락을 오늘/지연으로 나눠 표시한다. 사진·현장·상태 업무는 상시 확인 필요로 분리하며, 건물 정보 재확인은 제외하고 별도 완료 기록은 만들지 않는다.
- 선택한 기준일의 오늘·지연·상시 확인 필요 업무를 엑셀로 내보낼 수 있으며, 파일에는 연락처·비밀번호·내부 메모를 넣지 않는다.
- 임시 DB로 기존 계약 보존·잔금 예정일 검증·일정 계산·오늘/지연 분리·개인정보 미표시를 확인했다. 실제 브라우저 확인은 남아 있다.

## 운영 연결 상태 (2026-08-06)

- 메인 PC와 서브 PC의 Tailscale 연동을 완료했다.
- 메인 PC의 Streamlit은 `127.0.0.1:8501`에서 실행하고, Tailscale Serve의 기존 HTTPS 주소를 통해 서브 PC에서 접속하는 방식으로 사용한다.
- 일반 인터넷 공개, 공유기 포트 포워딩, Tailscale Funnel은 사용하지 않는다.
- 메인 PC는 Windows 자동 로그인 환경이다. 재부팅 뒤 Streamlit까지 자동 실행되도록 하는 작업 스케줄러 설정 절차는 `docs/streamlit_windows_auto_start_guide.md`에 기록했다.
- `RealEstate Streamlit` 예약 작업과 `start_streamlit.bat`를 2026-08-06에 등록했다. 기존 수동 Streamlit을 정상 종료한 뒤 예약 작업을 수동 실행하여 `http://127.0.0.1:8501`의 HTTP 200 응답을 확인했다.
- 남은 운영 확인: 메인 PC 재부팅 후 자동 로그인·30초 지연·Streamlit 자동 실행과 서브 PC HTTPS 접속이 모두 이어지는지 실제로 확인한다.

### 다음 단계에 반영된 사진 계획

- 사진 파일과 사진 보관 위치는 이 도구에서 관리하지 않는다.
- 7단계에서 매물별 `사진 보유 여부`를 `있음 / 없음 / 확인 필요`로 선택하고 필터할 수 있게 만든다.
- 사진 보유 여부가 `없음`이면 `사진 촬영 필요`, `확인 필요`이면 `사진 확인 필요` 업무로 표시한다.

### 추가 계획: 계약관리

- 계약관리는 별도 탭으로 만들되, 계약을 건물·호실에 직접 붙이지 않고 해당 매물 회차에 연결한다.
- 단기계약과 일반 계약의 시작일·종료일·기간·상태를 누적 관리한다.
- 계약자 연락처와 계약금·잔금은 계약 기록의 내부정보로 관리한다. 납부·결제 관리와 계약서 파일은 관리하지 않는다.

### 추가 계획: 상담관리

- 상담관리는 계약관리와 분리한 가벼운 CRM 탭으로 만든다.
- 전화·문자·방문 등 상담 이력과 다음 연락일만 매물 회차에 연결해 누적한다.
- 고객 이름·연락처는 상담 상세에서만 관리하고, 자동 문자·방문 예약·민감 개인정보는 관리하지 않는다.

## 최근 완료: 8단계

### 구현된 내용

- 건물명·지번으로 건물을 검색하고 공통정보를 확인·수정함
- 선택한 건물의 호실 목록과 각 호실의 최근 매물 조건을 표시함
- 호실의 구조·방향·옵션·방문 방법 등 고정정보를 수정함
- 호실별 과거 매물 이력을 날짜순으로 표시함
- 공동현관·방문 비밀번호는 `비밀번호 보기`를 눌렀을 때만 표시함
- 이번 매물에만 다른 옵션은 호실 기본 옵션을 바꾸지 않고 해당 매물의 옵션 변경 메모로 저장함

### 8단계 보완: 비밀번호 수정·삭제 (2026-08-03)

- 건물 관리 화면에서 공동현관 비밀번호를 `기존 비밀번호 유지 / 새 비밀번호로 변경 / 비밀번호 삭제`로 선택할 수 있게 보완했다.
- 같은 방식으로 호실의 방문 비밀번호도 수정하거나 삭제할 수 있게 했다.
- `비밀번호 삭제`를 저장하면 기존 값이 비워지며, 이후 `비밀번호 보기`에서는 `등록되지 않음`으로 표시된다.

### 화면 역할 보완: 매물 현황 리스트 (2026-08-03)

- 기존 `오늘의 매물 현황` 메뉴 이름을 `매물 현황 리스트`로 변경했다.
- 이 화면은 현재 매물의 조회·필터·확인 업무 처리와, 다음 9단계의 엑셀 내보내기 기준 화면으로 사용한다.
- 새 등록, 현재 조건 수정, 종료, 재등록은 계속 `매물 등록·수정` 메뉴에서 처리한다.

### 9단계 계획 보완: 엑셀 내보내기 기준 (2026-08-03)

- 매물 현황 리스트에서 조회·필터한 결과를 엑셀로 내보낸다.
- 공동현관·방문 비밀번호와 내부 메모는 내부 업무용 엑셀에 포함한다.
- 임대인·세입자의 개인 연락처와 상담관리 고객 이름·연락처만 엑셀에서 제외한다.

### 9단계 보완: 임대인·세입자 연락처 입력 (2026-08-03)

- 새 건물·호실·첫 매물 등록 및 기존 건물의 새 호실 등록 화면에 임대인·세입자 연락처 입력칸을 추가했다.
- 재등록과 현재 매물 수정 화면에서도 해당 매물 회차의 연락처를 입력·수정할 수 있다.
- 연락처는 매물 회차별 내부정보로 저장하며, 기본 매물 목록과 엑셀 내보내기에는 포함하지 않는다.
