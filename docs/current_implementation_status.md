> 기준 문서: `docs/TASK.md`  
> 표기 방법: **완료**는 코드와 기본 확인이 끝난 상태이며, **브라우저 확인 필요**는 실제 화면을 사람이 직접 눌러 보는 확인이 남았다는 뜻입니다.

## 현재 상태 요약

현재는 **13단계: 데이터 저장 코드 기능별 분리**와 이후의 계약 일정·오늘 할 일·광고관리·광고 문구 만들기, 날짜별 자동 백업의 코드 구현 및 기본 자동 확인을 마쳤습니다.

- 사용 가능 메뉴: 오늘 할 일, 매물 현황 리스트, 매물 등록·수정, 건물·호실 관리, 계약관리, 상담관리, 광고관리의 7개 메뉴
- 완료: 1~9단계, 11~13단계와 자동 백업·계약 일정·오늘 할 일·광고관리의 코드 구현 및 기본 확인
- 남음: 실제 브라우저 업무 흐름 확인, 백업 파일 복구 시험, 메인 PC 재부팅 뒤 자동 실행과 서브 PC HTTPS 접속의 연속 확인
- 운영 준비: 메인 PC와 서브 PC의 Tailscale 연동, `127.0.0.1:8501` 실행, Windows 예약 작업 자동 시작 설정은 완료
- 데이터 안전: 매물·계약·상담·광고·건물·호실 저장·수정·삭제 및 오늘 할 일 완료 체크 뒤 OneDrive 날짜별 SQLite 자동 백업과 무결성 검사를 수행
- 최근 완료: 광고 문구 만들기 화면, 자동 백업의 로그·마지막 상태 기록 갱신
- 오늘 할 일의 완료 체크 업무는 기본으로 숨기고, `완료 업무 보기`를 선택했을 때만 다시 표시한다. 엑셀도 현재 표시 중인 업무만 내보내며, 날짜 업무가 없는 매물·계약·상담 표는 표시하지 않는다.

### 상담 진행관리 1차 구현 (2026-08-10)

- 기존 상담 기록은 단계값을 비운 채 그대로 유지하고, 이 기능을 적용한 뒤 새로 등록하는 상담은 진행 단계를 메뉴에서 직접 선택해 저장한다. 기본 선택값은 `신규 문의`다.
- 새 상담에는 진행 단계·최근 상담일·최근 방문 결과·종료 사유·필수 조건을 기록할 수 있다. 기존 상담의 메모를 후속 기록으로 바꾸거나 일괄 변환하지 않는다.
- 상담 상세에서 전화·문자·방문·기타 후속 상담을 별도 이력으로 누적한다. 이력 저장은 상담의 진행 단계·최근 상담일·다음 연락일을 함께 갱신하며, 기존 첫 상담 내용은 보존한다.
- 후속 상담 이력은 선택한 한 건만 수정하거나 명시적 확인 뒤 삭제할 수 있다. 수정·삭제 뒤 남아 있는 가장 최근 이력의 단계·최근 상담일·다음 연락일을 상담 요약에 다시 반영하며, 첫 상담 내용과 다른 후속 이력은 유지한다.
- 후속 상담 등록·수정에서는 방문 결과 메뉴를 항상 함께 표시하며, 방문 상담이 아니면 `미입력`으로 두도록 안내한다.
- 후속 상담 이력 목록은 바로 표시하며, `후속 상담 이력 수정·삭제`를 펼친 뒤 이력을 선택하고 `수정 메뉴 열기`를 누른 경우에만 해당 이력의 수정·삭제 메뉴를 표시한다.
- 결과 단계가 `종료`이면 종료 사유를 필수로 받고, `종료` 또는 `계약 완료`이면 다음 연락일을 자동으로 비운다. 진행 단계·종료 사유 필터를 추가했다.
- 운영 DB에 새 열과 후속 이력 표를 만들기 전 보호 사본을 남긴다. 임시 DB에서 기존 상담 보존, 후속 이력 누적, 종료 처리, 삭제 시 이력 함께 삭제를 자동 확인했다. 실제 브라우저 확인은 남아 있다.
- 희망조건 기반 후보 매물 찾기는 이번 구현에 포함하지 않고, 상담 이력 기능 안정화 후 별도 단계로 진행한다.

### 계약 중개 방식 분리 (2026-08-10)

- 계약 유형은 `일반 계약 / 단기계약 / 확인 필요`만 사용하고, 중개 방식은 별도 선택값 `단독중개 / 공동중개 / 확인 필요`로 저장한다.
- 계약 등록·수정·조회 결과와 계약 엑셀에 중개 방식을 표시한다. 기존 계약은 빈값으로 유지한다.
- 이전에 `공동중개`가 계약 유형으로 저장된 경우에는 계약 유형을 `확인 필요`, 중개 방식을 `공동중개`로 안전하게 옮긴다. 운영 DB 열 추가 전 보호 사본을 남긴다.

### 상담·매물 입력 및 오늘 할 일 화면 보완 (2026-08-10)

- 상담 조회 목록에 건물명·지번주소·호실을 함께 표시해 같은 건물명도 바로 구분한다.
- 기존 상담은 후속 이력 기능을 강제로 적용하지 않고, 상세 화면의 별도 종료 처리에서 기존 메모·상담일을 유지한 채 종료 사유를 저장하고 다음 연락일을 해제한다.
- 새 매물 등록 화면의 룸 형태 선택값에서는 `분리형 원룸`을 제외한다. 기존 데이터와 다른 관리·조회 화면의 저장값은 바꾸지 않는다.
- 오늘 할 일에서 완료된 8월 8일 계약 업무처럼 과거 처리 업무는 기본 목록에서 숨기고 필요할 때만 확인하도록 정리했다. 실제 브라우저 확인은 남아 있다.

### 광고 템플릿 문구 생성 구현 (2026-08-08)

- 광고관리의 세 번째 메뉴 `광고 문구 만들기`에서 매물 등록·광고 채널 연결 없이 지역·방 형태·보증금·월세·입주 가능일을 직접 입력한다.
- 원룸 기본형·원룸 신축·옵션형·투룸 기본형·투룸 공간·수납형 중 템플릿을 선택하고, 옵션 강조·교통·생활 장점·추가 핵심 포인트를 조합해 `핵심 포인트 / 교통 & 생활 / 이런 분께 추천 / 안내사항` 구조의 제목·본문을 생성한다.
- 원룸·투룸 각각 20개의 `광고 제목 한 줄 템플릿`을 선택할 수 있으며, 선택한 제목은 그대로 사용한다.
- 북수리·공수리·장재리·월천지구는 실제 위치 확인 후 지역별 5개 생활권 문구를 체크박스로 복수 선택할 수 있다. 선택 문구는 모두 본문 `교통 & 생활`에 표시되며, 북수리·공수리·월천지구에는 `삼성전자 온양캠퍼스 출퇴근 편리한 위치`를 후보로 제공한다.
- 생성 결과는 화면에서 직접 수정하고 제목·본문의 복사 아이콘으로 복사한다. 다가구주택 전용면적·계약 가능 여부 안내는 기본으로 넣고, 실매물·실제 호실 사진 문구는 각각 사실 확인 체크 시에만 넣는다. 문구·입력값은 SQLite에 저장하지 않으며 기존 매물·광고 현황에 영향을 주지 않는다.
- 자동 확인: 금액 검사, 방 형태별 템플릿 우선순위, 옵션·지역 문구 조합, 전체 앱 문법 검사 통과. 실제 브라우저 확인은 남아 있다.

### 광고관리 구현 (2026-08-07)

- 상단 `광고관리` 탭에서 현재 매물 회차에 당근·직방·네이버 또는 직접 입력 채널을 복수로 연결한다.
- 같은 매물 회차의 같은 채널은 중복 등록하지 않으며, 상태·마지막 광고 확인일은 기존 행에서 빠르게 수정한다.
- 현재 광고 현황 검색·채널·상태 필터와 직접 입력 채널 이름 검색을 제공한다. 종료된 매물은 기본 목록에서 제외한다.
- 광고 현황은 오늘 할 일과 분리해 광고관리 탭에서만 확인한다.
- 임시 DB로 복수 채널·직접 입력·중복 차단·상태 수정을 확인했다. 실제 브라우저 확인은 남아 있다.

### 매물 보유처 구현 (2026-08-07)

- 매물 회차에 `listing_holder`를 추가했다. 기존 매물은 빈값으로 보존하며, 운영 DB에 새 열을 추가하기 전 `backups` 폴더에 보호 사본을 만든다.
- 신규 등록·기존 호실의 현재 매물 등록·최신 정보 수정에서 크린주택관리·삼성주택관리·한빛주택관리·국제주택관리·개인매물을 선택하거나 직접 입력할 수 있다.
- 매물 현황 리스트의 보유처 열·필터·직접 입력 검색과 현재 매물 엑셀 보유처 열을 추가했다.
- 임시 DB로 직접입력·저장·현황 필터·엑셀 열을 확인했다. 실제 브라우저 확인은 남아 있다.

### 계약 일정·통합 오늘 할 일 구현 (2026-08-07)

- `contracts.balance_due_date`를 호환 마이그레이션으로 추가했다. 실제 운영 DB에 새 열을 더하기 전 `backups` 폴더에 보호 사본을 만들며, 기존 계약의 잔금 예정일은 비워 둔다.
- 계약 등록·조회·수정에 잔금 예정일을 추가했고, 계약 진행 시작일 또는 정식 계약일보다 빠른 날짜는 저장하지 않는다. 계약 조회 엑셀에도 잔금 예정일을 포함한다.
- 계약관리의 `계약 일정`에서 정식 계약·계약금 추가 수령·잔금·임대차 종료의 기준일 이전 미처리 일정과 30일 이내 일정을 표시한다. 계약 진행 시작일은 가계약·구두 합의 이력으로만 관리한다. 임대차 만료는 당일·지남/7일/8~15일/16~30일로 분류하고, 30·15·7일 누적 수치를 제공한다.
- 첫 메뉴 `오늘 할 일`에서 매물 재확인·퇴실 예정, 계약 일정, 상담 다음 연락을 오늘/지연으로 나눠 표시한다. 사진·현장·상태 업무는 상시 확인 필요로 분리하며, 건물 정보 재확인은 제외하고 별도 완료 기록은 만들지 않는다.
- 오늘 할 일의 상시 확인 필요 목록은 건수만 보이는 기본 접힘 상태로 표시하며, 펼쳤을 때만 매물 표를 보여 준다.
- 오늘·지연의 매물 업무 표와 오늘 할 일 엑셀에는 해당 매물의 퇴실 예정일을 별도 열로 표시한다.
- 퇴실 예정 업무는 기준일 당일에만 오늘 할 일에 표시하며, 지난 퇴실 예정일은 지연 목록에 넣지 않는다.
- 매물 현황 리스트에는 퇴실 예정일·재확인일과 연결된 진행 중 상담의 가장 이른 다음 연락일을 함께 표시한다. 고객 정보와 상담 내용은 표시하지 않는다.
- 선택한 기준일의 오늘·지연·상시 확인 필요 업무를 엑셀로 내보낼 수 있으며, 파일에는 연락처·비밀번호·내부 메모를 넣지 않는다.
- 임시 DB로 기존 계약 보존·잔금 예정일 검증·일정 계산·오늘/지연 분리·개인정보 미표시를 확인했다. 실제 브라우저 확인은 남아 있다.

## 운영 연결·자동 백업 상태 (2026-08-10)

- 메인 PC와 서브 PC의 Tailscale 연동을 완료했다.
- 메인 PC의 Streamlit은 `127.0.0.1:8501`에서 실행하고, Tailscale Serve의 기존 HTTPS 주소를 통해 서브 PC에서 접속하는 방식으로 사용한다.
- 일반 인터넷 공개, 공유기 포트 포워딩, Tailscale Funnel은 사용하지 않는다.
- 메인 PC는 Windows 자동 로그인 환경이다. 재부팅 뒤 Streamlit까지 자동 실행되도록 하는 작업 스케줄러 설정 절차는 `docs/streamlit_windows_auto_start_guide.md`에 기록했다.
- `RealEstate Streamlit` 예약 작업과 `start_streamlit.bat`를 2026-08-06에 등록했다. 기존 수동 Streamlit을 정상 종료한 뒤 예약 작업을 수동 실행하여 `http://127.0.0.1:8501`의 HTTP 200 응답을 확인했다.
- OneDrive 로컬 동기화 폴더 `Documents\매물관리백업\daily`에 날짜별 SQLite 사본을 만들고, 무결성 검사를 통과한 사본만 확정한다. 최근 10일만 유지하며, 백업 결과와 마지막 상태는 `logs\backup.log`, `logs\backup_status.json`에 기록한다.
- OneDrive 데스크톱 앱 동기화가 2026-08-08에 정상 동작하는 것을 확인했다. 웹사이트 로그인만으로는 동기화되지 않으므로 데스크톱 앱을 로그인·실행·자동 시작 상태로 유지한다.
- 남은 운영 확인: 메인 PC 재부팅 후 자동 로그인·30초 지연·Streamlit 자동 실행과 서브 PC HTTPS 접속이 모두 이어지는지, 별도 위치에서 백업 파일을 열어 복구할 수 있는지 실제로 확인한다.

### 오늘 할 일 업무별 분리·계약 연동·상담 빠른 확인 (2026-08-08)

- 계약 상태를 `계약 진행` 또는 `잔금 예정`으로 바꾸면 연결 매물은 `계약 진행 중`으로, `계약 완료`면 `계약 완료`·종료 사유 `계약 완료`·당일 종료일로 바뀐다. `해지/만료`는 아직 종료되지 않은 `계약 진행 중` 매물만 `공실`로 되돌리며, 이미 종료된 매물은 자동 재오픈하지 않는다.
- 잔금 예정일은 전날(D-1)에 `잔금 예정 (D-1 알림)`으로 오늘 업무에 미리 표시하며, 잔금 당일의 `잔금 예정` 업무와 완료 체크는 별도로 관리한다.
- 상담 상태 변경은 해당 상담 기록만 갱신한다. 상담 내용·고객 연락처는 선택한 상담 아래에서만 표시한다. 완료 체크는 계속 일정 처리 표시이며 원본 상태를 자동 변경하지 않는다.
- 상담 표의 `다음 연락일`은 바로 수정하거나 비울 수 있다. `종료` 상태로 바꾸면 다음 연락일은 자동 취소되며, 날짜 변경 결과는 오늘·지연 업무에 즉시 다시 반영된다.

## 메인 PC 2인 전용 운영 상태 (2026-08-10)

- 운영 데이터는 메인 PC의 `C:\realestate-main\storage\real_estate.db` 한 곳만 사용하며, 사용자 PC에는 SQLite 파일이나 프로그램을 설치하지 않는다.
