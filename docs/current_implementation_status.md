### 추가 계획: 계약관리

- 계약관리는 별도 탭으로 만들되, 계약을 건물·호실에 직접 붙이지 않고 해당 매물 회차에 연결한다.
- 단기계약과 일반 계약의 시작일·종료일·기간·상태를 누적 관리한다.
- 계약자 연락처와 계약금·잔금은 계약 기록의 내부정보로 관리한다. 납부·결제 관리와 계약서 파일은 관리하지 않는다.

### 추가 계획: 상담관리

- 상담관리는 계약관리와 분리한 가벼운 CRM 탭으로 만든다.
- 전화·문자·방문 등 상담 이력과 다음 연락일만 매물 회차에 연결해 누적한다.
- 고객 이름·연락처는 상담 상세에서만 관리하고, 자동 문자·방문 예약·민감 개인정보는 관리하지 않는다.

- 별도 임시 데이터 파일에서 매물 1건, 계약 1건, 상담 1건을 만든 뒤 삭제하여 매물·계약·상담은 0건, 건물·호실은 각각 1건으로 남는 것을 자동 확인했다.
- 실제 브라우저에서 삭제 화면과 안내 문구를 직접 눌러 보는 확인은 남아 있다.

### 매물 등록 건물 주소 입력 단순화 (2026-08-04)

- `매물 등록·수정` 탭의 새 건물 정보에서 행정주소와 도로명주소 입력칸을 제거했다.
- 새 건물 등록·검색·중복 확인은 건물명과 지번을 기준으로 계속 처리한다.
- 기존에 저장된 행정주소·도로명주소 값은 삭제하지 않고 유지한다.
- 내부 업무용 엑셀 내보내기에서도 행정주소·도로명주소 열은 제외하고, 건물명과 지번주소만 내보낸다.

### 종료된 매물 조회 필터 추가 (2026-08-04)

- 매물 현황 리스트에 `현재 매물만 / 종료된 매물만 / 전체` 필터를 추가했다.
- 종료된 매물은 표에서 종료일과 종료 사유를 확인할 수 있으며, 현황 리스트에서는 조회만 한다.
- 종료 사유에 `타 부동산 계약`을 추가해, 다른 부동산에서 계약된 경우를 구분해 기록할 수 있다.
- 현재 매물의 빠른 수정과 엑셀 내보내기는 기존처럼 현재 매물만 대상으로 유지한다.

### 계약·상담 기록 삭제 추가 (2026-08-04)

- 계약 조회·수정에서 선택한 계약 기록을 확인 후 완전 삭제할 수 있게 했다.
- 상담 조회·수정에서 선택한 상담 기록을 확인 후 완전 삭제할 수 있게 했다.
- 계약 또는 상담을 삭제해도 연결된 매물 기록과 다른 종류의 기록은 유지된다.

### 일반 상담 추가 (2026-08-04)

- 상담 등록에서 `매물 상담 / 일반 상담`을 선택할 수 있게 했다.
- 일반 상담은 매물을 고르지 않고 고객 정보, 상담 내용, 희망 지역·방 형태·보증금·월세를 저장한다.
- 일반 상담은 나중에 상담 상세에서 맞는 매물 회차를 연결할 수 있다.
- 기존 매물 상담 기록은 그대로 유지하며, 일반 상담을 저장할 수 있도록 데이터 구조를 안전하게 보완했다.

### 13단계 진행: 계약·상담 저장소 분리 (2026-08-03)

- `storage/contract_repository.py`로 계약 저장·조회·수정 코드를 분리했다.
- `storage/consultation_repository.py`로 상담 저장·조회·수정 코드를 분리했다.
- `storage/export_repository.py`로 엑셀용 현재 매물 조회 코드를 분리했다.
- `storage/building_repository.py`로 건물·호실 관리 화면의 검색·상세·수정·이력 조회 코드를 분리했다.
- `storage/listing_repository.py`로 매물 현황 리스트의 조회·필터·빠른 수정 코드를 분리했다.
- `storage/listing_write_repository.py`로 현재 매물 수정·종료·재등록 저장 코드를 분리했다.
- `storage/listing_create_repository.py`로 새 건물·호실과 첫 매물을 함께 등록하는 저장 코드를 분리했다.
- 계약·상담 화면과 서비스가 새 저장소 파일을 사용하도록 변경했다.
- 임시 단일 데이터 파일에서 계약·상담 등록과 조회가 동일하게 동작하는 것을 자동 확인했다.
- 매물 등록 화면의 건물·호실 조회, 계약·상담 화면의 매물 회차 검색도 각각의 업무 파일을 사용하도록 연결했다.
- 임시 단일 데이터 파일에서 새 건물·호실·첫 매물 등록과 기존 건물에 새 호실 추가가 정상 동작하고, 건물 1건·호실 2건·매물 2건으로 정확히 저장되는 것을 자동 확인했다.
- `database.py`에서 예전 업무 코드 사본을 제거했다. 이제 공통 연결, 표 생성, 기존 데이터 파일 호환 처리만 남는다.
- 새 임시 데이터 파일에서 건물·호실·매물·계약·상담 등록과 조회, 엑셀용 조회를 함께 자동 확인했다. 실제 `real_estate.db` 파일은 열거나 수정하지 않았다.

### 기존 호실 최신 정보 수정 방식 전환 (2026-08-04)

- 기존 건물에서 호실을 선택하면 최신 매물 정보 입력칸이 바로 열린다.
- 저장하면 새 매물 회차를 만들지 않고 같은 최신 매물 기록의 가격·상태·입주일 등을 갱신한다.
- 종료된 최신 매물도 새 상태를 저장하면 종료 상태를 지우고 다시 최신 매물로 사용한다.
- 연결된 계약·상담 기록은 같은 매물 기록에 계속 유지된다.
- 최신 정보 수정 화면에서도 호실 옵션 체크박스와 기타 옵션 메모를 불러와 수정할 수 있다.
- 실제 브라우저에서 기존 호실 선택 → 최신 정보 저장 → 계약·상담 기록 유지 확인은 남아 있다.

### 호실 옵션 체크 입력 (2026-08-04)

- 새 건물·호실 등록과 기존 건물의 새 호실 등록에서 냉장고, 세탁기, 에어컨, 가스렌지, 인덕션, 옷장, 신발장을 체크박스로 선택할 수 있게 했다.
- 목록에 없는 옵션은 `기타 옵션 메모`에 입력할 수 있으며, 선택값과 함께 호실 기본정보에 저장한다.
- 기존 매물 회차의 정보는 바꾸지 않는다.

### 잘못 만든 호실 완전 삭제 (2026-08-04)

- 기존 호실 최신 정보 수정 화면과 현재 매물 등록 화면에서 `이 호실 완전 삭제`를 선택할 수 있게 했다.
- 삭제 전 매물·계약·상담 기록의 개수를 표시하고, 확인 체크 후에만 삭제한다.
- 호실과 연결된 매물·계약·상담 기록은 함께 삭제되며, 건물 정보는 남는다.
- 실제 브라우저에서 삭제 안내와 삭제 후 기존 호실 목록에서 사라지는지 확인은 남아 있다.

### 등록·현황 확인 업무 기준 통일 (2026-08-04)

- 매물 등록과 기존 호실 최신 정보 수정에 `확인·관리 사항`을 추가했다. 사진 보유 여부, 청소·도배·수리 상태, 재확인 예정일을 같은 자리에서 저장한다.
- `해야 할 일`은 직접 입력하지 않고, 위 상태와 사진 상태·입주 가능 유형·매물 상태를 바탕으로 현황 리스트에서 자동 표시한다.
- 현황 리스트의 빠른 수정도 사진 보유 여부, 청소·도배·수리 상태, 재확인 예정일을 동일하게 수정한다.
- 임시 데이터에서 신규 저장 → 최신 정보 수정 → 현황 빠른 수정 뒤 사진·현장·재확인 업무가 각각 정확히 표시·해제되는 것을 자동 확인했다. 실제 브라우저 입력 확인은 남아 있다.
- 현황 리스트 표에 청소·도배·수리 상태를 함께 보여 주고, 빠른 수정 저장 직후에는 저장한 값을 요약해 표시하도록 보완했다.
- 사진 상태를 `촬영 완료`로 저장하면 사진 보유 여부도 자동으로 `있음`으로 맞춘다. 이전 데이터에서 촬영 완료와 사진 없음이 함께 남아 있어도 사진 촬영 필요 업무는 표시하지 않는다.

## 추가 운영 계획: 메인 PC 이전 및 2인 전용 접속 (2026-08-03)

- 개발과 기능 확인이 끝난 뒤 프로젝트 폴더 전체와 SQLite 데이터 파일을 사무실 메인 PC로 옮긴다.
- 운영 데이터 파일은 GitHub·Streamlit Community Cloud에 올리지 않는다.
- 초기 운영은 메인 PC에서 Streamlit과 SQLite를 실행하고, 두 사용자만 Tailscale 개인 네트워크로 접속하는 방식으로 계획한다.
- 사용자 PC에는 데이터 파일을 두지 않으며, 메인 PC의 데이터 파일 한 곳만 사용한다. 메인 PC에서만 실행 중인 프로그램은 Tailscale Serve로 연결하고, 일반 인터넷 공개 기능은 사용하지 않는다.
- 메인 PC 재시작, 두 사용자 동시 조회·저장, 이전 전후 데이터 건수, 백업 복구 확인을 이전 완료 조건으로 둔다.
- 메인 PC 상시 실행이 어려워질 때만 로그인·권한 보호를 포함한 Supabase 전환을 별도 계획으로 검토한다.
