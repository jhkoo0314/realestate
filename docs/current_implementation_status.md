### 계약 일정·통합 오늘 할 일 구현 (2026-08-07)

- `contracts.balance_due_date`를 호환 마이그레이션으로 추가했다. 실제 운영 DB에 새 열을 더하기 전 `backups` 폴더에 보호 사본을 만들며, 기존 계약의 잔금 예정일은 비워 둔다.
- 계약 등록·조회·수정에 잔금 예정일을 추가했고, 계약 진행 시작일보다 빠른 날짜는 저장하지 않는다. 정식 계약일보다 이른 잔금 예정일도 실제 업무 순서에 맞게 저장할 수 있다. 계약 조회 엑셀에도 잔금 예정일을 포함한다.
- 계약관리의 `계약 일정`에서 정식 계약·계약금 추가 수령·잔금·임대차 종료의 기준일 이전 미처리 일정과 30일 이내 일정을 표시한다. 계약 진행 시작일은 가계약·구두 합의 이력으로만 관리한다. 임대차 만료는 당일·지남/7일/8~15일/16~30일로 분류하고, 30·15·7일 누적 수치를 제공한다.
- 첫 메뉴 `오늘 할 일`에서 매물 재확인·퇴실 예정, 계약 일정, 상담 다음 연락을 오늘/지연으로 나눠 표시한다. 사진·현장·상태 확인은 매물 현황에서 확인하며, 오늘 할 일에서는 제외한다. 건물 정보 재확인은 제외하고 별도 완료 기록은 만들지 않는다.
- `퇴실 예정` 상태의 현재 매물은 퇴실 예정일이 오늘보다 지나면 앱 실행 시 자동으로 `공실`로 바뀐다. 퇴실일 당일에는 오늘 할 일을 유지하고, 계약 완료·종료 또는 다른 상태의 매물은 자동 변경하지 않는다.
- 오늘·지연의 매물 업무 표와 오늘 할 일 엑셀에는 해당 매물의 퇴실 예정일을 별도 열로 표시한다.
- 퇴실 예정 업무는 퇴실 7일 전부터 전날까지 매일 `퇴실 예정 확인 (D-n 알림)`으로, 퇴실 당일에는 `퇴실 예정`으로 오늘 할 일에 표시하며 날짜별 완료 체크를 분리한다. 지난 퇴실 예정일은 지연 목록에 넣지 않는다.
- 임시 데이터로 D-7·D-6·D-1·당일 표시, D-8·지난 날짜 미표시, 날짜별 완료 키 분리를 자동 확인했다. 실제 브라우저 확인은 남아 있다.
- 매물 현황 리스트에는 퇴실 예정일을 표시한다. 재확인일과 연결된 진행 중 상담의 다음 연락일은 표 열에서 숨기고, 재확인 관리·오늘 할 일·상담관리에서 확인한다. 고객 정보와 상담 내용은 표시하지 않는다.
- 매물 현황 상단의 재확인 현황은 `재확인 관리` 하나로 표시한다. 오늘·지연 재확인과 오늘 다음 날부터 7일째까지의 예정 재확인을 합산하고, 아래 문구에서 각각의 건수를 구분한다.
- `재확인 대상 매물 보기`를 펼치면 재확인 관리 건수와 같은 기준의 대상 매물번호·구분·재확인일·건물·호실·보유처를 확인할 수 있다.
- 선택한 기준일의 오늘·지연 업무를 엑셀로 내보낼 수 있으며, 파일에는 연락처·비밀번호·내부 메모를 넣지 않는다.
- 임시 DB로 기존 계약 보존·잔금 예정일 검증·일정 계산·오늘/지연 분리·개인정보 미표시를 확인했다. 실제 브라우저 확인은 남아 있다.

- 상담 상태 변경은 해당 상담 기록만 갱신한다. 상담 내용·고객 연락처는 선택한 상담 아래에서만 표시한다. 완료 체크는 계속 일정 처리 표시이며 원본 상태를 자동 변경하지 않는다.
- 상담 표의 `다음 연락일`은 바로 수정하거나 비울 수 있다. `종료` 상태로 바꾸면 다음 연락일은 자동 취소되며, 날짜 변경 결과는 오늘·지연 업무에 즉시 다시 반영된다.

### 매물 보증금·월세 범위 필터 (2026-08-07)

- 매물 현황 리스트에 보증금과 월세의 최소·최대 금액(만원) 필터를 각각 추가했다.
- 두 가격 범위는 기존 검색·상태·룸 형태·사진·확인 업무 필터와 함께 적용한다. 가격이 비어 있는 매물은 해당 가격 범위를 선택했을 때 제외한다.
- 최대 금액이 최소 금액보다 작으면 조회하지 않고 안내한다. 실제 브라우저에서 단일·복합 필터 확인은 남아 있다.

### 매물 현황 표 지번 함께 표시 (2026-08-07)

- 매물 현황 리스트 표에서 건물명과 지번을 독립 열로 나란히 표시해, 건물명이 같은 후보도 바로 구분할 수 있게 했다.
- 기존 건물명·지번·호수 통합 검색은 그대로 유지한다. 실제 브라우저에서 지번 검색과 표기 확인은 남아 있다.

### 지번 지역·번호 분리 입력·표시 (2026-08-07)

- 매물 등록·수정과 건물·호실 관리의 건물정보 수정은 `지번 지역`, `번지 번호`를 분리 입력한다.
- 저장과 통합검색은 기존 `lot_address` 한 열에 두 값을 합친 지번값을 계속 사용한다. DB 열 추가와 기존 데이터 일괄 변경은 하지 않는다.
- 매물 현황 리스트와 내부 업무용 매물 엑셀에는 지번 지역·번호를 각각 독립 열로 표시한다. 매물 엑셀에서는 중복되는 지번주소 열을 제외한다. 기존 데이터는 안전하게 분리할 수 있는 경우에만 표시용으로 나누고, 원문은 보존한다.
- 기존 지번 형식을 안전하게 나눌 수 없는 경우에는 원문을 유지하며, 코드 기본 확인을 마쳤다. 실제 브라우저 확인은 남아 있다.

### 계약 일정·통합 오늘 할 일 구현 완료 (2026-08-07~08)

- 계약 기록에 잔금 예정일을 추가하고, 계약 진행·정식 계약·계약금 추가 수령·잔금·임대차 종료 일정을 기준일별로 계산한다.
- 계약 일정은 당일·지연·7일·8~15일·16~30일을 구분하며, 30·15·7일 누적 수치를 제공한다.
- 오늘 할 일은 매물·계약·상담의 날짜 업무를 오늘/지연으로, 사진·현장·상태 업무를 상시 확인 필요으로 나눠 표시한다. 날짜 업무의 완료 체크는 원본 일정·상태를 바꾸지 않는다.
- 계약 상태 변경은 연결 매물에만 규칙대로 반영하고, 상담 상태·다음 연락일 변경은 해당 상담 기록에만 반영한다. 기본 표와 오늘 할 일 엑셀에는 연락처·비밀번호·내부 메모를 넣지 않는다.
- 임시 DB 자동 확인을 마쳤고, 실제 브라우저에서 업무 표·완료 체크·상태 연동을 확인해야 한다.

## 메인 PC 2인 전용 운영 상태 (2026-08-10)

- 운영 데이터는 메인 PC의 `C:\realestate-main\storage\real_estate.db` 한 곳만 사용하며, 사용자 PC에는 SQLite 파일이나 프로그램을 설치하지 않는다.
- Streamlit은 메인 PC의 `127.0.0.1:8501`에서만 실행하고, 허가된 사용자 PC는 Tailscale Serve HTTPS 주소로 접속한다. Funnel, 공유기 포트 포워딩, `0.0.0.0` 공개 바인딩은 사용하지 않는다.
- 메인 PC·서브 PC Tailscale 연동, Serve 설정, 예약 작업 등록과 수동 실행 확인은 끝났다. 재부팅 후 자동 로그인·자동 실행·서브 PC HTTPS 접속, 두 사용자 동시 저장 반영, 백업 복구 시험은 아직 실제 확인이 필요하다.
- 운영 데이터와 백업 파일은 GitHub·공개 링크·개인 기기에 올리거나 공유하지 않는다.

### 퇴실 예정일 경과 자동 정리 보완 (2026-08-25)

- 퇴실 예정일이 지난 현재 매물은 앱 실행 시 `공실`로만 바꾸지 않고, 입주 가능 유형을 `즉시입주`로 바꾸며 입주 가능일·퇴실 예정일을 함께 비운다.
- 과거 자동 전환으로 이미 `공실`이지만 지난 퇴실 예정일이 남은 기록도 같은 기준으로 한 번 정리한다. 퇴실 예정일 당일은 여전히 자동 전환하지 않는다.
- 임시 데이터베이스 자동 확인을 추가했다. 실제 브라우저에서 상태 전환·표시 확인은 남아 있다.

### 기존 호실 새 매물 상태 기본값 (2026-08-25)

- 종료된 기존 호실에 현재 매물을 다시 등록할 때, 매물 상태 선택의 기본값을 `확인 필요`에서 `공실`로 바꿨다. 새 건물·호실의 첫 매물 등록은 이미 `공실` 기본값을 사용하고 있었다.
- 기존 매물의 최신 정보 수정 화면은 저장된 상태를 계속 그대로 표시한다. 실제 브라우저에서 재등록 화면의 기본 선택 확인은 남아 있다.

### 오늘 할 일 상시 확인 항목 제거 (2026-08-27)

- 오늘 할 일 화면에서는 날짜가 없는 사진·현장·상태 확인 업무를 제거했다. 오늘·지연의 매물·계약·상담 날짜 업무만 요약·표·엑셀에 표시한다.
- 날짜 없는 확인 업무는 기존처럼 매물 현황의 확인 업무에서 관리한다. 실제 브라우저에서 오늘 할 일 화면과 엑셀 확인은 남아 있다.

### 상담에서 계약 등록 화면 전환 오류 수정 (2026-08-27)

- 상담 상세의 `이 상담으로 계약 등록`을 누른 뒤 상단 메뉴 위젯 값을 같은 실행에서 바꾸려던 오류를 수정했다. 이제 다음 실행 시작 시 적용할 화면 전환 요청을 저장한 뒤 계약관리 등록 화면으로 이동한다.
- 실제 브라우저에서 상담 상세에서 계약 등록으로 이동하는 확인은 남아 있다.

### 계약 단계 이력의 잔금 완료 기록 (2026-08-28)

- 계약 단계 이력의 새 입력값을 `잔금 예정`에서 `잔금 완료`로 바꿨다. 이력은 실제 처리 결과를 기록하며, 미래 잔금 일정은 계약 기본정보의 잔금 예정일에서 관리한다.
- `잔금 완료` 이력은 계약·연결 매물을 진행 중으로 유지한다. 사용자가 `계약 완료` 이력을 선택할 때만 매물 종료를 자동 반영한다. 기존에 저장한 `잔금 예정` 이력은 표시·수정 시 그대로 보존한다.

### 정식 계약일 전 잔금 예정일 허용 (2026-08-28)

- 잔금 예정일이 정식 계약일보다 빠른 실제 업무 순서를 저장할 수 있도록 날짜 제한을 제거했다. 잔금 예정일은 계약 진행 시작일보다만 빠르지 않게 검사한다.

### 상담 종료 입력 흐름 정리 (2026-08-28)

- 후속 상담 이력의 `결과 단계`를 `이번 상담 결과`로 바꾸고, 저장값 `종료`는 화면에서 `상담 종료`로 표시한다.
- 상담 종료를 선택한 경우에만 종료 사유를 필수로 보여 주며, 저장 시 상담 종료와 다음 연락일 해제를 안내한다. 진행 단계에는 종료 사유를 숨기고 다음 연락일만 입력한다.
- `이번 상담 결과` 선택칸은 입력 폼 밖에 두어, `상담 종료`를 선택하는 즉시 종료 사유 입력칸이 표시된다.

### 집중 대응 상담의 계약 연동 제외 (2026-08-28)

- 집중 대응은 다음 연락일 도래·지연 또는 상담 등록 후 3일 이내의 상담만 대상으로 계산한다. 다만 출처 상담에 계약 진행·잔금 예정·계약 완료 계약이 연결돼 있으면 추천 대상에서 제외한다.
