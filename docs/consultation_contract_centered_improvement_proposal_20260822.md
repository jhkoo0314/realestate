> 작성일: 2026-08-22  
> 목적: 상담 등록 → 조건 확인 → 방문 → 계약 연결 흐름을 더 빠르고 일관되게 만들고, 광고관리를 월별 광고비 기록과 광고 문구 만들기로 정리하는 제안서다.

## 0. 점검 범위와 운영 데이터 검증

- 당시 프로젝트 규칙 파일은 단수형 이름이었으며, 현재는 `AGENTS.md`를 사용한다. `README.md`, 현재 구현 상태, 데이터 사전, 화면 명세, 테스트 기준, 상담·계약 구현 계획, 관련 코드와 운영 SQLite DB를 읽기 전용으로 점검했다.
- 운영 DB는 `storage/real_estate.db`이며, 표 구조와 데이터는 변경하지 않았다.
- 제공된 전체 집계는 아래와 같이 실제 DB와 일치했다.

| 항목 | DB 재조회 결과 |
|---|---:|
| 활성 건물 / 전체 매물 / 상담 / 방문 상담 | 131 / 226 / 42 / 24 |
| 계약 / 계약 완료 / 계약 진행 / 잔금 예정 | 12 / 10 / 1 / 1 |
| 단독중개 / 공동중개 | 8 / 4 |
| 계약의 출처 상담 연결 | 12건 모두 연결됨 |

유입경로별 상담·방문·계약 생성·계약 완료도 `당근 22/12/5/4`, `네이버 10/4/2/2`, `워크인 4/4/2/2`, `타 부동산 연계 3/3/2/2`, `직방 3/1/1/0`으로 일치했다.

상담일부터 정식계약일까지의 중앙값은 2일이고, 12건 중 10건이 4일 이내다. 다만 1건은 정식계약일이 상담일보다 하루 빠르게 저장돼 있어, 속도 지표에는 날짜 오류 표시가 필요하다.

방 유형의 제공 수치도 기존 단일 필드 기준으로 원룸 19건, 투룸 16건이다. 복수 희망값까지 문자열 검색으로 합치면 원룸 21건, 투룸 18건이 되어, 앞으로는 복수 선택 저장 규칙을 하나로 정해야 한다. 현재 소개 가능 재고 역시 `공실`, `퇴실 예정`, `계약 진행 중` 포함 여부에 따라 달라지므로 대시보드에 기준을 함께 표시해야 한다.

### 문서와 코드의 차이

- 이전 상담 진행관리 계획의 본문에는 새 상담 단계로 `계약 진행 / 계약 완료`가 남아 있으나, 실제 코드는 새 상담 선택값에서 이를 숨기고 계약관리의 자동 연동으로 처리한다.
- 데이터 사전과 최신 계약-상담 계획은 출처 상담 연결을 설명하지만, 현재 상담 화면에서는 계약에 연결된 상담의 후속 이력을 편집하지 못하게 막는다. 이는 계약 상태가 상담 상태를 담당하도록 한 안전장치다.
- 현재 날짜 계산은 여러 파일에서 `date.today()`를 직접 사용한다. 메인 PC가 한국 시간으로 설정돼 있으면 현재는 맞지만, 명시적인 한국 시간 기준은 아니다.

## 2. 개선 기능 우선순위

### 1차 필수 개선

1. 상담 등록의 지역·방 유형을 표준 선택값으로 바꾸되, 모두 선택 입력으로 유지한다.
2. `desired_room_types`를 새 상담의 기준 필드로 정하고, 기존 `desired_room_type`은 호환 표시용으로만 유지한다.
3. 상담 목록에 **오늘 접수 / 1일 이내 / 2~3일 / 다음 연락 오늘 / 다음 연락 지연** 집중 대응 배지와 필터를 추가한다.
4. 다음 연락일은 현재처럼 사용자가 필요할 때 직접 입력·수정·해제한다. 자동 제안이나 자동 변경은 만들지 않는다.
5. 종료 사유를 모든 경로에서 선택 입력으로 통일한다.
6. 계약 등록·상세에 연결 상담 요약을 표시하고, 출처 상담 없는 계약은 명시적 `상담 없이 계약` 선택으로 유지한다.
7. 광고관리 1차 범위를 매물별 광고 기능 삭제 후 **월별 광고비 기록 + 광고 문구 만들기**로 바꾼다.

### 2차 권장 개선

1. 지역·방 유형의 기존 자유입력값을 화면에서 `기존 입력값`으로 표시하고, 사용자가 저장할 때만 표준값으로 다시 선택하게 한다.
2. 현재 소개 가능 재고와 희망 방 유형·지역 수요를 같은 화면에 비교한다.
3. 상담 상세에서 현재 매물 후보를 단순 필터 결과로 보여 준다. 점수·AI 추천·자동 연결은 만들지 않는다.

### 보류

- 주차·엘리베이터·반려동물·단기계약의 개별 상담 컬럼: 1차에는 `required_features_note`의 선택 메모로 유지한다. 반복적으로 필터·통계가 필요하다고 확인될 때만 별도 항목을 검토한다.
- 별도 지역 테이블, 고객 테이블, 자동 문자·알림, 복잡한 추천 점수, 광고 플랫폼 연동.

### 삭제 (승인된 실제 구현 범위)

- 기존 매물별 광고 조회, 매물 연결, 게시 채널·상태·마지막 확인일 입력과 관련 코드를 삭제한다.
- 실제 DB 변경 전 `listing_advertisements`의 행 수와 백업 파일을 확인하고, 백업 검증 후 해당 표와 데이터를 삭제한다. 이 문서 반영 단계에서는 삭제하지 않는다.
- 광고 문구 만들기는 월별 광고비 기록과 함께 광고관리 화면에 유지한다.

### 현재 상태 유지

- 계약의 실제 매물 연결과 출처 상담 연결을 분리하는 구조.
- 계약 완료 시 출처 상담 종료·다음 연락일 해제, 해지·삭제 시 상담 자동 재개 금지.
- 종료 사유 데이터 보존, 오늘 할 일의 완료 체크가 원본 상태를 바꾸지 않는 원칙.

## 3. 화면별 변경안

### 상담 등록 화면

| 구분 | 제안 |
|---|---|
| 추가되는 항목 | 지역 복수 선택, 방 유형 복수 선택, `기타` 입력칸(각각 기타 선택 때만 표시) |
| 변경되는 항목 | 자유입력 지역·방 형태를 표준 선택으로 변경. 유입경로는 기존 선택값을 유지하되 `미입력` 선택을 허용 |
| 삭제·숨김 | 같은 목적의 방 형태 입력칸을 두 개 보여 주지 않음 |
| 자동 처리 | 상담일은 오늘 날짜 기본값, 진행 단계는 `신규 문의` |
| 사용자 입력 | 유입경로·지역·방 유형·예산·입주일·필수 조건은 모두 선택 입력. 최소 등록은 상담 구분과 기본 상담 기록만으로 가능 |

**조건 분류**

| 분류 | 항목 | 권고 |
|---|---|---|
| 시스템 기본값 | 상담일, 진행 단계, 상담 상태 | 자동 입력. 사용자를 막는 필수 입력으로 만들지 않음 |
| 입력하면 좋은 선택항목 | 유입경로, 지역, 방 유형, 입주 예정일, 보증금, 월세 | 성과 분석·추천에 직접 쓰므로 빠른 선택값 제공 |
| 기존 메모로 충분 | 관리비 포함 월 총예산, 주차·엘리베이터·반려동물·단기계약, 기타 필수조건 | 1차에는 `required_features_note`에 짧게 기록. 빈값 경고 없음 |
| 현재 단계 불필요 | 고객 등급, 계약 가능성 점수, 상세 결제·광고 채널 연결 | 입력 부담 대비 업무 가치가 낮거나 범위 밖 |

### 상담 상세 화면

- 상단에 `집중 대응 상태`를 배지로 표시한다. 예: `오늘 접수 · 1차 추천 확인`, `상담 후 2일 · 추가 추천 확인`, `다음 연락 지연`.
- 기존 활동 이력은 그대로 두고, 활동 저장 때 마지막 연락일이 자동 갱신되는 현재 동작을 유지한다.
- 종료 사유 메뉴는 항상 선택 가능하되 비워도 저장할 수 있게 한다. 종료하면 다음 연락일만 자동 해제한다.
- 계약에 연결된 상담은 현재처럼 계약관리에서 계약 상태를 처리한다. 상담 화면에서 계약 상태를 임의로 바꾸지 않는다.

### 상담 목록

- 새 필터: `집중 대응만`, `오늘 1차 추천`, `72시간 추가 추천`, `다음 연락 지연`, `방문 예정`.
- 새 표시: 상담일, 최근 상담일, 다음 연락일을 기반으로 한 짧은 배지. 별도 상태값·별도 완료 체크는 저장하지 않는다.
- 목록의 고객 연락처 공개 범위는 현재 내부 상담 목록 정책을 그대로 유지한다.

### 오늘 할 일

- `다음 연락 오늘/지연`은 현재 표와 완료 체크를 유지한다.
- 24/72시간은 같은 상담을 별도 완료 업무로 중복 생성하지 않는다. 오늘 할 일 상담 행 또는 상담 목록의 안내 배지로만 표시한다.
- 종료·계약 완료 상담은 집중 대응·다음 연락 목록에서 제외한다.

### 계약 등록 화면

- `계약으로 이어진 상담 (선택)`은 유지한다. 선택하지 않으면 `상담 없이 계약`임을 명시한다.
- 선택한 상담 아래에 내부 업무용 요약을 표시한다: 상담번호, 유입경로, 희망 지역, 희망 방 유형, 예산, 입주 가능일, 최근 방문 결과, 최근 상담일. 상담 내용 전체는 펼쳐서만 본다.
- 고객 이름·연락처 자동 입력은 유지한다. 원래 상담 매물은 바꾸지 않는다.

### 계약 상세 화면

- 연결 상담 요약과 현재 동기화 상태를 표시한다.
- 기존 계약에 상담을 새로 연결할 때만 `현재 계약 상태를 연결 상담에 반영` 체크를 보이고, 그 이유를 짧게 설명한다.
- 계약 완료는 출처 상담을 종료하고 다음 연락일을 해제한다. 계약 해지·만료·삭제는 상담을 자동 재개하지 않으며, 필요하면 사용자가 상담에서 직접 후속 관리로 되돌린다.

### 대시보드·리포트

- 상담·방문·계약·광고비 성과 리포트는 만들지 않는다.
- 기존 매물 현황 대시보드는 현재 기능을 유지한다. 이번 범위에서 유입경로별 전환율, 재고-수요 비교, 계약 속도 통계는 추가하지 않는다.

### 광고관리 화면

- 화면 이름을 **광고비 기록**으로 바꾼다.
- 1차 입력은 `기준연월`, `광고 채널`, `월 광고비`, `메모` 네 항목뿐이다. 채널은 당근·네이버·직방·기타를 선택하고, 기타일 때만 이름을 직접 입력한다.
- `현재 광고 현황`, `매물에 광고 채널 연결`, 매물별 광고 상태·마지막 확인일 입력은 화면과 DB에서 삭제한다. 삭제 전 검증된 백업을 남긴다.
- 같은 기준연월·광고 채널은 한 행만 사용한다. 금액 정정은 같은 행을 수정하고, 삭제는 명시적 확인 후에만 허용한다.
- 월별 광고비는 기록·정정 목적만으로 사용한다. 상담·방문·계약 건당 비용이나 전환율 리포트는 만들지 않는다.
- 광고 문구 만들기는 데이터 저장과 무관한 보조 기능으로 유지한다.

**표준 저장 방식 제안**

- 지역: 새 상담은 `desired_area`에 표준값을 ` | `로 연결해 저장한다. 예: `북수리 | 탕정역권`. 기타가 있으면 `기타: 천안아산역`처럼 함께 저장한다.
- 방 유형: 새 상담의 기준 값은 `desired_room_types`로 한다. 복수 선택은 `원룸 | 투룸` 형식으로 저장한다. 호환이 필요한 기존 화면·엑셀에는 첫 선택값을 `desired_room_type`에 함께 보관하되, 사용자는 한 번만 선택한다.
- 기존 데이터는 일괄 변경하지 않는다. 조회·리포트에서만 `desired_room_types`가 비어 있으면 `desired_room_type`을 읽는다.

## 5. 업무 흐름 변화

| 현재 흐름 | 개선 후 흐름 |
|---|---|
| 상담 등록 때 지역·방 형태를 자유입력 | 표준 선택값을 빠르게 고르고, 모르면 비워 둠 |
| 다음 연락일을 사용자가 매번 판단 | 사용자가 필요할 때 직접 입력·수정·해제하며, 시스템은 자동 제안하지 않음 |
| 상담 목록에서 기한만 확인 | 오늘/1일/2~3일/지연 배지로 초기 대응 우선순위 판단 |
| 방문 결과는 이력에서 확인 | 방문 결과·최근 방문을 목록과 연결 상담 요약에서 확인 |
| 계약 화면에서 상담을 고르지만 조건은 다시 찾아봄 | 연결 상담의 유입경로·희망조건·방문 결과를 요약으로 바로 확인 |
| 광고 매물 연결을 관리함 | 월별 광고비 기록과 광고 문구 만들기만 관리 |

### 실제 사용자 행동 순서

1. **신규 문의 등록**: 상담 구분을 고르고, 유입경로와 아는 희망조건만 선택한다. 모르는 항목은 비워 둔다.
2. **고객 조건 확인**: 지역·방 유형·예산·입주일을 보완하고, 특수 조건은 짧은 메모로 남긴다.
3. **매물 추천**: 오늘 접수·72시간 이내 배지를 보고 상담 우선순위를 정한다. 1차에는 자동 추천이 아닌 기존 매물 검색을 사용한다.
4. **방문**: 후속 상담 이력에 방문과 결과만 남긴다. 최근 상담일·방문 결과·다음 연락일은 자동 갱신된다.
5. **추가 추천**: 다음 연락일 또는 72시간 배지를 보고 추가 연락을 한다. 오늘 할 일의 완료 체크는 일정 처리 표시만 남긴다.
6. **계약 등록**: 실제 계약 매물을 고르고 원본 상담을 선택한다. 선택 상담의 조건·유입경로를 확인하고 계약자 정보를 채운다.
7. **계약 완료**: 실제 완료일에 계약 완료를 기록한다. 연결 상담은 종료되고 다음 연락일은 해제된다.

## 6. 성과 리포트 제외 결정

상담·방문·계약 전환율, 유입경로별 성과, 재고-수요 비교, 계약 속도, 광고비 효율을 계산·표시하는 성과 리포트는 이번 범위에서 만들지 않는다. 기존 상담·활동·계약·유입경로 데이터는 그대로 보존하며, 향후 별도 승인 시에만 실제 업무 필요성을 다시 검토한다.

## 10. 최종 권고안

### 지금 반드시 고쳐야 할 것

1. 종료 사유를 선택 입력으로 통일한다.
2. 지역·방 유형의 새 입력을 표준화하고, 복수 선택 기준 필드를 하나로 정한다.
3. 상담 후 첫 1~3일과 다음 연락 지연을 기존 화면에서 바로 보이게 한다.
4. 계약 화면에 연결 상담의 업무 요약을 보여 준다.
5. 매물별 광고 기능을 안전한 백업 절차 뒤 삭제하고, 월별 광고비 기록과 광고 문구 만들기만 유지한다.

### 다음 단계로 미뤄도 되는 것

- 주차·엘리베이터·반려동물·단기계약의 개별 구조화 입력
- 간단 후보 매물 필터

### 만들지 않는 것이 좋은 것

- 매물별 광고 상태·마지막 확인일을 다시 필수로 관리하는 구조
- 별도 지역 테이블·고객 CRM 테이블·복잡한 분석용 인증 구조
- 자동 문자, 자동 상태 변경, AI 추천 점수, 광고 플랫폼 연동
- 기존 지역·방 유형 데이터의 일괄 자동 변환
- 상담·방문·계약·광고비 성과 리포트

### 예상 작업 순서와 규모

1. 상담 입력·종료 사유·표준값 규칙 정리
2. 집중 대응 배지와 오늘 할 일 중복 방지
3. 계약 연결 요약·상태 동기화 회귀 확인
4. 기존 매물별 광고 데이터 보호 백업·검증 후 표·화면·관련 코드 삭제
5. 월별 광고비 표·입력 화면 및 광고 문구 만들기, 문서·자동·브라우저 수용 테스트

예상 규모는 **중간**이다. 월별 광고비를 위해 신규 표 1개가 필요하고, 기존 매물별 광고 표·데이터는 승인된 삭제 범위다. 가장 큰 위험은 삭제된 광고 데이터의 복구와 표준값 적용으로 기존 자유입력의 의미를 바꾸는 일이므로, 광고는 사전 백업 검증 뒤 삭제하고, 지역·방 유형 과거값은 그대로 보존하는 방식이 적절하다.

## 승인 필요 결정

아래 결정은 사용자가 확정했다.

1. 지역은 복수 선택 + `기타` 자유입력, 방 유형은 복수 선택으로 한다.
2. 다음 연락일은 사용자가 수동 입력한다. 자동 제안은 만들지 않는다.
3. 종료 사유는 모든 종료 경로에서 완전 선택 입력으로 통일한다.
4. 성과 리포트는 만들지 않는다.
5. 광고관리는 `월별 광고비 기록 + 광고 문구 만들기`만 유지한다. 기존 매물별 광고 기능·데이터는 보호 백업을 검증한 뒤 삭제한다.

이 결정은 기능 방향 승인 기록이며, 사용자의 별도 구현 지시 전에는 코드, DB 스키마, 운영 데이터, 화면 구조를 변경하지 않는다.
