# 계약관리와 상담관리 연결 구현 방안

> 작성일: 2026-08-22  
> 상태: 코드 구현·임시 DB 자동 확인 완료 / 실제 브라우저 확인 필요

## 1. 목적

계약은 실제로 계약한 매물 회차에 기록하고, 상담은 상담 당시 문의한 매물 회차에 그대로 남긴다. 계약 기록에 상담 기록을 별도로 연결해 **어떤 유입 상담이 어떤 실제 계약으로 이어졌는지** 확인하고 분석할 수 있게 한다.

예를 들어 고객이 1번 매물을 보고 상담한 뒤 2번 매물로 계약한 경우에도, 상담의 원래 매물은 1번으로 보존하고 계약의 실제 매물은 2번으로 기록한다.

```text
상담 S-000120
├─ 유입경로: 당근
└─ 상담 매물: M-000001

계약 C-000045
├─ 실제 계약 매물: M-000002
└─ 연결 상담: S-000120
```

## 2. 현재 상태와 문제

- 계약과 상담은 각각 매물 회차에만 연결되어 있다.
- 계약에는 어떤 상담에서 이어졌는지 저장하는 항목이 없다.
- 계약 등록 시 상담에 이미 있는 고객 정보를 다시 입력해야 한다.
- 상담관리의 진행 단계에 `계약 진행`, `계약 완료`가 있어 계약 이후 업무의 기준 화면이 나뉜다.

계약 이후의 상태와 처리 이력은 계약관리에서 한 번만 관리해야 한다.

## 3. 데이터 원칙

1. 계약의 실제 매물과 상담의 원래 매물은 서로 달라도 된다.
2. 상담의 원래 매물 연결을 계약 매물로 바꾸지 않는다.
3. 계약자 이름·연락처는 상담에서 자동으로 가져오되, 계약 시점의 값도 계약에 보관한다. 이후 상담 정보를 고쳐도 과거 계약 정보는 바뀌지 않는다.
4. 계약과 연결된 상담을 삭제해도 계약·계약자 정보·계약 단계 이력은 유지한다. 계약의 상담 연결만 해제한다.
5. 기존 계약이나 상담을 일괄 변경하거나 자동 연결하지 않는다.

## 4. 데이터 구조 변경

`contracts` 표에 아래 선택 항목을 추가한다.

| 항목 | 저장 이름 | 설명 |
|---|---|---|
| 연결 상담 | `source_consultation_id` | 계약으로 이어진 상담 기록 ID. 비워 둘 수 있음. |
| 계약자 이름 | `contractor_name` | 상담에서 가져온 계약 시점의 이름 또는 직접 입력값. |

기존 `contractor_contact`는 계속 사용한다.

`source_consultation_id`는 `consultations.id`를 참조하며, 연결 상담이 삭제되면 `NULL`로 바뀌게 한다. 이때 계약의 계약자 이름·연락처와 계약 정보는 보존한다.

## 5. 계약 등록 흐름

1. 직원이 실제 계약한 매물 회차를 선택한다.
2. `연결 상담 선택`에서 상담 목록을 보고 상담번호·고객명·상담일·유입경로·상담 매물을 확인한 뒤 선택한다. 빠른 필터는 목록을 좁히는 선택 기능으로만 제공한다.
3. 상담 당시 매물이 실제 계약 매물과 달라도 선택을 허용한다.
4. 상담을 선택하면 고객명·연락처를 계약자 이름·연락처에 자동으로 채운다.
5. 직원은 필요할 때 계약자 정보를 바로잡을 수 있다.
6. 계약을 저장하면 실제 계약 매물과 선택 상담을 함께 연결한다.
7. 상담 없이 바로 계약한 경우에는 상담 선택 없이 저장할 수 있다.

계약 등록 화면에는 실제 계약 매물과 상담 당시 매물을 함께 보여 주어, 서로 다른 매물을 선택한 사실을 명확히 확인하게 한다.

## 6. 계약 상태와 상담 상태의 자동 연동

자동 연동 대상은 계약에 직접 연결한 상담 1건뿐이다. 계약 상태를 계약관리에서 변경하거나 계약 단계 이력의 결과 상태가 바뀌었을 때 아래 규칙을 적용한다.

| 계약 상태 | 연결 상담에 자동 반영 |
|---|---|
| 계약 예정 | 변경하지 않음 |
| 계약 진행 / 잔금 예정 | 진행 단계 `계약 진행`, 상담 상태 `진행 중` |
| 계약 완료 | 진행 단계 `계약 완료`, 상담 상태 `종료`, 다음 연락일 해제 |
| 해지 / 만료 | 상담을 자동 재개하지 않음 |

상담 자동 종료는 연결된 상담에만 적용한다. 같은 상담에 다른 진행 중 계약이 연결되어 있을 수 있는 경우에는, 다른 `계약 진행` 또는 `잔금 예정` 계약이 없는지 확인한 뒤 종료한다.

해지·만료 때 상담을 자동 재개하지 않는 이유는 고객이 다시 매물을 찾는지 실제 확인이 필요하기 때문이다. 필요하면 상담관리에서 새 후속 상담을 기록한다.

## 7. 상담관리 변경

새 상담 및 후속 상담의 진행 단계 선택지에서 아래 두 값을 제거한다.

- `계약 진행`
- `계약 완료`

새 입력에 쓰는 단계는 다음으로 제한한다.

- 신규 문의
- 조건 확인
- 방문 예정
- 방문 완료
- 검토 중
- 종료

상담 상세에는 `이 상담으로 계약 등록` 버튼을 제공한다. 이 버튼은 선택한 상담을 계약 등록 화면으로 넘기고, 직원이 실제 계약 매물과 계약 조건을 입력하도록 한다.

기존 데이터에 이미 저장된 `계약 진행`, `계약 완료` 상담 및 후속 상담 이력은 삭제·일괄 변경하지 않는다. 과거 기록으로 계속 표시하고, 새 입력 선택지에서만 제외한다.

## 8. 기존 계약의 상담 연결

`계약 조회·수정`의 계약 상세에 `연결 상담` 영역을 추가한다.

- 상담번호·고객명·연락처 검색 후 수동 연결
- 잘못 연결한 상담의 변경 또는 연결 해제
- 상담의 원래 매물, 유입경로, 상담일을 계약 상세에서 확인
- 계약자 연락처와 일치하는 상담은 후보로 우선 보여 줄 수 있으나 자동 연결하지 않음

기존 계약에 상담을 새로 연결할 때는 기본으로 상담 상태를 변경하지 않는다. 과거 계약을 뒤늦게 연결했을 때 현재 진행 중인 상담을 잘못 종료하지 않기 위해서다. 사용자가 명시적으로 `현재 계약 상태를 연결 상담에 반영`한 경우에만 상태 연동을 실행한다.

## 9. 조회·분석·개인정보 표시

계약 상세에는 아래 내용을 함께 표시한다.

- 실제 계약 매물번호·건물·호실
- 연결 상담번호
- 상담 당시 매물번호·건물·호실
- 상담 유입경로
- 상담일과 상담 진행 단계

계약 목록과 내부 업무용 계약 엑셀에는 개인정보 없이 아래 분석 항목을 추가할 수 있다.

- 연결 상담번호
- 상담 유입경로
- 상담 매물번호

고객명·고객 연락처·계약자 연락처는 기존 보안 규칙대로 기본 목록과 계약 엑셀에 포함하지 않는다.

## 10. 구현 대상

| 영역 | 변경 내용 |
|---|---|
| `storage/database.py` | 계약-상담 연결, 계약자 이름 열, 기존 DB 호환·보호 사본 처리 |
| `storage/contract_repository.py` | 연결 상담 저장·조회·해제, 계약 상태에 따른 상담 연동 |
| `services/contract_service.py` | 상담 존재 여부 검사, 자동 연동 규칙 |
| `ui/contract_management.py` | 상담 검색·선택, 자동 입력, 기존 계약 연결·해제, 연결 정보 표시 |
| `services/consultation_service.py` | 신규 상담 단계 선택지에서 계약 단계 제외 |
| `ui/consultation_management.py` | 계약 등록으로 넘기는 동작, 기존 계약 단계 기록의 호환 표시 |
| 기획·테스트 문서 | 데이터 정의, 업무 흐름, 화면 명세, 테스트 기준, 진행 상태 갱신 |

## 11. 필수 확인 시나리오

1. 1번 매물 상담을 2번 매물 계약에 연결할 수 있다.
2. 상담 선택 시 고객 이름·연락처가 계약자 정보에 자동 입력된다.
3. 상담 없이 계약을 등록할 수 있다.
4. 계약 진행·잔금 예정 상태는 연결 상담만 `계약 진행`으로 반영한다.
5. 계약 완료는 연결 상담을 종료하고 다음 연락일을 해제한다.
6. 해지·만료는 상담을 자동으로 재개하지 않는다.
7. 기존 계약에 상담을 수동 연결해도 계약·상담 이력이 바뀌지 않는다.
8. 기존 계약의 상태를 상담에 반영하는 동작은 사용자가 명시적으로 확인했을 때만 실행된다.
9. 상담을 삭제한 뒤에도 연결된 계약과 계약자 정보는 남고 상담 연결만 해제된다.
10. 계약 목록과 엑셀에 고객명·연락처가 노출되지 않는다.

## 12. 구현 전 결정 사항

- 한 상담에 여러 계약을 연결할 수 있게 유지한다. 다만 상담 자동 종료 전에는 다른 진행 중 계약 여부를 확인한다.
- 자동 상태 연동의 원인은 계약 상태 및 계약 단계 이력으로 한정한다.
- 계약 해지·만료 뒤 고객의 재상담 여부는 자동 판단하지 않는다.

## 13. 구현 및 확인 기록 (2026-08-22)

- `contracts`에 `source_consultation_id`, `contractor_name`을 안전한 호환 마이그레이션으로 추가했다. 운영 DB 변경 전 보호 사본을 만들고, 기존 계약 12건과 상담 42건은 보존했다.
- 계약 등록과 계약 조회·수정에서 상담 목록을 바로 보고 선택·해제할 수 있게 했다. 고객명·연락처 등의 빠른 필터는 목록 축소용으로만 제공하며, 신규 계약은 선택 상담의 고객 이름·연락처를 자동으로 채운다.
- 계약 진행·잔금 예정·계약 완료 상태와 계약 단계 이력의 상태 변경은 연결 상담에만 자동 반영한다. 계약 완료는 다른 진행 중 연결 계약이 없을 때 상담을 종료하고 다음 연락일을 해제한다.
- 상담관리의 새 진행 단계에서는 `계약 진행`, `계약 완료`를 제거했다. 기존에 저장된 값은 수정 화면에서 계속 표시·보존한다.
- 상담 상세의 `이 상담으로 계약 등록` 버튼은 해당 상담을 계약 등록 화면으로 넘긴다.
- 임시 DB로 다른 매물 상담 연결, 계약 진행 반영, 계약 완료 시 상담 종료를 확인했다. 실제 브라우저의 등록·수정 흐름 확인은 남아 있다.
- 계약 단계 이력의 새 입력은 `가계약 / 정식계약 / 잔금 예정 / 계약 완료 / 해지`로 단순화했다. 단계는 현재 계약이 도달한 상태를 뜻하며, 단계별 계약 상태는 자동으로 정한다. 기존 `계약금 수령 / 잔금 / 입주 / 기타` 이력은 보존한다.
- 계약 등록의 정식 계약일·계약금 추가 수령 예정일·잔금 예정일·임대차 시작·종료일은 미래 일정으로 관리한다. 계약 단계 이력의 날짜는 해당 단계가 실제로 확정·처리된 `상태 변경일`로만 기록하며, 미래 잔금 예정일을 이력에 미리 남기지 않는다.
- 기존 완료 계약에 상담을 나중에 연결한 뒤 `현재 계약 상태를 연결 상담에 반영`을 선택하면 해당 확인값을 저장 규칙까지 유지해, 연결 상담 종료와 다음 연락일 해제가 실제로 실행되도록 보완했다. 임시 DB 자동 확인은 통과했으며 실제 브라우저 확인은 남아 있다.
