# 부동산 매물관리 도구 구현 작업표

> 작업 방식: 먼저 작동하는 뼈대를 만들고, 매 단계마다 실제 브라우저 화면을 보면서 수정한다.
>
> 기준 문서: `docs/` 폴더의 PRD, 데이터 항목 정의서, 화면 명세, 업무 흐름서, 테스트·운영 문서

## 0. 이 문서 사용법

- 한 번에 완성하려 하지 않는다. 아래 **단계 순서대로** 만든다.
- 각 작업을 마치면 브라우저에서 직접 확인한 뒤 체크박스를 표시한다.
- 화면을 보고 불편한 점이 생기면 바로 코드를 고치기보다, 먼저 이 문서의 `결정 기록`에 적는다.
- 기능을 바꿀 때는 관련된 `docs/` 문서와 테스트 항목도 함께 확인한다.
- 1차 버전의 목표는 “화려한 서비스”가 아니라 **매물을 빠르고 안전하게 등록·확인하는 내부 도구**다.

### 코드 파일과 폴더를 나누는 원칙

- `app.py`는 프로젝트 최상위 폴더에 두는 프로그램의 **입구**다. 상단 메뉴, 공통 화면 모양, 화면 전환만 관리한다.
- 사용자에게 보이는 화면은 `ui/` 폴더에서 관리한다.
- 신규 등록·재등록·수정의 입력 검사와 업무 규칙은 `services/` 폴더에서 관리한다.
- 데이터 파일을 읽고 저장하는 코드는 `storage/` 폴더에서 관리한다.
- 새 기능이 생길 때는 역할에 맞는 기존 폴더에 파일을 추가한다. 루트 폴더에 기능 파일을 계속 쌓지 않는다.
- 공통 선택값, 입력 검사, 화면 문구처럼 여러 기능이 함께 쓰는 내용도 필요해질 때 역할별 폴더에 공통 파일로 관리한다.
- 처음부터 불필요하게 많은 파일을 만들지는 않는다. 기능이 실제로 생기는 단계에 맞춰 한 파일씩 추가한다.

현재 구조:

```text
C:\realestate\
├─ app.py                  # 실행과 메뉴 전환
├─ ui\                     # 사용자 화면
├─ services\               # 등록·수정 규칙
├─ storage\                # 데이터 저장과 실제 데이터 파일
└─ docs\                   # 기획·작업 문서
```

## 1. 완성 모습

사무실 직원이 브라우저에서 다음 3개 화면을 사용한다.

1. **매물 현황 리스트**: 현재 매물을 조회·필터하고 확인 업무를 찾으며, 조회 결과를 엑셀로 내보낸다.
2. **매물 등록·수정**: 새 건물·호실·매물을 등록하거나 현재 조건을 수정·종료·재등록한다.
3. **건물·호실 관리**: 건물 공통정보, 호실 고정정보, 과거 매물 이력을 확인한다.

핵심 안전장치:

- 동일 건물·호실의 중복 등록 방지
- 재등록 시 과거 가격과 상태 보존
- 비밀번호·내부 메모의 기본 목록 노출 방지
- 저장 오류 시 입력한 내용 유지
- 원본 데이터와 백업 파일 분리

## 2. 1차 버전에서 만들 범위

### 반드시 만든다

- 건물, 호실, 매물 회차 저장
- 건물명·지번·호수 검색
- 신규 등록, 기존 건물의 새 호실 등록, 기존 호실 재등록
- 현재 매물 조건 수정 및 매물 종료
- 오늘의 확인 업무(재확인·사진·현장·입주일·광고 준비)
- 목록 검색·필터·상세 보기
- 일반 매물 목록 엑셀 내보내기
- SQLite 데이터 저장과 백업
- 매물 회차에 연결한 단기·일반 계약 기간과 상태 관리
- 매물 회차에 연결한 간단한 상담 이력과 다음 연락 관리

### 이번에는 만들지 않는다

- 기존 `구재현` 시트 자동 가져오기
- 방문 예약, 자동 문자 발송, 주민번호 등 민감 개인정보, 계약금·잔금의 납부·결제 관리
- 외부 인터넷 공개, 로그인, 권한별 사용자 관리
- 사진 파일 업로드·사진 위치·사진 폴더 경로·링크 관리
- 여러 사람이 같은 매물을 동시에 수정하는 기능

## 단계 3 — 신규 등록 화면 만들기

목표: 새 건물, 새 호실, 첫 매물을 한 번에 안전하게 등록한다.

### 이 단계에서 만들 파일 역할

- [x] `app.py`: 등록 화면을 선택해 보여 주기만 한다.
- [x] `ui/listing_form.py`: 신규 등록 화면과 저장 전 확인 화면을 담당한다.
- [x] `services/listing_service.py`: 입력값 검사와 건물·호실·매물 저장 순서를 담당한다.
- [x] `storage/database.py`: `listing_service.py`가 요청한 저장·조회만 처리한다.

등록 화면이 커져도 `app.py`에 입력칸과 저장 규칙을 직접 추가하지 않는다.

### 기본 입력칸

- [x] 건물명(필수), 지번(필수)
- [x] 호수(필수), 룸 형태, 층, 방향
- [x] 매물 접수일(기본값 오늘, 실제 접수일로 수정 가능), 매물 상태(필수)
- [x] 보증금·월세(필수, 만원 단위 숫자)
- [x] 관리비, 입주 가능 유형, 입주 가능일
- [x] 사진 상태, 이번 매물 메모

### 입력 검사

- [x] 건물명 또는 지번이 비면 저장하지 않는다.
- [x] 호수가 비면 저장하지 않는다.
- [x] 보증금·월세에는 숫자 입력칸을 사용하고, 비어 있거나 0이면 이유를 알려 준다.
- [x] 입주 가능 유형이 `날짜 지정`이면 날짜 입력을 요구한다.
- [x] 오류가 나도 이미 입력한 내용은 지우지 않는다.
- [x] 저장 전 `건물명 · 지번 · 호수 · 보증금/월세` 요약을 보여 준다.
- [x] 건물·호실·첫 매물은 모두 성공할 때만 한꺼번에 저장한다. 중간에 하나라도 실패하면 일부만 저장되면 안 된다.

### 화면 확인

- [x] 테스트용 `대성빌 / 북수리 1026 / 302호 / 500/45`를 별도 테스트 데이터 파일에 저장한다.
- [x] 저장한 건물·호실·매물 1건과 상세값을 다시 읽어 확인한다.
- [x] 필수값 누락과 날짜 지정 후 날짜 누락을 자동 시험한다.
- [ ] 실제 브라우저에서 신규 등록 화면의 입력 흐름과 저장 결과를 확인한다.

## 단계 4 — 검색·중복 방지 만들기

목표: 같은 건물이나 같은 호실을 잘못 여러 번 만들지 않는다.

- [x] 건물명 또는 지번으로 기존 건물을 찾는다.
- [x] `건물명 + 지번`이 같으면 기존 건물을 먼저 보여 준다.
- [x] 건물명은 같아도 지번이 다르면 자동으로 합치지 않는다.
- [x] 같은 건물에서 같은 호수를 새로 등록하지 못하게 한다.
- [x] `302`와 `302호`를 같은 호실로 처리한다.
- [x] 기존 건물을 선택하면 주소·공동현관·주차 같은 건물 정보는 다시 입력하지 않는다.

### 화면 확인

- [ ] 대성빌을 다시 검색했을 때 기존 건물이 우선 보인다.
- [ ] 대성빌에 302호를 다시 만들려고 하면 막힌다.
- [ ] 대성빌에 201호를 새로 등록할 수 있다.

## 단계 5 — 기존 호실 재등록 만들기

목표: 같은 호실이 다시 매물로 나올 때 과거 기록은 지키고 새 조건만 추가한다.

- [x] 건물과 호실을 선택할 수 있다.
- [x] 호실의 고정정보(구조·방향·옵션·방문 방법)를 자동으로 불러온다.
- [x] 이전 매물의 가격과 상태는 참고용으로만 보여 준다.
- [x] `새 매물 회차로 등록` 버튼을 별도로 둔다.
- [x] 새 회차 저장 시 이전 회차의 가격·상태·날짜를 바꾸지 않는다.
- [x] 활성 매물이 남아 있으면 `현재 매물 수정`과 `새 매물 회차 생성`의 차이를 안내하고 사용자가 선택하게 한다.
- [x] 실제로 다시 확인하지 않은 비밀번호·옵션의 마지막 확인일을 자동으로 오늘 날짜로 바꾸지 않는다.

### 화면 확인

- [ ] 대성빌 302호에 `500/47, 공실, 즉시입주` 매물을 새 회차로 등록한다.
- [ ] 과거 이력에서 이전 `500/45` 기록과 새 `500/47` 기록을 모두 확인한다.

## 단계 6 — 현재 매물 수정과 종료 만들기

목표: 현재 매물의 변경과 매물 종료를 헷갈리지 않게 한다.

- [x] `현재 매물 수정`은 같은 매물 회차의 가격·상태·입주일·메모만 수정한다.
- [x] 여러 항목을 바꿔도 저장 버튼을 누를 때 한 번에 반영한다.
- [x] 사진 상태를 `촬영 완료`로 바꾸고 촬영일을 기록할 수 있다.
- [x] 종료 시 종료일과 종료 사유를 기록한다.
- [x] 계약 여부를 실제로 확인하기 전에는 자동으로 `계약 완료`로 바꾸지 않는다.
- [x] 잘못 등록한 매물도 바로 삭제하지 않고 `정보 오류` 사유로 종료해 이력을 남긴다.
- [x] 건물·호실은 즉시 완전 삭제 대신 비활성화할 수 있게 한다.

### 화면 확인

- [ ] 월세만 수정해도 새 매물 회차가 생기지 않는다.
- [ ] 계약 완료 처리한 매물은 현재 목록에서는 사라지고 이력에는 남는다.

## 3-1. 단계별 상세 구현계획과 테스트

### 공통 진행 원칙

각 단계는 아래 순서로 진행한다.

1. **작은 기능 하나를 만든다.** 예: 메뉴 하나, 저장 버튼 하나처럼 범위를 작게 잡는다.
2. **개발자가 확인한다.** 코드가 오류 없이 실행되고, 기본적인 자동 확인을 통과하는지 본다.
3. **브라우저에서 직접 확인한다.** 실제 사무실 사용자가 누르는 순서대로 눌러 본다.
4. **문제 기록 후 수정한다.** 오류 화면, 어떤 버튼을 눌렀는지, 기대한 결과를 `결정·수정 기록`에 남긴다.
5. **다시 확인한다.** 수정한 부분뿐 아니라 관련된 기존 기능도 한 번 더 확인한다.

테스트 결과 표기:

- **PASS**: 기대한 대로 동작함
- **FAIL**: 다르게 동작하거나 업무를 할 수 없음
- **BLOCKED**: 앞선 오류나 PC 환경 문제로 시험할 수 없음

### 단계 1 상세 — 실행 가능한 빈 화면

#### 구현 순서

1. 프로그램 시작 파일(`app.py`)을 만든다.
2. 화면 이름, 사무실 내부용 안내문, 기본 넓이를 설정한다.
3. 메뉴 상태를 한 곳에서 관리해 메뉴를 눌러도 화면 선택이 흔들리지 않게 한다.
4. 각 메뉴 화면은 우선 제목·설명·빈 상태만 보여 주는 함수로 나눈다. 이렇게 하면 다음 단계에서 한 화면을 고쳐도 다른 화면에 영향을 덜 준다.
5. 데이터가 없을 때 등록 화면으로 이동하는 버튼을 연결한다.

#### 테스트 및 합격 기준

| ID | 직접 할 일 | 기대 결과 | 관련 기준 |
|---|---|---|---|
| S1-01 | 프로그램을 실행한다. | 오류 없이 브라우저가 열리고 `매물 현황 리스트`가 먼저 보인다. | TC-036 |
| S1-02 | 세 메뉴를 차례로 누른다. | 선택한 메뉴의 제목과 내용이 각각 보인다. | 화면 명세 2장 |
| S1-03 | 데이터가 없는 상태에서 첫 화면을 본다. | 빈 표가 아니라 첫 매물 등록 안내와 버튼이 보인다. | TC-043 |
| S1-04 | 등록 안내 버튼을 누른다. | `매물 등록·수정` 화면으로 이동한다. | 화면 명세 7.4 |

**단계 완료 조건:** S1-01~04가 모두 PASS이고, 화면을 처음 보는 사람이 메뉴와 등록 버튼을 찾을 수 있다.

### 단계 2 상세 — 데이터 저장 뼈대

#### 구현 순서

1. 데이터 파일의 위치를 설정 파일 또는 한 곳의 상수로 정한다. 코드 여러 곳에 경로를 적지 않는다.
2. 건물·호실·매물 회차용 표를 만든다. 각 기록에는 내부 번호, 만든 시각, 수정 시각을 둔다.
3. 건물과 호실, 호실과 매물 회차의 연결 규칙을 만든다.
4. 데이터 파일이 없거나 경로가 틀렸을 때의 안내를 만든다.
5. 저장, 한 건 조회, 목록 조회 기능을 화면과 분리된 코드로 만든다. 화면 디자인을 고쳐도 저장 규칙이 깨지지 않게 하기 위함이다.
6. 저장 중 오류가 나면 중간 데이터가 남지 않도록 “모두 저장 또는 모두 취소” 처리한다.

### 단계 3 상세 — 신규 등록

2. 처음에는 필수 입력칸만 보이고, 관리비·옵션·현장 상태 같은 자세한 칸은 접어서 보여 준다.
3. 가격 입력칸 옆에 항상 `(만원)`을 표시한다.
4. 저장 버튼을 누르기 전에 빠진 값과 잘못된 값을 한 번에 검사한다.
5. 오류는 해당 입력칸 바로 아래에 쉬운 말로 보여 준다.
6. 저장 직전 요약 내용을 보여 준 뒤, 저장 성공 시 등록한 매물 상세 또는 현황 화면으로 이동한다.

### 단계 4 상세 — 검색과 중복 방지

5. 중복을 발견했을 때는 단순 오류가 아니라 “기존 건물 선택” 또는 “현재 매물 수정” 같은 다음 행동을 안내한다.

### 단계 5 상세 — 기존 호실 재등록

2. 건물·호실의 고정정보는 자동으로 채우되, 이번 매물 조건은 빈 입력칸 또는 참고값으로 둔다.
3. 이전 매물과 이번 입력값을 나란히 보여 줘 차이를 쉽게 확인하게 한다.

#### 구현 순서

1. 엑셀에 보낼 열 목록을 코드에서 명시적으로 정한다. 현재 매물의 비밀번호·내부 메모를 포함하되, 임대인·세입자 개인 연락처와 상담관리 고객 이름·연락처는 제외한다.
2. 전체 현재 매물과 현재 검색 결과 중 하나를 선택하게 한다.
3. 금액은 숫자, 날짜는 날짜 형태로 내보낸다.
4. 파일 생성 전에 내보낼 건수와 제외되는 내부정보를 안내한다.
5. 만들어진 파일 이름에는 생성 날짜와 시간을 붙인다.

#### 테스트 및 합격 기준

| ID | 직접 할 일 | 기대 결과 | 관련 기준 |
|---|---|---|---|
| S9-01 | 전체 현재 매물과 현재 조회 결과를 각각 내보낸다. | 선택한 범위가 파일에 정확히 들어간다. | TC-048 |
| S9-02 | 파일을 열어 금액·날짜 열을 정렬한다. | 숫자·날짜로 정렬되며 글자처럼 섞이지 않는다. | TC-049 |
| S9-03 | 파일의 모든 열을 확인한다. | 공동현관·방문 비밀번호, 내부 메모, 열쇠 위치는 포함되고, 임대인·세입자 개인 연락처와 상담관리 고객 이름·연락처는 없다. | TC-046 |
| S9-04 | 메뉴와 화면을 확인한다. | 기존 엑셀 가져오기 기능은 없다. | TC-050 |
| S9-05 | 접수일 8월 1일~8월 31일로 조회한 뒤 `현재 조회 결과`를 내보낸다. | 화면의 건수·매물 목록과 엑셀의 건수·매물 목록이 같다. | 날짜 내보내기 추가 기준 |
| S9-06 | 날짜 필터를 비운 뒤 `현재 매물 전체`를 내보낸다. | 기간 제한 없이 전체 현재 매물이 들어간다. | 날짜 내보내기 추가 기준 |
| S9-07 | 날짜 범위를 고른 엑셀 파일 이름을 확인한다. | 시작일·종료일·생성 시각을 확인할 수 있다. | 날짜 내보내기 추가 기준 |

**단계 완료 조건:** S9-01~04가 PASS이고, 엑셀 파일에 개인 연락처가 포함되지 않는다.

### 단계 10 상세 — 백업·복구·운영

#### 구현 순서

1. 운영 PC의 프로그램 폴더, 데이터 폴더, 백업 폴더를 분리한다.
2. 백업은 원본을 복사하는 방식으로 만들며, 원본을 옮기거나 지우지 않는다.
3. 일일·주간·월간 백업 이름과 보관 개수 규칙을 구현한다.
4. 백업 성공·실패와 파일 위치를 기록한다.
5. 복구는 항상 별도 검증 위치에서 먼저 열어 보고, 운영 데이터 교체는 프로그램을 끈 뒤에만 한다.
6. 운영 PC와 다른 사용자 PC의 접속 방법, 장애 시 확인 순서를 짧은 안내문으로 만든다.

#### 테스트 및 합격 기준

| ID | 직접 할 일 | 기대 결과 | 관련 기준 |
|---|---|---|---|
| S10-01 | 프로그램 종료 후 다시 실행한다. | 저장한 데이터가 그대로 보인다. | TC-051 |
| S10-02 | 운영 PC를 재시작한 뒤 정해진 방법으로 실행한다. | 기존 데이터로 정상 실행된다. | TC-052 |
| S10-03 | 일일 백업을 실행한다. | 원본과 다른 위치에 날짜·시간이 든 백업이 만들어진다. | TC-053 |
| S10-04 | 백업본을 별도 테스트 폴더에서 연다. | 건물·호실·최근 매물 이력을 정상 조회한다. | TC-054 |
| S10-05 | 사용자 PC 두 대에서 운영 PC 주소로 접속한다. | 두 화면에서 같은 목록을 본다. | TC-057 |
| S10-06 | 한 PC에서 새 매물을 저장하고 다른 PC에서 새로 조회한다. | 다른 PC에도 새 매물이 보인다. | TC-058 |
| S10-07 | 운영 PC의 프로그램을 종료한 뒤 사용자 PC에서 접속한다. | 데이터 손상 없이 운영 PC 실행 필요 안내로 원인을 알 수 있다. | TC-060 |

**단계 완료 조건:** S10-01~07이 PASS이고, 백업본으로 실제 조회까지 성공했다.

## 5. 배포 전 최소 확인 목록

- [ ] 신규 건물·호실·첫 매물 등록이 된다.
- [ ] 같은 호실 재등록 시 과거 가격이 남는다.
- [ ] 현재 매물 수정은 새 이력을 만들지 않는다.
- [ ] 재확인·사진 촬영 필요 매물을 찾을 수 있다.
- [ ] 비밀번호는 기본 목록에 나오지 않고, 엑셀에는 포함된다. 개인 연락처는 엑셀에 나오지 않는다.
- [ ] 프로그램을 다시 실행해도 데이터가 남는다.
- [ ] 백업을 만들고 복구 확인을 해 봤다.
- [ ] 사용자 PC 2대에서 같은 데이터가 보인다.
- [ ] 치명적인 문제(데이터 유실, 저장 불가, 과거 기록 덮어쓰기)가 없다.
- [ ] 실제 사용자가 설명 없이 `대성빌 302호` 신규 등록과 재등록을 완료한다.
