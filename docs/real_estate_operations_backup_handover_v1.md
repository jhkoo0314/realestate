# 부동산 매물관리 도구 운영·백업·인수인계 문서 v1.0

> 적용 범위: 사무실 내부용 Streamlit + SQLite 매물관리 도구
>
> 운영 기준: 재현님 PC는 개발용이고, 실제 프로그램과 데이터는 사무실에서 지정한 운영 PC에 둔다.
>
> 데이터 기준: 기존 `구재현` 시트는 참고만 하며 시스템으로 이전하지 않는다.

## 1. 운영 구조

```text
재현님 PC
└─ 개발·수정·테스트용 복사본

사무실 운영 PC
├─ Streamlit 프로그램
├─ SQLite 원본 데이터
├─ 사진 보유 여부·촬영 상태 정보
└─ 백업 파일

사무실 사용자 PC 1·2
└─ 브라우저로 운영 PC에 접속
```

### 핵심 원칙

- 실제 데이터는 운영 PC의 SQLite 파일 하나만 사용한다.
- 사용자 PC에 SQLite 파일을 복사해 각각 실행하지 않는다.
- Google Drive·OneDrive·네트워크 공유폴더에서 SQLite 원본을 직접 실행하지 않는다.
- 운영 PC의 Streamlit 프로그램이 실행 중일 때만 다른 PC에서 접속할 수 있다.
- 로그인은 없으므로 사무실 내부망에서만 접속한다.
- 인터넷 포트 포워딩이나 공개 주소를 설정하지 않는다.

## 2. 운영 PC 선정 기준

운영 PC는 재현님 PC가 아니어도 된다. 다음 조건을 만족하는 사무실 PC를 지정한다.

- 업무시간 동안 대부분 켜져 있음
- 사무실에 계속 남아 있는 PC
- 다른 직원이 전원·프로그램 실행을 관리할 수 있음
- 사무실 내부 네트워크에 연결됨
- 저장공간에 여유가 있음
- Windows 업데이트나 절전으로 자주 꺼지지 않음

가장 적합한 PC는 사장님 또는 사무실 공용 관리 PC다. 특정 직원 개인 PC를 운영 PC로 지정하면 해당 직원의 퇴사·교체 때 접속이 끊길 수 있다.

## 3. 운영 폴더 구조

운영 PC에 다음과 같이 폴더를 만든다.

```text
D:\매물관리\
├─ app.py                         # 화면 실행 파일
├─ requirements.txt               # 필요한 Python 패키지 목록
├─ run_app.bat                    # 프로그램 실행용 바로가기
├─ database\
│  └─ real_estate.db              # 실제 원본 SQLite 파일
├─ backups\
│  ├─ daily\                      # 일일 백업
│  └─ monthly\                    # 월별 보관본
├─ exports\                      # 엑셀 내보내기 파일
├─ logs\                         # 오류·실행 기록
└─ README_운영방법.md             # 사무실용 간단 사용법
```

실제 드라이브 문자는 운영 PC 환경에 따라 달라질 수 있다. 중요한 것은 `database\real_estate.db`가 프로그램과 같은 운영 폴더 안에 있고, 사용자 PC가 이 파일을 직접 열지 않는 것이다.

## 4. 프로그램 실행

### 4.1 정상 실행

1. 운영 PC를 켠다.
2. `D:\매물관리\run_app.bat`을 실행한다.
3. 검은색 실행창을 닫지 않고 최소화한다.
4. 운영 PC에서 `http://localhost:8501`로 화면을 확인한다.
5. 다른 PC에서는 아래 주소로 접속한다.

```text
http://운영PC이름:8501
```

또는 운영 PC의 내부 IP를 사용하는 경우:

```text
http://192.168.0.20:8501
```

운영 PC 이름을 사용하는 방식이 IP 변경에 덜 취약하다. 운영 PC 이름과 접속 주소는 사무실 책상이나 바탕화면에 기록해 둔다.

### 4.2 프로그램 종료

- 업무 중에는 실행창을 닫지 않는다.
- 종료가 필요하면 먼저 다른 사용자가 저장 중인지 확인한다.
- 실행창에서 `Ctrl+C`를 누르거나 창을 닫아 정상 종료한다.
- 컴퓨터를 강제로 끄기 전에 프로그램을 먼저 종료한다.

### 4.3 자동 실행

운영 PC의 Windows 시작프로그램에 `run_app.bat` 바로가기를 등록할 수 있다.

자동 실행을 설정하더라도 첫 운영 주간에는 정상적으로 켜지는지 직접 확인한다. 자동 실행 실패 시 수동 실행할 수 있도록 바탕화면 바로가기를 함께 둔다.

## 5. 사무실 사용자 접속

### 사용 방법

1. 운영 PC가 켜져 있는지 확인한다.
2. 바탕화면의 `매물관리` 바로가기를 연다.
3. 브라우저에서 매물관리 화면을 사용한다.

사용자 PC에는 프로그램이나 SQLite를 설치하지 않는다. 모든 사용자는 운영 PC의 같은 화면과 같은 데이터를 본다.

### 접속이 안 될 때 확인 순서

1. 운영 PC가 켜져 있는가?
2. 운영 PC의 Streamlit 실행창이 열려 있는가?
3. 사용자 PC와 운영 PC가 같은 사무실 네트워크에 연결돼 있는가?
4. 접속 주소의 운영 PC 이름 또는 IP가 맞는가?
5. 운영 PC의 Windows 방화벽에서 Streamlit 포트가 내부망에 허용돼 있는가?

인터넷에서 접속할 수 있도록 설정하지 않는다. 외부 접속이 필요해지는 경우는 별도의 온라인 운영방식 검토 대상이다.

## 6. 데이터 저장 원칙

### 6.1 SQLite 원본

원본 데이터 파일은 다음 한 곳이다.

```text
D:\매물관리\database\real_estate.db
```

이 파일에 저장되는 내용:

- 건물
- 호실
- 현재·과거 매물 회차
- 매물 상태·가격·입주일
- 내부 비밀번호
- 사진 보유 여부·촬영 상태
- 확인 업무

### 6.2 사진 파일

사진 원본과 사진 보관 위치는 이 도구에서 관리하지 않으며 SQLite에 넣지 않는다.

SQLite에는 사진 보유 여부와 촬영 상태만 저장한다.

### 6.3 과거 `구재현` 시트

- 기존 시트는 자동 이전하지 않는다.
- 새 시스템에 현재 필요한 매물부터 직접 등록한다.
- 기존 시트는 참고자료로 별도 보관한다.
- 기존 시트의 내용을 수정해 새 시스템의 원본으로 취급하지 않는다.

## 7. 일상 운영 절차

### 업무 시작 전

- 운영 PC가 켜져 있는지 확인
- Streamlit 실행창이 열려 있는지 확인
- 오늘의 현황에서 `재확인 필요`와 `퇴실 예정` 확인
- 전일 백업이 생성됐는지 확인

### 매물 접수 시

1. 건물명 또는 지번 검색
2. 기존 건물 선택 또는 새 건물 등록
3. 기존 호실 선택 또는 새 호실 등록
4. 이번 상태·가격·입주 가능일 입력
5. 사진·청소·수리 등 필요한 업무 표시
6. 저장 후 현재 매물 목록에서 확인

### 같은 호실 재등록 시

1. 건물과 호실 검색
2. 고정정보와 이전 조건 확인
3. 이번 가격·상태·입주일 입력
4. 변경된 비밀번호·옵션·사진 여부 확인
5. `새 매물 회차로 등록`
6. 과거 이력이 남아 있는지 확인

### 업무 종료 전

- 새 매물 저장 여부 확인
- 오늘 처리한 재확인 업무 상태 변경
- 미확인 가격·입주일을 확인 필요로 남김
- 백업 생성 여부 확인
- 운영 PC를 끄는 경우 Streamlit을 먼저 종료

## 8. 백업 정책

### 8.1 백업 대상

최소한 다음 파일을 백업한다.

- `database\real_estate.db`
- `app.py`
- `requirements.txt`
- `run_app.bat`
- `README_운영방법.md`
- 필요한 설정 파일

사진 원본은 이 도구의 백업 범위에 포함하지 않는다. SQLite 백업에는 사진 보유 여부와 촬영 상태만 들어간다.

### 8.2 백업 시점

| 주기 | 내용 | 보관 |
|---|---|---|
| 매일 | SQLite 원본 복사 | 최근 30개 |
| 매주 | 프로그램 폴더와 DB 전체 | 최근 8개 |
| 매월 | 월말 전체 백업 | 최소 12개월 |
| 큰 변경 전 | 개발 버전 적용 전 백업 | 변경 전·후 각 1개 |

### 8.3 백업 파일 이름

```text
real_estate_2026-08-01_1800.db
real_estate_full_2026-08-01.zip
```

파일명에 날짜와 시간을 넣어 어떤 시점의 백업인지 바로 알 수 있게 한다.

### 8.4 백업 위치

원본과 다른 위치에 백업한다.

권장 우선순위:

1. 운영 PC의 다른 드라이브 또는 외장 저장장치
2. 사무실에서 관리하는 제한된 백업 폴더
3. 접근권한이 제한된 Google Drive 백업 폴더

공동현관·방문 비밀번호가 포함될 수 있으므로 백업 파일을 공개 링크로 공유하지 않는다.

## 9. 백업 실행 예시

개발 시 자동화할 기본 동작은 다음과 같다.

```text
1. database\real_estate.db를 읽기 전용으로 복사
2. backups\daily\real_estate_날짜시간.db로 저장
3. 최근 30개보다 오래된 일일 백업 삭제
4. 백업 성공 여부를 logs\backup.log에 기록
```

백업 파일을 만들기 위해 원본 SQLite를 삭제하거나 이동하지 않는다. 운영 중인 원본 파일은 항상 유지한다.

## 10. 복구 절차

### 10.1 단순 데이터 확인

원본을 바로 교체하지 않고 백업본을 별도 폴더에 복사해 먼저 열어본다.

```text
복구검증\database\real_estate.db
```

확인 항목:

- 건물 수
- 호실 수
- 최근 매물 수
- 대성빌 302호 이력
- 내부정보 표시 여부

### 10.2 실제 복구

1. 모든 사용자가 저장을 끝냈는지 확인한다.
2. Streamlit을 종료한다.
3. 현재 원본 DB를 `database\before_restore\`에 보관한다.
4. 검증된 백업본을 `database\real_estate.db`로 복사한다.
5. Streamlit을 다시 실행한다.
6. 오늘의 현황과 최근 등록 매물을 확인한다.
7. 복구 사실과 사용한 백업 날짜를 기록한다.

원본을 바로 삭제하지 않는다. 복구 직전 원본은 최소 30일 보관한다.

### 10.3 복구 후 확인표

- [ ] 프로그램이 정상 실행됨
- [ ] 오늘의 현황이 열림
- [ ] 대성빌 302호가 조회됨
- [ ] 과거 매물 이력이 남아 있음
- [ ] 가격과 입주일이 날짜별로 맞음
- [ ] 비밀번호가 목록에 노출되지 않음
- [ ] 다른 사용자 PC에서도 접속됨

## 11. 장애 대응

### 프로그램이 열리지 않음

- 운영 PC의 Python 환경 확인
- 실행창의 오류 문구 확인
- `requirements.txt`에 필요한 패키지가 설치돼 있는지 확인
- 최근 코드 변경 전 백업 버전으로 실행

### 데이터가 보이지 않음

- 잘못된 DB 경로를 사용하고 있는지 확인
- 운영 PC가 개발용 DB를 읽고 있지 않은지 확인
- SQLite 파일이 실제로 존재하는지 확인
- 빈 DB를 자동 생성하지 않도록 오류를 확인

### 다른 PC에서 접속되지 않음

- 운영 PC 실행 여부 확인
- 주소와 포트 확인
- 동일 네트워크 여부 확인
- Windows 방화벽 내부망 허용 확인

### 저장이 실패함

- 화면의 오류 항목 확인
- 금액이 숫자인지 확인
- 날짜 지정인데 날짜가 빠지지 않았는지 확인
- 중복 호실인지 확인
- 오류가 반복되면 저장하지 않고 화면과 오류 문구를 캡처

### 데이터가 잘못 수정됨

- 즉시 현재 DB를 별도 복사해 보존
- 최근 백업과 현재 DB를 비교
- 필요한 경우 복구 전 원본을 보관한 뒤 백업 복구
- 어떤 사용자가 언제 무엇을 수정했는지 운영 기록에 남김

## 12. 개발 버전 배포 절차

재현님 PC에서 수정한 버전을 운영 PC에 적용할 때는 다음 순서를 따른다.

1. 재현님 PC에서 테스트 시나리오를 실행한다.
2. 운영 PC의 전체 폴더를 백업한다.
3. 운영 중인 Streamlit을 종료한다.
4. 코드 파일만 교체한다.
5. 운영 DB 파일은 별도 지시 없이는 교체하지 않는다.
6. 운영 PC에서 프로그램을 실행한다.
7. 신규 등록·재등록·기존 이력 조회를 확인한다.
8. 문제가 없으면 배포일과 변경내용을 기록한다.

### 코드와 데이터 분리 원칙

```text
코드 변경 → app.py, 설정, 패키지
데이터 변경 → database\real_estate.db
```

코드를 업데이트한다는 이유로 SQLite 원본을 덮어쓰지 않는다.

## 13. 인수인계 패키지

재현님이 업무를 그만두거나 운영 담당자가 바뀔 때 다음 폴더를 전달한다.

```text
매물관리_인수인계_2026-08-01\
├─ app.py
├─ requirements.txt
├─ run_app.bat
├─ database\
│  └─ real_estate.db
├─ backups\
│  └─ 최신 백업 파일
├─ exports\
│  └─ 최근 엑셀 내보내기
├─ README_운영방법.md
├─ 오늘의_운영체크리스트.md
└─ 변경이력.md
```

### 인수인계 전에 확인할 내용

- [ ] 운영 PC가 명확히 지정돼 있음
- [ ] 운영 PC의 Windows 사용자 또는 담당자가 정해져 있음
- [ ] 바탕화면에 실행 바로가기가 있음
- [ ] 다른 PC에서 접속 주소가 작동함
- [ ] SQLite 최신 백업이 있음
- [ ] 백업 복구를 한 번 시험함
- [ ] 사진 보유 여부와 촬영 상태가 업무 기준대로 표시됨

## 15. 변경관리 원칙

- 상태값·데이터 항목을 바꾸기 전 데이터 항목 정의서를 먼저 수정한다.
- 화면을 바꾸기 전 화면 명세와 테스트 시나리오를 함께 수정한다.
- 코드만 변경하고 운영 DB 구조를 임의로 바꾸지 않는다.
- 데이터 구조 변경 전 전체 백업을 만든다.
- 변경 후 핵심 시나리오 TC-001, TC-014, TC-018, TC-025, TC-051, TC-054를 다시 실행한다.
- 변경일·변경자·변경내용을 `변경이력.md`에 기록한다.

## 16. 운영상 절대 하지 않을 일

- SQLite 원본을 Google Drive 동기화 폴더에서 직접 실행
- 사용자 PC마다 SQLite를 복사해 별도 운영
- 운영 중인 DB를 개발용 DB로 덮어쓰기
- 백업 확인 없이 원본 DB 삭제
- 매물이 사라졌다는 이유만으로 계약 완료 처리
- 공동현관·방문 비밀번호가 포함된 파일을 공개 링크로 공유
- 기존 `구재현` 시트를 자동으로 시스템에 일괄 반영

## 17. 운영 완료 기준

다음 조건을 모두 충족하면 운영 준비가 끝난 것으로 본다.

- 지정 운영 PC에서 프로그램이 실행된다.
- 두 사용자 PC가 내부망으로 같은 매물 목록에 접속한다.
- 신규 건물·호실·첫 매물 등록이 가능하다.
- 기존 호실 재등록 시 과거 이력이 유지된다.
- 일일 백업 파일이 자동 또는 수동으로 생성된다.
- 백업본으로 복구 테스트를 완료했다.
- 인수인계자가 실행·등록·재등록·복구 방법을 이해했다.
- 기존 `구재현` 시트는 이전되지 않고 참고자료로만 보관된다.
