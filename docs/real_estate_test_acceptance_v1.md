# 부동산 매물관리 도구 테스트 시나리오·수용 기준서 v1.0

> 적용 범위: 사무실 내부 PC에서 사용하는 Streamlit + SQLite 기반 1차 버전
>
> 목적: 화면이 열리는지만 확인하는 것이 아니라, 실제 원룸·투룸 매물 업무를 빠르고 안전하게 처리할 수 있는지 검증한다.

## 1. 테스트 원칙

1. 실제 업무 순서인 `검색 → 등록 → 기존 호실 최신 정보 수정 → 종료 → 계약·상담 확인`을 기준으로 테스트한다.
2. 기존 호실 최신 정보 수정 뒤 연결된 계약·상담 기록이 유지되는지를 가장 중요하게 확인한다.
3. 저장 실패, 중복 등록, 잘못된 날짜 등 오류 상황도 반드시 확인한다.
4. 공동현관·방문 비밀번호가 기본 목록에 노출되지 않는지 확인한다.
5. 기존 `구재현` 시트를 가져오는 기능은 테스트하지 않는다. 해당 기능 자체가 화면에 없어야 한다.
6. 테스트는 개발자 판단이 아니라 실제 사용자 관점에서 합격·불합격을 판정한다.

## 2. 테스트 대상

### 2.1 포함 기능

- 매물 현황 리스트
- 건물 검색·신규등록
- 호실 검색·신규등록
- 첫 매물 회차 등록
- 기존 호실 최신 정보 수정
- 현재 매물 조건 수정
- 건물·호실 기본정보 수정
- 매물 종료 처리
- 과거 매물 이력 조회
- 매물 회차에 연결한 계약 기간·상태 관리
- 사진 보유 여부
- 엑셀 내보내기
- SQLite 백업·복구
- 사무실 내부망에서 2인 접속

### 2.2 제외 기능

- 기존 `구재현` 시트 가져오기·자동변환
- 방문 예약, 자동 문자 발송, 주민번호 등 민감 개인정보, 계약금·잔금의 납부·결제 관리
- 로그인·사용자 권한
- 고객용 공개 페이지
- 광고 채널 자동 등록
- 모바일 전용 화면
- 사진 원본 업로드·편집

## 3. 테스트 환경

| 항목 | 기준 |
|---|---|
| 운영 PC | 사무실에서 지정한 메인 운영 PC |
| 사용자 PC | 운영 PC와 같은 사무실 네트워크에 연결된 PC 2대 |
| 브라우저 | 사무실에서 실제 사용하는 최신 Chrome 또는 Edge |
| 실행 방식 | 운영 PC에서 Streamlit 실행, 사용자 PC는 브라우저 접속 |
| 데이터 저장 | 운영 PC의 SQLite 파일 1개 |
| 사진 | 사진 보유 여부와 촬영 상태만 저장. 파일·경로·링크는 저장하지 않음 |
| 외부 공개 | 인터넷 공개 금지, 사무실 내부망에서만 접속 |

## 5. 합격 판정 방법

각 테스트는 아래 중 하나로 기록한다.

| 결과 | 의미 |
|---|---|
| PASS | 예상 결과와 정확히 일치 |
| FAIL | 예상 결과와 다르거나 업무 진행이 불가능 |
| BLOCKED | 앞선 오류 또는 환경 문제로 테스트 불가 |
| N/A | 이번 빌드에 적용하지 않음 |

테스트 기록에는 실행일, 실행자, 결과, 발견한 문제, 화면 캡처 또는 재현 방법을 남긴다.

# 6. 신규 건물·호실·첫 매물 등록 테스트

## TC-001. 신규 건물과 첫 매물 정상 등록

**사전조건:** 데이터베이스에 `대성빌 / 북수리 1026`이 없다.

**실행 절차:**

1. `매물 등록·수정`을 연다.
2. `대성빌` 또는 `북수리 1026`을 검색한다.
3. 결과가 없는 것을 확인하고 `새 건물 등록`을 누른다.
4. 건물 A, 호실 A-1, 첫 매물 회차 정보를 입력한다.
5. `건물·호실·첫 매물 등록`을 누른다.

**예상 결과:**

- 저장 전 `대성빌 · 북수리 1026 · 302호 · 500/45` 요약이 표시된다.
- 건물 1건, 호실 1건, 매물 회차 1건이 생성된다.
- 저장 성공 안내가 표시된다.
- 오늘의 현황에서 대성빌 302호를 확인할 수 있다.
- 사진 촬영 필요 목록에 표시된다.
- 선택한 호실 옵션과 기타 옵션 메모가 호실 기본정보에 저장된다.

**합격 기준:** 위 예상 결과가 모두 충족되고 중복 데이터가 생성되지 않는다.

## TC-002. 건물 필수정보 누락 차단

**실행 절차:** 건물명 또는 지번을 비운 채 저장한다.

**예상 결과:**

- 저장되지 않는다.
- 비어 있는 항목 아래에 이유가 표시된다.
- 이미 입력한 호실·가격 정보는 화면에 유지된다.

## TC-003. 호수 누락 차단

**실행 절차:** 건물정보를 입력하고 호수를 비운 채 저장한다.

**예상 결과:** 호수 입력 안내가 표시되고 아무 데이터도 일부 저장되지 않는다.

## TC-004. 숫자가 아닌 가격 입력 차단

**실행 절차:** 보증금에 `오백`, 월세에 `45만원`을 입력하고 저장한다.

**예상 결과:** 숫자 입력 안내가 표시되고 저장되지 않는다. 화면에는 `(만원)` 단위가 명확히 보인다.

## TC-005. 날짜 지정 후 날짜 누락 차단

**실행 절차:** 입주 가능 유형을 `날짜 지정`으로 선택하고 날짜를 비운 채 저장한다.

**예상 결과:** 입주 가능일 입력 안내가 표시되고 저장되지 않는다.

## TC-006. 선택정보 미입력 허용

**실행 절차:** 방향, 옵션, 관리비 등을 비운 채 최소 필수정보만 저장한다.

**예상 결과:** 정상 저장되고 정보 상태는 `기본등록`으로 표시된다.

# 7. 중복 방지 테스트

## TC-007. 동일 건물 중복 후보 표시

**사전조건:** 대성빌이 이미 등록돼 있다.

**실행 절차:** `대성빌` 또는 `북수리 1026`을 검색한다.

**예상 결과:** 기존 대성빌이 검색 결과에 표시되고 신규 건물 등록보다 기존 건물 선택이 우선된다.

## TC-008. 같은 건물·같은 호실 중복 생성 차단

**사전조건:** 대성빌 302호가 등록돼 있다.

**실행 절차:** 대성빌에 새 호실 `302호`를 등록하려 한다.

**예상 결과:** 기존 302호가 있다는 안내가 표시되고 새 호실 생성이 차단된다.

## TC-009. `302`와 `302호` 동일 처리

**실행 절차:** 기존 호수가 `302`인 상태에서 `302호`를 신규 등록하려 한다.

**예상 결과:** 두 값을 같은 호실로 인식하고 기존 호실 선택을 안내한다.

## TC-010. 건물명만 같고 지번이 다른 경우

**실행 절차:** 건물명은 `대성빌`이지만 지번이 다른 건물을 등록한다.

**예상 결과:** 자동으로 기존 대성빌에 합치지 않고, 다른 지번임을 사용자가 확인할 수 있게 한다.

# 8. 기존 건물의 신규 호실 테스트

## TC-011. 건물정보 재입력 없이 새 호실 등록

**사전조건:** 대성빌은 있고 201호는 없다.

**실행 절차:**

1. 대성빌을 선택한다.
2. `새 호실 등록`을 누른다.
3. 201호와 첫 매물 조건을 입력한다.
4. 저장한다.

**예상 결과:**

- 주소·공동현관·엘리베이터·주차를 다시 입력하지 않는다.
- 기존 건물에 201호가 연결된다.
- 201호의 첫 매물 회차가 생성된다.
- 기존 302호 데이터에는 변화가 없다.

# 9. 기존 호실 최신 정보 수정 테스트

## TC-012. 기존 고정정보 자동 불러오기

**사전조건:** 대성빌 302호의 첫 매물이 종료돼 있다.

**실행 절차:** 대성빌 → 302호 → `최신 정보 수정`을 선택한다.

**예상 결과:** 건물 주소, 공동현관, 호실 형태, 방향, 특징, 방문 방법이 표시된다.

## TC-013. 현재 가격을 기본값으로 표시

**예상 결과:** 현재 조건 500/45가 입력칸의 기본값으로 보이고, 바뀐 값만 수정할 수 있다.

## TC-014. 기존 호실 최신 정보 저장

**실행 절차:** 기존 호실을 선택해 500/47, 공실, 즉시입주로 바꾸고 `최신 정보 저장`을 누른다.

**예상 결과:**

- 새 매물 회차는 생성되지 않는다.
- 선택한 최신 매물 기록의 가격·상태·입주 가능 정보가 바뀐다.
- 현재 매물 목록에는 500/47이 표시된다.
- 연결된 계약·상담 기록은 그대로 유지된다.
- 기존 호실 옵션 체크값과 기타 옵션 메모를 수정하면 호실 기본정보에 반영된다.

## TC-015. 가격 확인 필요 처리

**실행 절차:** 가격 입력 단계에서 `가격 확인 필요`를 선택한다.

**예상 결과:** 보증금·월세를 0으로 저장하지 않고 확인 필요 항목으로 표시한다.

## TC-016. 기존 호실 바로 수정

**사전조건:** 대성빌 302호에 종료되지 않은 활성 매물이 있다.

**실행 절차:** 같은 호실을 선택해 최신 정보를 수정하려 한다.

**예상 결과:** 기존 호실을 선택하면 최신 매물 정보 입력칸이 바로 표시된다. 저장하면 새 매물 회차를 만들지 않고 같은 최신 매물 기록을 수정한다. 연결된 계약·상담 기록은 유지된다.

## TC-017. 재등록 시 확인일 오기록 방지

**실행 절차:** 기존 비밀번호와 옵션을 보지만 실제 확인하지 않은 채 재등록한다.

**예상 결과:** 기존값은 유지되지만 해당 정보의 마지막 확인일은 자동으로 오늘로 바뀌지 않는다.

# 10. 현재 매물 수정 테스트

## TC-018. 현재 가격 수정

**실행 절차:** 활성 매물의 월세를 47에서 45로 수정하고 `현재 매물 수정`을 누른다.

**예상 결과:** 새 회차를 만들지 않고 현재 회차의 월세와 수정일시만 변경된다.

## TC-019. 입주 가능 유형 변경

**실행 절차:** 날짜 지정 매물을 `즉시입주`로 변경한다.

**예상 결과:** 현재 목록에 즉시입주가 표시되고, 과거 날짜가 현재 입주일로 잘못 노출되지 않는다.

## TC-020. 사진 보유 여부 변경

**실행 절차:** 사진 보유 여부를 `없음`에서 `있음`으로 변경한다.

**예상 결과:** 사진 촬영 필요 목록에서 사라지고 사진 보유 칸에 `있음`으로 표시된다.

## TC-021. 여러 값 수정 후 한 번에 저장

**실행 절차:** 상태, 가격, 입주일, 메모를 차례로 바꾸고 `변경사항 저장`을 누른다.

**예상 결과:** 입력 중에는 저장되지 않고 버튼을 누를 때 한 번에 모두 반영된다.

# 11. 건물·호실 기본정보 수정 테스트

## TC-022. 공동현관 비밀번호 변경

**실행 절차:** 건물 상세에서 공동현관 비밀번호를 변경하고 건물 기본정보로 저장한다.

**예상 결과:** 같은 건물의 모든 호실 상세에서 변경된 공동현관 비밀번호를 확인할 수 있다.

## TC-023. 호실 방향 수정

**실행 절차:** 302호 방향을 수정하고 `호실 기본정보 저장`을 누른다.

**예상 결과:** 향후 재등록 시 변경된 방향을 불러온다. 과거 매물의 가격·상태는 변하지 않는다.

## TC-024. 이번 매물에만 다른 옵션 적용

**실행 절차:** 기본 옵션과 다른 내용을 `이번 매물에만 적용`으로 저장한다.

**예상 결과:** 호실 기본 옵션은 유지되고, 이번 매물 회차의 옵션 변경 메모에만 저장된다.

# 12. 매물 상태·종료 테스트

## TC-025. 계약 완료 처리

**실행 절차:** 활성 매물을 종료하고 사유를 `계약 완료`로 선택한다.

**예상 결과:**

- 종료일과 종료 사유가 기록된다.
- 현재 활성 목록에서 제외된다.
- 호실의 과거 매물 이력에서는 확인 가능하다.

## TC-026. 계약 여부 미확인 상태

**실행 절차:** 매물이 기존 목록에서 사라졌지만 실제 계약 여부를 확인하지 못했다.

**예상 결과:** 자동으로 계약 완료가 되지 않는다. `확인 필요` 또는 `보류`로 처리할 수 있다.

## TC-027. 잘못 등록한 매물 삭제

**실행 절차:** 잘못 등록한 매물에서 `이 매물 완전 삭제`를 열고, 삭제 확인을 선택한 뒤 삭제한다.

**예상 결과:** 매물은 현재 목록과 과거 이력에서 사라진다. 연결된 계약·상담 기록도 함께 삭제된다. 건물·호실은 남는다.

## TC-028. 잘못 만든 호실 완전 삭제

**실행 절차:** 잘못 만든 호실에서 `이 호실 완전 삭제`를 열고, 삭제될 매물·계약·상담 건수를 확인한 뒤 삭제 확인을 선택한다.

**예상 결과:** 선택한 호실과 연결된 매물·계약·상담 기록이 함께 삭제된다. 건물 정보는 남고, 등록 화면의 기존 호실 목록에서도 해당 호실이 사라진다.

# 13. 매물 현황 리스트 테스트

## TC-029. 오늘 새 접수 필터

**예상 결과:** 오늘 접수된 매물만 표시되고 숫자와 표의 건수가 일치한다.

## TC-030. 퇴실 예정 필터

**예상 결과:** 상태가 퇴실 예정인 활성 매물만 표시된다.

## TC-031. 재확인 필요 자동 표시

**사전조건:** 재확인 예정일이 오늘이거나 지난 매물이 있다.

**예상 결과:** 재확인 필요 숫자와 목록에 해당 매물이 표시된다.

## TC-032. 사진 촬영 필요 필터

**예상 결과:** 사진 보유 여부가 `없음`인 활성 매물만 표시된다.

사진 보유 여부를 `있음 / 없음 / 확인 필요` 중에서 선택할 수 있고, `없음`인 매물은 사진 촬영 필요 목록에 표시된다.

사진 보유 여부가 `확인 필요`이면 `해야 할 일`에 `사진 확인 필요`가 표시되고, 같은 이름의 확인 업무 필터로 찾을 수 있다.

## TC-032-1. 등록 화면 관리 상태와 현황 업무 일치

**실행 절차:** 매물 등록 또는 최신 정보 수정에서 사진 보유 여부를 `없음`, 청소 상태를 `필요`, 재확인 예정일을 오늘로 저장한다.

**예상 결과:** 별도 할 일 입력 없이 현황 리스트의 `해야 할 일`에 `사진 촬영 필요`, `현장 상태 확인 필요`, `재확인 필요`가 표시된다. 현황 리스트의 빠른 수정에서도 같은 관리 상태를 수정할 수 있다.

## TC-033. 건물명·지번·호수 검색

**실행 절차:** `대성빌`, `북수리 1026`, `302`를 각각 검색한다.

**예상 결과:** 세 검색어 모두 대성빌 302호를 찾는다.

## TC-034. 여러 필터 조합

**실행 절차:** 형태 `원룸`, 상태 `퇴실 예정`, 확인 업무 `사진 촬영`을 함께 선택하고 조회한다.

**예상 결과:** 세 조건을 모두 만족하는 매물만 표시된다.

## TC-035. 필터 초기화

**예상 결과:** 모든 필터가 기본값으로 돌아가고 활성 매물 전체가 다시 표시된다.

## TC-035-2. 보증금·월세 범위 필터

**실행 절차:** 보증금 최소 500, 최대 500과 월세 최소 45, 최대 45를 입력해 조회한다. 이어 보증금 최소를 최대보다 크게 입력해 조회한다.

**예상 결과:** 두 금액 조건을 모두 만족하는 매물만 표시된다. 금액이 비어 있는 매물은 해당 금액 범위를 적용한 결과에 나오지 않는다. 최소·최대 순서가 잘못되면 조회하지 않고 해당 금액 범위를 고치라는 안내가 보인다.

## TC-035-3. 지번 지역·번호 분리 입력·표시·엑셀

**실행 절차:** 새 건물 등록에서 지번 지역 `장재리`, 번지 번호 `1234`를 입력한다. 이어 현황 리스트에서 `장재리`, `1234`, `장재리 1234`를 각각 검색하고, 매물 엑셀을 내려받는다.

**예상 결과:** 등록값은 기존 통합 지번값으로 저장돼 세 검색어 모두 결과를 찾는다. 현황 리스트와 매물 엑셀에는 `지번 지역`과 `번지 번호`가 별도 열로 표시된다. 기존 지번 데이터는 자동 수정·삭제되지 않는다.

## TC-035-1. 종료된 매물 조회

**실행 절차:** 매물 현황 리스트에서 현재 매물 1건을 선택하고 `이 매물 종료 처리`에서 종료 사유·종료일을 입력한 뒤 확인 체크와 `종료 처리`를 누른다. 이어 `표시할 매물`을 `종료된 매물만`으로 선택해 조회한다.

**예상 결과:** 종료 후 해당 매물은 기본 `현재 매물만` 표에서 사라지고, 종료일·종료 사유가 기록된다. 기본 표에는 종료일·종료 사유 열이 보이지 않는다. `종료된 매물만` 또는 `전체` 조회에서는 종료된 매물과 함께 두 열을 확인할 수 있으며, 종료된 매물은 현황 리스트에서 조회만 한다.

# 18-1. 계약관리 테스트

## TC-061. 단기계약 등록

**실행 절차:** 대성빌 302호의 5월 매물 회차를 선택하고 `5월 1일 계약 진행 시작 / 계약 진행 / 단기계약`을 등록한 뒤, `5월 8일 정식 계약 / 6월 1일~11월 30일 임대차 기간 / 계약 완료`로 수정한다.

**예상 결과:** 가계약 진행 기록과 정식 계약·임대차 기간이 같은 계약 기록에 이어서 저장되며, 계약은 302호 자체가 아니라 선택한 5월 매물 회차에 연결된다.

가계약 단계에서 계약금 전체를 100만원, 가계약금 수령액을 50만원, 계약금 추가 수령 예정일을 8월 8일, 잔금을 900만원으로 입력하면 계약금 미수령 50만원이 표시된다. 가계약금 수령액을 계약금 전체보다 크게 입력하면 저장되지 않는다.

## TC-062. 같은 호실의 반복 단기계약 이력

**실행 절차:** 같은 302호의 11월 매물 회차를 선택하고 `11월 1일 시작 / 3개월 / 단기계약`을 등록한다.

**예상 결과:** 5월 6개월 계약과 11월 3개월 계약이 별도 기록으로 모두 남고, 서로의 기간·상태를 덮어쓰지 않는다.

## TC-063. 계약 해지·만료 이력 보존

**실행 절차:** 저장된 계약의 상태를 해지 또는 만료로 바꾼다.

**예상 결과:** 계약 기록은 삭제되지 않으며, 상태 변경과 수정일만 반영된다.

## TC-064. 계약 범위 밖 정보 미저장

**예상 결과:** 계약자 연락처와 계약금·잔금은 내부정보로 입력할 수 있으며, 결제와 계약서 파일 입력 기능은 없다.

## TC-064-1. 계약 조회 결과 엑셀 내보내기

**실행 절차:** 계약 상태 또는 임대차 종료일 조건으로 계약을 조회한 뒤 `계약 조회 결과 엑셀 내려받기`를 누른다.

**예상 결과:** 현재 조회 결과와 같은 건수의 계약이 들어가고, 날짜·금액은 정렬 가능한 형식으로 저장된다. 계약자 연락처 열은 없다.

## TC-064-2. 계약 일정과 잔금 예정일

**실행 절차:** 계약 진행 시작일·정식 계약일·계약금 추가 수령 예정일·잔금 예정일·임대차 종료일이 각각 다른 계약을 준비한다. 기준일을 바꿔 계약 일정 화면을 확인한다.

**예상 결과:** 해당 날짜의 일정이 각각 표시된다. 임대차 종료는 7일 이내, 8~15일, 16~30일, 당일 또는 지남으로 한 번만 분류된다. 해지·만료 계약은 만료 예정 목록에 없다.

## TC-064-3. 통합 오늘 할 일 개인정보 보호

**실행 절차:** 매물 재확인, 계약 일정, 상담 다음 연락일이 같은 기준일에 있는 데이터를 준비해 오늘 할 일을 조회한다.

**예상 결과:** 업무 종류·기한·건물·호실·상태만 표시되며, 연락처·비밀번호·내부 메모는 보이지 않는다. 원래 기록을 수정하면 통합 업무 목록도 다시 계산된다.

## TC-065. 상담 이력 누적과 다음 연락 확인

**실행 절차:** 대성빌 302호의 매물 회차에 전화 상담과 방문 상담을 각각 등록하고, 한 상담의 다음 연락일을 오늘 이전 날짜로 입력한다.

**예상 결과:** 두 상담 기록이 해당 매물 회차에 날짜순으로 남고, 지난 다음 연락일의 상담은 `다음 연락 필요`로 표시된다.

## TC-066. 상담 고객 정보 보호

**실행 절차:** 고객 이름과 연락처를 입력해 상담을 저장한 뒤, 기본 매물 목록과 상담 목록을 확인한다.

**예상 결과:** 고객 이름은 상담 목록에서 확인할 수 있고, 연락처는 상담 상세에서 `연락처 보기`를 눌렀을 때만 표시된다. 두 정보 모두 기본 매물 목록과 일반 엑셀에는 표시되지 않는다.

## TC-067. 상담 범위 밖 정보 미저장

**예상 결과:** 상담관리 화면에는 자동 문자 발송, 방문 예약 달력, 주민번호 등 민감 개인정보 입력 기능이 없다.

## TC-067-1. 상담 조회 결과 엑셀 내보내기

**실행 절차:** 상담 상태 또는 `다음 연락 필요만 보기` 조건으로 상담을 조회한 뒤 `상담 조회 결과 엑셀 내려받기`를 누른다.

**예상 결과:** 현재 조회 결과와 같은 건수의 상담이 들어가며, 고객 이름·연락처와 자유 입력 상담 내용 열은 없다.

## TC-068. 계약 기록 삭제

**실행 절차:** 계약 조회·수정에서 저장된 계약을 선택하고 `이 계약 기록 완전 삭제`를 연 뒤, 삭제 확인을 선택해 삭제한다.

**예상 결과:** 선택한 계약만 목록에서 사라지고, 연결된 매물과 상담 기록은 남는다.

## TC-069. 상담 기록 삭제

**실행 절차:** 상담 조회·수정에서 저장된 상담을 선택하고 `이 상담 기록 완전 삭제`를 연 뒤, 삭제 확인을 선택해 삭제한다.

**예상 결과:** 선택한 상담만 목록에서 사라지고, 연결된 매물과 계약 기록은 남는다.

## TC-070. 일반 상담 등록과 매물 연결

**실행 절차:** 상담 등록에서 `일반 상담`을 선택해 매물 없이 고객 정보와 희망 조건을 저장한다. 이후 상담 상세에서 맞는 매물 회차를 찾아 연결한다.

**예상 결과:** 일반 상담은 연결 매물 없이 조회되며 희망 조건을 확인할 수 있다. 매물을 연결한 뒤에도 상담 내용과 희망 조건은 유지된다.

## TC-071. 고객 이름 없이 빈 상담 저장

**실행 절차:** 매물 상담 또는 일반 상담 등록에서 고객 이름을 입력하지 않고, 연락처·상담 내용 등 선택 입력값도 비운 채 저장한다.

**예상 결과:** 고객 이름 입력칸이 없으며, 저장이 가능하다. 비어 있는 값은 내부적으로 `미입력`으로 기록되고 기존 상담 기록은 바뀌지 않는다.

## TC-072. 상담 구분·상담일 필터

**실행 절차:** 일반 상담과 매물 상담을 각각 1건 이상 준비한다. 상담 조회·수정에서 `일반 상담`만 선택해 조회하고, 이어 상담일 시작·종료일을 선택해 기간을 좁혀 조회한다.

**예상 결과:** 선택한 상담 구분과 상담일 기간을 모두 만족하는 기록만 보인다. 시작일보다 빠른 종료일을 선택하면 조회하지 않고 날짜 순서를 안내한다. 상태·다음 연락 필요 필터를 함께 선택해도 모든 조건을 만족하는 기록만 보인다.

# 19. 성능 기준

테스트 기준 데이터는 건물 200건, 호실 1,000건, 매물 회차 5,000건 이하로 구성한다.

| 항목 | 합격 기준 |
|---|---|
| 첫 화면 표시 | 사무실 내부망에서 통상 3초 이내 |
| 건물·호실 검색 | 검색 실행 후 통상 2초 이내 |
| 매물 저장 | 저장 클릭 후 통상 2초 이내 |
| 필터 조회 | 조회 클릭 후 통상 2초 이내 |
| 상세정보 열기 | 통상 1초 이내 |
| 엑셀 내보내기 | 테스트 기준 데이터에서 10초 이내 |

운영 PC 성능이나 네트워크 이상이 아닌데 기준을 반복적으로 넘으면 개선 후 재시험한다.

## 20. 결함 등급

| 등급 | 기준 | 예시 |
|---|---|---|
| 치명적 | 데이터 유실·손상 또는 프로그램 사용 불가 | 과거 매물 삭제, 저장 후 DB 손상 |
| 높음 | 핵심 업무 진행 불가 | 신규 등록 불가, 재등록 시 과거값 덮어쓰기 |
| 보통 | 우회 가능하지만 업무 지연 | 특정 필터 오류, 일부 입력 검증 오류 |
| 낮음 | 업무에는 영향이 적은 표시 문제 | 문구·정렬·여백 오류 |

치명적·높음 결함은 1차 배포 전에 반드시 해결한다.

## 21. 최종 수용 기준

1차 버전은 다음 조건을 모두 충족해야 사무실 운영을 시작할 수 있다.

- TC-001부터 TC-060까지 적용 대상 테스트를 완료한다.
- 치명적 결함과 높음 결함이 0건이다.
- 신규 건물·호실·첫 매물 등록이 정상 작동한다.
- 기존 호실 최신 정보 수정 시 새 매물 회차가 생기지 않고 계약·상담 기록이 유지된다.
- 오늘의 현황에서 확인 필요 매물을 찾을 수 있다.
- 공동현관·방문 비밀번호는 기본 목록에 노출되지 않으며, 임대인·세입자 개인 연락처와 상담관리 고객 이름·연락처는 일반 엑셀 내보내기에 포함되지 않는다.
- 프로그램 재시작 후 데이터가 유지된다.
- SQLite 백업본으로 복구할 수 있다.
- 두 사용자 PC에서 같은 데이터를 조회할 수 있다.
- 기존 `구재현` 시트 가져오기 기능이 존재하지 않는다.
- 실제 사용자가 대성빌 302호 신규등록과 최신 정보 수정을 별도 설명 없이 완료할 수 있다.
