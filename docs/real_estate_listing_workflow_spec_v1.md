# 부동산 매물관리 도구 등록·수정 업무 흐름서 v1.0

> 문서 목적: 사용자가 실제 화면에서 어떤 순서로 검색·입력·저장하는지 정의한다.
>
> 운영 기준: 기존 `구재현` 시트는 이전하지 않는다. 새 도구 사용 시점부터 현재 필요한 매물만 직접 등록한다.

## 1. 공통 원칙

1. 모든 등록은 먼저 건물명 또는 지번을 검색하는 것으로 시작한다.
2. 기존 건물·호실이 있으면 새로 만들지 않고 기존 기록을 선택한다.
3. 기본 화면에는 필수항목만 표시하고, 나머지는 `상세정보`에서 입력한다.
4. 같은 호실의 조건이 바뀌면 호실을 새로 만들지 않고 최신 매물 정보를 수정한다.
5. 모르는 값은 임의로 입력하지 않고 `확인 필요`로 남긴다.
6. 저장 전에 사용자가 입력한 대상과 가격을 한 줄로 확인한다.
7. 기존값을 바꾸는 경우 `기본정보 수정`인지 `이번 매물만 적용`인지 구분한다.

## 2. 시작 화면

사용자가 `매물 등록·수정` 메뉴를 누르면 처음 보이는 화면이다.

```text
건물명 또는 지번 검색
[                              ] [검색]

최근 등록한 건물
- 대성빌 · 북수리 1026
- ○○빌 · 북수리 1270

[새 건물 등록]
```

검색 결과는 다음 정보를 보여준다.

| 표시 항목 | 목적 |
|---|---|
| 건물명 | 이름이 비슷한 건물 구분 |
| 지번 | 동일 건물 확인 |
| 등록 호실 수 | 기존 데이터 존재 여부 확인 |
| 마지막 확인일 | 정보가 오래됐는지 판단 |

검색어 입력 전에는 전체 건물 목록을 길게 펼치지 않는다. 최근 등록한 건물만 소수 표시한다.

# 3. 상황 A: 신규 건물 + 신규 호실 + 첫 매물 등록

## 3.1 사용 조건

- 건물명 또는 지번을 검색했지만 등록된 건물이 없다.
- 새 도구 사용 이후 처음 접수된 건물이다.

## 3.2 화면 흐름

### 단계 A-1. 기존 건물 검색

사용자가 건물명 또는 지번을 입력한다.

검색 결과가 없으면 다음 문구를 표시한다.

> 등록된 건물이 없습니다. 새 건물로 등록하시겠습니까?

버튼:

- `새 건물 등록`
- `다시 검색`

### 단계 A-2. 건물 최소정보 입력

기본 표시 항목:

| 항목 | 필수 | 입력 예시 |
|---|---:|---|
| 건물명 | 아니오 | 대성빌 · 모르면 비워 둠 |
| 지번 | 예 | 북수리 1026 |
| 공동현관 비밀번호 | 아니오 | 1234# |
| 건물 메모 | 아니오 | 주차장 입구가 좁음 |

`건물 상세정보`를 펼치면 엘리베이터, 주차 등 필요한 건물 정보를 입력할 수 있다. 건물명이 없으면 `건물명 미입력`으로 저장한다. 새 건물 등록은 지번을 기준으로 관리하므로 행정주소와 도로명주소 입력칸은 제공하지 않는다.

건물만 별도로 저장한 뒤 화면을 닫지 않는다. 바로 호실 입력으로 이어진다.

### 단계 A-3. 호실 최소정보 입력

| 항목 | 필수 | 입력 예시 |
|---|---:|---|
| 호수 | 예 | 302 |
| 룸 형태 | 권장 | 분리형 원룸 |
| 층 | 아니오 | 3층 자동 제안 |
| 방문 방법 | 아니오 | 비밀번호 |
| 방문 비밀번호 | 아니오 | 5678# |

호수 입력 시 층을 자동 제안할 수 있지만 저장 전 수정 가능해야 한다.

호실 옵션은 냉장고, 세탁기, 에어컨, TV, 가스렌지, 인덕션, 옷장, 신발장을 체크박스로 선택하고, 목록에 없는 내용은 `기타 옵션 메모`에 적는다. 방향과 구조상 장점 등은 `호실 상세정보`에서 입력한다. 사진 파일·사진 위치·사진 링크는 이 도구에서 입력하지 않는다.

### 단계 A-4. 첫 매물 조건 입력

| 항목 | 필수 | 입력 예시 |
|---|---:|---|
| 매물 상태 | 예 | 퇴실 예정 |
| 보증금(만원) | 예 | 500 |
| 월세(만원) | 예 | 45 |
| 입주 가능 유형 | 예 | 날짜 지정 |
| 입주 가능일 | 조건부 | 2026-08-20 |
| 이번 매물 메모 | 아니오 | 세입자와 방문시간 협의 |

입주 가능 유형이 `날짜 지정`일 때만 날짜 입력창을 보여준다.

### 단계 A-5. 저장 전 확인

저장 버튼 위에 아래 내용을 한 줄로 보여준다.

> 대성빌 · 북수리 1026 · 302호 · 분리형 원룸 · 500/45 · 8월 20일 입주 가능

저장 버튼:

> `건물·호실·첫 매물 등록`

### 단계 A-6. 저장 완료

저장 성공 후 다음 결과를 표시한다.

> 대성빌 302호가 등록되었습니다.

버튼:

- `현재 매물 목록에서 보기`
- `같은 건물의 다른 호실 등록`
- `새 매물 등록`

## 3.3 저장되는 데이터

- 건물 1건 생성
- 호실 1건 생성
- 매물 회차 1건 생성

세 저장 중 하나라도 실패하면 일부만 저장된 상태로 남기지 않고 전체 저장을 취소한다.

# 4. 상황 B: 기존 건물 + 신규 호실 + 첫 매물 등록

## 4.1 사용 조건

- 건물은 이미 등록돼 있다.
- 이번 호실은 아직 등록돼 있지 않다.

## 4.2 화면 흐름

### 단계 B-1. 건물 선택

건물명 또는 지번으로 기존 건물을 선택한다.

선택 즉시 다음 요약을 표시한다.

```text
대성빌 · 북수리 1026
공동현관 1234# · 엘리베이터 있음 · 주차 가능
등록 호실: 201, 301, 401
```

내부정보인 공동현관 비밀번호는 등록·상세 화면에서만 보여준다.

### 단계 B-2. 신규 호실 선택

기존 호실 목록 아래에 다음 버튼을 둔다.

> `새 호실 등록`

사용자는 호수와 룸 형태를 입력한다. 기존 건물정보는 다시 입력하지 않는다.

### 단계 B-3. 매물 조건 입력

상태, 보증금, 월세, 입주 가능 유형을 입력한다. 필요한 경우 상세정보를 추가한다.

저장 버튼:

> `새 호실·첫 매물 등록`

## 4.3 저장되는 데이터

- 기존 건물정보 유지
- 새 호실 1건 생성
- 새 매물 회차 1건 생성

---

# 5. 상황 C: 기존 호실의 최신 매물 정보 수정

## 5.1 사용 조건

- 과거에 등록했던 동일 호실의 가격·상태·입주일 등 최신 조건이 바뀌었다.
- 이 기능은 같은 호실을 다시 만들지 않고 필요한 정보만 갱신하는 핵심 흐름이다.

## 5.2 화면 흐름

### 단계 C-1. 건물과 호실 선택

건물 선택 후 등록된 호실을 표로 보여준다.

| 호실 | 구조 | 최근 조건 | 최근 상태 | 마지막 접수일 |
|---|---|---|---|---|
| 201 | 원룸 | 300/40 | 종료 | 2026-03-10 |
| 302 | 분리형 원룸 | 500/45 | 계약 완료 | 2026-02-20 |
| 401 | 원룸 | 500/42 | 공실 | 2026-07-30 |

이미 활성 매물이 있는 호실을 선택하면 다음 경고를 표시한다.

> 선택한 호실의 최신 매물 정보를 아래에서 바로 수정합니다. 연결된 계약·상담 기록은 유지됩니다.

호실을 선택하면 별도의 재등록 확인 단계 없이 최신 정보 입력칸을 같은 화면에 바로 표시한다.

### 단계 C-2. 기존정보 자동 불러오기

자동으로 불러오는 정보:

- 건물명과 주소
- 공동현관 비밀번호
- 엘리베이터·주차 등 건물정보
- 호수·층·룸 형태·방향
- 호실 옵션과 구조 특징
- 방문 방법과 방문 비밀번호
- 사진 보유 여부(있음 / 없음 / 확인 필요)

이 정보는 바로 수정하지 않고 요약 형태로 보여준다.

### 단계 C-3. 이전 매물 참고값 표시

```text
이전 매물: 500/45
이전 관리비: 5만원
이전 상태: 계약 완료
마지막 등록: 2026-02-20
```

기존 가격과 상태를 기본값으로 불러온다. 바뀐 값만 수정해 저장하며, 연결된 계약·상담 기록은 유지한다.

호실 옵션도 같은 화면에서 냉장고, 세탁기, 에어컨, TV, 가스렌지, 인덕션, 옷장, 신발장 체크박스로 수정한다. 기존 체크값과 기타 옵션 메모를 불러오며, 체크를 해제하거나 기타 메모를 바꾸면 호실 기본 옵션에 반영한다.

가격 입력 방식:

- `이전 가격 유지`
- `새 가격 입력`
- `가격 확인 필요`

`가격 확인 필요`를 선택하면 보증금·월세를 0으로 저장하지 않고, 매물 상태 또는 확인 메모에 가격 확인 필요를 남긴다.

### 단계 C-4. 이번 매물 최소정보 입력

| 항목 | 처리 방식 |
|---|---|
| 매물 상태 | 반드시 새로 선택 |
| 보증금·월세 | 유지·새 입력·확인 필요 중 선택 |
| 입주 가능 유형 | 반드시 새로 선택 |
| 입주 가능일 | 날짜 지정 시 새로 입력 |
| 이번 매물 메모 | 필요한 경우 입력 |

### 단계 C-5. 변경 가능 정보 빠른 확인

모든 상세정보를 다시 묻지 않고 아래 항목만 간단히 확인한다.

| 항목 | 선택값 |
|---|---|
| 공동현관 비밀번호 | 기존값 유지 / 수정 / 확인 필요 |
| 방문 방법·비밀번호 | 기존값 유지 / 수정 / 확인 필요 |
| 관리비 | 기존값 유지 / 수정 / 확인 필요 |
| 옵션 | 변경 없음 / 변경 있음 / 확인 필요 |
| 사진 보유 여부 | 있음 / 없음 / 확인 필요. 사진 관련 업무는 이 값 하나로 판단 |
| 청소·도배·수리 | 완료 / 필요 / 진행 중 / 확인 필요 |

기본값은 자동으로 `기존값 유지`로 확정하지 않는다. 사용자가 이번 매물에서 확인하지 않은 항목은 이전 정보를 보여주되, 마지막 확인일을 갱신하지 않는다.

### 단계 C-6. 저장

저장 버튼:

> `최신 정보 저장`

저장 전 확인:

> 대성빌 302호의 최신 매물 정보를 500/47, 퇴실 예정, 8월 25일 입주 가능으로 저장합니다.

## 5.3 저장되는 데이터

- 건물정보 유지
- 호실 고정정보 유지 또는 확인된 변경만 수정
- 선택한 최신 매물 기록의 조건 갱신
- 연결된 계약·상담 기록 유지

# 6. 상황 D: 현재 매물 조건 수정

## 6.1 사용 조건

새 매물이 다시 나온 것이 아니라, 현재 운영 중인 매물의 조건이 바뀐 경우다.

예시:

- 임대인이 월세를 45만원에서 43만원으로 조정
- 입주 가능일이 8월 20일에서 즉시입주로 변경
- 사진 촬영을 완료
- 청소가 완료됨

## 6.2 처리 원칙

기존 호실을 선택하면 최신 매물 기록 안에서 다음 값을 바로 수정한다.

- 매물 상태
- 보증금·월세·관리비
- 입주 가능일
- 사진·청소·도배·수리·광고 상태
- 이번 매물 메모
- `확인·관리 사항`: 사진 보유 여부, 청소·도배·수리 상태, 재확인 예정일. 이 값으로 현황 리스트의 해야 할 일을 자동 표시한다.

수정 시 `updated_at`을 자동 기록한다.

가격 변경 이력은 별도로 만들지 않는다. 같은 최신 매물 기록의 현재값을 수정하며, 계약·상담 기록은 같은 매물 기록에 유지한다.

저장 버튼:

> `최신 정보 저장`

신규 등록 버튼과 색상·문구를 분명히 구분한다.

---

# 7. 상황 E: 건물·호실 기본정보 수정

## 7.1 사용 조건

- 공동현관 비밀번호가 변경됨
- 방향이나 룸 형태가 잘못 입력됨
- 옵션·방문 방법이 바뀜

## 7.2 수정 범위 확인

기존정보와 다른 값을 입력하면 다음 선택을 표시한다.

```text
이 변경을 어디에 적용할까요?

( ) 건물·호실 기본정보 수정
( ) 이번 매물에만 적용
```

적용 기준:

| 항목 | 기본 적용 위치 |
|---|---|
| 건물명·주소·공동현관·엘리베이터 | 건물 기본정보 |
| 호수·구조·방향·방문 방법 | 호실 기본정보 |
| 가격·입주일·청소·광고 상태 | 이번 매물 회차 |
| 이번에만 다른 옵션 | 이번 매물 회차 메모 |

# 8. 상황 F: 매물 종료 처리

## 8.1 종료 흐름

매물 현황 리스트에서 현재 매물을 선택한 뒤, 아래의 `이 매물 종료 처리`를 펼쳐 `종료 처리`를 누른다. 매물 등록·수정 화면에서도 같은 종료 처리를 할 수 있다.

종료 사유 선택:

- 계약 완료
- 타 부동산 계약
- 임대인 보류
- 광고 중단
- 정보 오류
- 기타

계약 여부가 확인되지 않으면 `계약 완료`를 선택하지 않는다. `확인 필요` 또는 `보류`로 둔다.

종료 저장 후:

- 현재 매물 기본 목록에서 제외
- 호실의 과거 매물 이력에는 유지
- 종료일과 종료 사유 기록

# 9. 매물 현황 리스트 처리 흐름

> 구현 기준: 등록·건물정보 수정에서는 지번 지역과 번지 번호를 따로 입력하고, 기존 지번값으로 합쳐 저장한다. 현황 리스트와 매물 엑셀에는 지번 지역·번지 번호를 독립 열로 표시하며, 매물 엑셀의 중복 `지번주소` 열은 제외한다. 통합검색은 합쳐진 지번값을 계속 사용한다.

## 9.1 상단 요약

다음 숫자만 보여준다.

- 오늘 새 접수
- 퇴실 예정
- 재확인 필요
- 사진 촬영 필요(사진 보유 여부가 없음)
- 사진 확인 필요(사진 보유 여부가 확인 필요)
- 광고 준비 필요

## 9.2 표에서 가능한 빠른 작업

| 작업 | 처리 방식 |
|---|---|
| 상태 변경 | 표에서 선택 후 저장 |
| 입주 가능일 수정 | 날짜 선택 후 저장 |
| 사진 보유 여부 | 있음 / 없음 / 확인 필요 중 선택. 없음이면 사진 촬영 필요, 확인 필요면 사진 확인 필요가 자동 표시 |
| 재확인 완료 | 마지막 확인일 기록, 다음 확인일 선택 |
| 상세 확인 | 행을 눌러 매물 상세 열기 |
| 종료 처리 | 현재 매물을 선택한 뒤 종료 사유·종료일을 입력하고 확인 후 저장. 목록에서 제외 |

보증금과 월세는 각각 최소·최대 금액(만원) 범위로 필터할 수 있으며, 다른 검색·상태·룸 형태·사진·확인 업무 조건과 함께 적용한다. 금액이 비어 있는 매물은 해당 금액 범위에 포함하지 않는다.

여러 행을 한꺼번에 수정하는 기능은 실제 필요가 확인되기 전까지 만들지 않는다.

# 10. 오류 방지 규칙

## 10.1 저장 전 검사

- 지번이 비어 있으면 건물 저장 불가. 건물명은 비워 둘 수 있으며 이때 `건물명 미입력`으로 저장
- 호수가 비어 있으면 호실 저장 불가
- 같은 건물의 같은 호수가 이미 있으면 새 호실 생성 차단
- 보증금·월세에 문자가 포함되면 숫자 입력 안내
- 입주 유형이 날짜 지정인데 날짜가 없으면 저장 차단
- 기존 호실을 선택하면 해당 최신 매물 기록을 수정하며 새 매물 회차를 만들지 않음

## 10.2 삭제 원칙

- 매물 회차는 매물 현황 리스트와 매물 등록·수정 화면에서 완전 삭제할 수 있다.
- 삭제 전에는 연결된 계약·상담 기록도 함께 삭제됨을 알리고 확인을 받는다.
- 잘못 등록한 매물은 필요에 따라 `정보 오류` 종료 처리로 이력을 남길 수도 있다.
- 건물은 `비활성`으로 전환해 목록에서 숨긴다.
- 잘못 만든 호실은 매물·계약·상담 기록 수를 먼저 보여 주고 사용자가 명시적으로 확인한 경우에만 완전 삭제할 수 있다. 이때 연결된 매물·계약·상담 기록도 함께 삭제되며 건물은 남는다.

## 10.3 저장 성공·실패 표시

성공:

> 저장되었습니다: 대성빌 302호 · 500/45

실패:

> 저장하지 못했습니다. 입력값은 유지됩니다. 표시된 항목을 확인해 주세요.

저장 실패 시 사용자가 입력한 내용을 화면에서 지우지 않는다.

# 11. 화면 전환 원칙

- 저장 전 다른 메뉴로 이동하면 `입력 중인 내용이 있습니다` 경고를 표시한다.
- 저장 후 목록으로 강제 이동하지 않고 다음 행동을 선택하게 한다.
- 브라우저 새로고침 후 미저장 입력 복구는 1차 범위에서 제외한다.
- 비밀번호는 목록에 노출하지 않고 상세 화면에서만 확인한다.
- 한 화면에서 필수입력과 상세입력을 시각적으로 구분한다.

# 13. 계약관리 흐름

1. 계약관리의 `계약 등록` 화면에서 건물명·지번·호수로 관련 매물 회차를 찾는다.
2. 반드시 계약할 당시의 매물 회차를 선택한다. 건물이나 호실에 직접 계약을 붙이지 않는다.
3. 가계약 단계에서는 계약 상태를 `계약 진행`으로 두고 계약 진행 시작일, 계약금 전체, 가계약금 수령액, 남은 계약금 수령 예정일을 기록한다. 화면은 계약금 미수령액을 자동 계산한다. 정식 계약 뒤에는 정식 계약일, 임대차 시작일·종료일 또는 기간(개월)을 이어서 입력한다.
4. 저장 전 `대성빌 302호 / 2026-05-01 진행 시작 / 2026-05-08 정식 계약 / 6개월 단기계약`처럼 구분해 보여 준다.
5. 저장하면 새 계약 기록을 추가한다. 기존 계약·매물 가격·매물 상태는 바꾸지 않는다.
6. `계약 조회·수정` 화면에서는 계약 상태뿐 아니라 가계약 진행일·정식 계약일·임대차 기간·내부정보를 이어서 수정한다. 해지·만료는 기록을 삭제하지 않고 상태만 바꾼다. 잘못 등록한 계약은 확인 후 완전 삭제할 수 있으며, 매물과 상담 기록은 남긴다.

계약 완료는 실제 확인 후에만 선택한다. 계약자 연락처와 계약금·가계약금·잔금은 내부정보로 관리한다. 여러 입금 내역이나 결제 처리는 관리하지 않으며, 계약서 파일도 이 흐름에 넣지 않는다.

# 13-1. 상담관리 흐름

1. 상담관리 탭에서 `매물 상담` 또는 `일반 상담`을 선택한다.
2. 매물 상담은 건물명·지번·호수로 매물 회차를 찾아 선택한다. 일반 상담은 매물을 선택하지 않는다.
3. 고객 이름·연락처, 상담일, 상담 종류, 유입 경로, 상담 내용, 다음 연락일, 상담 상태를 입력한다. 일반·매물 상담 모두 희망 지역·방 형태·보증금·월세를 선택 입력할 수 있다.
4. 저장하면 새 상담 기록을 추가한다. 일반 상담은 나중에 맞는 매물이 정해지면 상담 상세에서 매물 회차를 연결할 수 있다.
5. 다음 연락일이 오늘이거나 지났으면 `다음 연락 필요`로 표시한다.
6. 상담이 계약으로 이어지면 계약관리 탭에서 별도 계약 기록을 등록한다.
7. 상담 조회·수정에서는 일반 상담·매물 상담 구분, 상담 상태, 상담일 시작·종료일, 다음 연락 필요 조건을 조합해 기록을 찾는다.

고객 이름·연락처는 팔로업을 위해 상담 상세에서만 관리한다. 자동 문자 발송, 방문 예약 달력, 주민번호 등 민감 개인정보는 이 흐름에서 관리하지 않는다.

- 가격 변경의 세부 이력
