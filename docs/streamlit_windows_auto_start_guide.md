# Windows 자동 로그인 PC용 Streamlit 자동 실행 안내

> 작성일: 2026-08-06  
> 대상: Windows에 자동 로그인되는 메인 PC  
> 목적: PC를 켠 뒤 Streamlit을 자동 실행하고, Tailscale Serve의 기존 HTTPS 주소로 다른 업무용 PC가 접속할 수 있게 한다.

## 1. 동작 기준

메인 PC는 전원을 켤 때 지정된 Windows 계정으로 자동 로그인되는 환경이다. 따라서 작업 스케줄러의 **로그온할 때** 트리거를 사용한다. 사람이 로그인 화면에서 별도 조작할 필요는 없다.

```text
메인 PC 전원 켜짐
  → Windows 자동 로그인
  → 30초 대기
  → Streamlit 자동 실행 (127.0.0.1:8501)
  → Tailscale Serve가 기존 HTTPS 주소로 중계
  → 사용자 PC에서 브라우저로 접속
```

- Streamlit은 외부 또는 사내 LAN에 직접 공개하지 않고 `127.0.0.1:8501`에서만 실행한다.
- Tailscale Serve 설정은 별도로 한 번 완료되어 있고, 재부팅 후에도 유지되는 것을 전제로 한다.
- 자동 로그인에 실패하여 Windows 로그인 화면에 멈추면 이 작업은 실행되지 않는다.

관련 연결 방식과 Serve 설정은 [메인 PC Tailscale 연결 실행 계획서](tailscale_main_pc_connection_plan.md)를 따른다.

## 2. 배치 파일 만들기

`C:\realestate-main` 폴더에 아래 이름의 파일을 만든다.

```text
start_streamlit.bat
```

파일 확장자가 `.bat`인지 확인한다. `start_streamlit.bat.txt`가 되면 실행되지 않는다.

내용:

```bat
@echo off
cd /d C:\realestate-main
C:\realestate-main\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true
```

가상환경을 별도로 활성화하지 않고 해당 가상환경의 Python을 직접 실행하므로, 일반적인 자동 실행 환경에서 경로 문제가 적다.

## 3. 배치 파일 사전 테스트

1. 기존에 실행 중인 Streamlit 콘솔 창이 있으면 먼저 종료한다.
2. `start_streamlit.bat`를 더블클릭한다.
3. 검은 콘솔 창이 열려 있고 오류 없이 Streamlit이 실행되는지 확인한다.
4. 메인 PC 브라우저에서 아래 주소를 연다.

   ```text
   http://127.0.0.1:8501
   ```

정상 화면이 열리면 콘솔 창을 닫아 테스트 실행을 종료한다. 이 창을 닫으면 Streamlit도 종료된다.

## 4. 작업 스케줄러 등록

Windows 검색에서 `작업 스케줄러`를 열고, 오른쪽 메뉴에서 **작업 만들기**를 선택한다.

### 일반 탭

| 항목 | 값 |
|---|---|
| 이름 | `RealEstate Streamlit` |
| 실행 방식 | `사용자가 로그온할 때만 실행` |
| 권한 | `가장 높은 수준의 권한으로 실행` 체크 권장 |

이 PC에서는 Windows 자동 로그인이 실제 로그온으로 처리되므로 위 실행 방식을 유지한다. Streamlit 자체에 관리자 권한이 필수는 아니지만, 권한 문제를 줄이기 위해 체크해 둘 수 있다.

### 트리거 탭

**새로 만들기**에서 다음을 설정한다.

| 항목 | 값 |
|---|---|
| 작업 시작 | `로그온할 때` |
| 사용자 | 메인 PC가 자동 로그인하는 Windows 계정 |
| 작업 지연 | `30초` |

30초 지연은 Tailscale과 네트워크 서비스가 준비될 시간을 준다.

### 동작 탭

**새로 만들기**에서 다음을 입력한다.

| 항목 | 값 |
|---|---|
| 프로그램/스크립트 | `C:\Windows\System32\cmd.exe` |
| 인수 추가 | `/c "C:\realestate-main\start_streamlit.bat"` |
| 시작 위치 | `C:\realestate-main` |

### 조건 탭

메인 PC가 노트북이면 다음 조건을 해제한다.

```text
컴퓨터의 AC 전원이 켜져 있는 경우에만 작업 시작
```

데스크톱 PC라면 기본값을 유지해도 된다.

### 설정 탭

다음 항목을 설정한다.

- `요청 시 작업 실행 허용` 체크
- `예약된 시작 시간을 놓친 경우 가능한 즉시 작업 실행` 체크
- `작업이 이미 실행 중인 경우 다음 규칙 적용`: `새 인스턴스를 시작하지 않음`

이 중복 실행 방지는 작업 스케줄러가 시작한 프로세스끼리 적용된다. 이미 수동 실행한 Streamlit이 있다면 8501 포트 충돌이 날 수 있으므로, 수동 실행 창은 종료한 뒤 작업을 테스트한다.

## 5. 작업 스케줄러 테스트와 완료 기준

1. 작업 목록에서 `RealEstate Streamlit`을 선택한다.
2. 오른쪽의 **실행**을 누른다.
3. 메인 PC에서 `http://127.0.0.1:8501`이 열리는지 확인한다.
4. 사용자 PC에서 기존 Tailscale Serve HTTPS 주소가 열리는지 확인한다.

예시:

```text
https://desktop-igfd864.tailf84215.ts.net
```

완료 확인표:

| 확인 항목 | 결과 |
|---|---|
| 배치 파일 더블클릭으로 로컬 화면이 열림 | [ ] |
| 작업 스케줄러에서 수동 실행 후 로컬 화면이 열림 | [x] |
| 메인 PC 재부팅·자동 로그인 후 약 30초 안에 로컬 화면이 열림 | [ ] |
| 사용자 PC에서 기존 HTTPS 주소가 열림 | [x] |
| `tailscale serve status`에서 `127.0.0.1:8501` 중계가 확인됨 | [ ] |

## 6. 접속이 안 될 때

다음 순서로 확인한다.

1. 메인 PC가 켜졌고 Windows 자동 로그인이 완료되었는가?
2. 작업 스케줄러의 `RealEstate Streamlit` 작업에서 마지막 실행 결과가 성공으로 표시되는가?
3. 메인 PC에서 `http://127.0.0.1:8501`이 열리는가?
4. 8501 포트를 사용하는 기존 Streamlit 실행 창이 남아 있지 않은가?
5. 메인 PC의 Tailscale이 연결됨 상태인가?
6. `tailscale serve status`에서 Serve 대상이 `127.0.0.1:8501`로 표시되는가?
7. 사용자 PC의 Tailscale이 연결됨 상태인가?

Tailscale Serve 설정을 다시 만들거나 초기화하는 방법은 기존 연결 계획서의 절차를 따른다. 문제 해결을 위해 Streamlit을 `0.0.0.0`에 바인딩하거나 공유기 포트 포워딩·Tailscale Funnel을 사용하지 않는다.

## 7. 적용 기록

### 2026-08-06 적용 내용

- `C:\realestate-main\start_streamlit.bat`를 만들었다.
- Windows 작업 스케줄러에 `RealEstate Streamlit` 작업을 등록했다.
- 작업은 `DESKTOP-IGFD864\W10` 계정의 로그온 시 30초 뒤 실행되며, 최고 권한·요청 시 실행 허용·예약 시작 누락 시 가능한 즉시 실행·중복 인스턴스 시작 안 함으로 설정했다.
- 배치파일이 사용하는 가상환경의 Streamlit 버전은 `1.51.0`으로 확인했다.

### 남은 실제 확인

- 기존 수동 Streamlit이 `127.0.0.1:8501`을 사용 중이어서 첫 예약 작업 수동 실행은 포트 충돌로 종료됐다. 기존 프로세스를 정상 종료한 뒤 `RealEstate Streamlit` 작업을 다시 실행했다.
- 재실행 뒤 `127.0.0.1:8501`이 수신 중이고, `http://127.0.0.1:8501`의 HTTP 응답 코드 `200`을 확인했다. 작업 스케줄러의 `267009`는 실패가 아니라 작업이 계속 실행 중임을 뜻한다.
- 남은 확인은 메인 PC 재부팅 뒤 자동 로그인·30초 지연 후 동일한 로컬 주소와 서브 PC의 기존 HTTPS 주소가 모두 열리는지 확인하는 것이다.
- 이 환경에서는 `tailscale` 명령이 PATH에 없어 `tailscale serve status` 명령으로는 아직 중계 대상을 확인하지 못했다. 기존 HTTPS 주소의 실제 접속으로 확인한다.
