# 부동산 매물관리 도구 PRD v1.1

> 문서 목적: 원룸·투룸 매물의 반복 등록과 확인 업무를 줄이기 위한 사무실 내부용 매물관리 도구의 1차 요구사항을 정의한다.

## 1. 제품 개요

### 1.1 배경

충남 아산시 배방읍 북수리 권역의 중개업무에서는 원룸·투룸의 계약 기간이 짧고, 같은 건물·같은 호실이 반복적으로 매물로 나온다. 현재는 엑셀에 건물명, 호수, 가격, 입주 가능일, 비밀번호, 메모 등을 기록하고 있으나, 같은 정보를 다시 입력하거나 최신 여부를 확인하는 시간이 누적된다.

### 1.2 해결할 문제

- 동일 건물·호실이 다시 나올 때 주소, 구조, 옵션 등 기존 정보를 다시 입력한다.
- 가격·입주일·상태처럼 이번에 바뀐 정보와 고정정보가 엑셀 한 줄에 섞인다.
- 사진 촬영, 비밀번호 재확인, 퇴실 예정 등 오늘 해야 할 확인 업무가 목록 안에서 묻힌다.
- 담당자가 바뀌어도 기존 매물 기록을 이어서 쓰기 어렵다.

### 1.3 제품 정의

이 도구는 외부 고객용 서비스나 SaaS가 아니다. 사무실 내부에서 사용하는 **엑셀 개선형 매물장**이다.

핵심 기능은 다음 한 문장으로 정의한다.

> 건물과 호실 정보는 한 번 저장하고, 같은 호실이 다시 매물로 나오면 이번 가격·입주일·상태만 입력해 새 매물 이력으로 남긴다.

### 1.4 성공 기준

- 매물 신규·재등록 시간이 기존 엑셀 입력보다 짧아진다.
- 기존 호실 재등록 시 주소·구조·옵션을 다시 타이핑하지 않는다.
- 오늘 확인해야 할 매물을 목록 상단에서 바로 확인한다.
- 과거 가격과 매물 이력을 잃지 않는다.
- 재현님이 업무를 떠나도 다른 직원이 데이터와 프로그램을 이어서 사용한다.

## 2. 사용자와 운영 환경

| 구분 | 정의 |
|---|---|
| 주요 사용자 | 사무실 내 중개보조원 1~2명 |
| 사용 장소 | 사무실 내부 네트워크 |
| 사용 기기 | 사무실 PC 중심, 브라우저 사용 |
| 로그인 | 1차 버전에서는 미구현 |
| 외부 공개 | 금지. 인터넷 공개 주소를 제공하지 않음 |
| 동시 수정 | 빈도가 매우 낮다고 가정. 같은 매물의 동시 편집은 1차 범위에서 별도 공동편집 기능을 만들지 않음 |
| 기존 데이터 | 기존 `구재현` 시트는 이관하지 않으며, 새 도구 사용 시점부터 직접 등록 |

### 2.1 권장 운영 구조

```text
사무실 메인 PC
├─ 매물관리 화면
├─ SQLite 데이터 파일
└─ 일일 백업 파일

사무실 내 사용자 PC
└─ 브라우저로 메인 PC의 화면 접속
```

SQLite 파일은 메인 PC에만 둔다. 네트워크 공유폴더나 Google Drive 동기화 폴더에서 SQLite 파일을 여러 PC가 직접 여는 방식은 사용하지 않는다.

## 3. 범위

### 3.1 1차 포함 범위

- 건물 신규등록 및 검색
- 호실 신규등록 및 검색
- 동일 호실의 새 매물 회차 등록
- 현재 매물 목록 조회·필터·간단 수정
- 오늘 확인할 매물 목록
- 건물·호실의 고정정보 조회·수정
- 과거 매물 회차 조회
- 사진 폴더 링크 연결
- 엑셀 내보내기 및 SQLite 백업

### 3.2 1차 제외 범위

- 고객용 홈페이지·공개 매물 페이지
- 외부 고객 로그인, 결제, 알림톡, 자동 광고 등록
- 복잡한 권한관리와 사용자별 권한
- 고객 상담·방문·계약의 상세 관리 화면
- 계약서·신분증 등 파일 원본 저장
- 여러 지점·모바일 상시 접속을 위한 클라우드 운영
- 화려한 그래프, 카드 중심 UI, 애니메이션

### 3.3 향후 확장 범위

- 고객 문의 및 상담 이력
- 방문 일정과 후속 연락 일정
- 계약 진행, 계약금, 잔금, 입주 완료 관리
- 광고 등록 상태 및 광고 문구 생성 보조
- 사진 촬영 요청 및 사진 관리

향후 기능도 매물 회차를 기준으로 연결한다. 화면은 CRM이나 ERP처럼 확장하지 않고, 매물 상세에서 간단한 기록표를 추가하는 방식으로 발전시킨다.

## 4. 핵심 업무 원칙

1. **최초 입력은 최소화한다.** 모르는 값은 비워두거나 `확인 필요`로 남긴다.
2. **고정정보와 변동정보를 분리한다.** 건물·호실 정보와 이번 매물 조건을 한 줄에 섞지 않는다.
3. **과거 기록을 덮어쓰지 않는다.** 같은 호실이 재등록되면 새 매물 회차를 만든다.
4. **표 중심으로 빠르게 본다.** 엑셀처럼 한눈에 목록을 보고 필요한 행을 수정한다.
5. **내부정보와 광고정보를 분리한다.** 비밀번호·열쇠 위치·연락처·내부 메모는 외부 문구나 공유 화면에 노출하지 않는다.
6. **오늘 할 행동을 우선 표시한다.** 정보가 부족하거나 재확인이 필요한 매물은 목록에서 놓치지 않게 한다.

## 5. 데이터 구분

### 5.1 건물 공통정보

여러 호실에 공통으로 적용되는 정보다.

- 건물명
- 지번주소, 도로명주소
- 공동현관 비밀번호
- 엘리베이터, 주차, CCTV
- 반려동물, 전입신고, 단기계약 가능 여부
- 관리비 공통 조건 또는 포함 항목
- 건물 공통 옵션과 광고 장점
- 내부 확인사항
- 최초 등록일, 마지막 확인일, 정보 상태

### 5.2 호실 고정정보

같은 호실이 다시 나올 때 대체로 유지되는 정보다.

- 호수, 층, 룸 형태
- 분리형 여부, 방향, 면적 또는 면적 미확인
- 베란다, 붙박이장, 양창, 수납공간 등 구조 특징
- 호실별 옵션
- 방문 방법과 방문 비밀번호
- 구조상 장점·단점, 시설 내부 메모
- 사진 폴더 링크

### 5.3 매물 회차 변동정보

동일 호실이라도 매물로 나올 때마다 새로 기록하는 정보다.

- 접수일, 매물 상태
- 보증금, 월세, 관리비
- 퇴실 예정일, 입주 가능일, 즉시입주 여부
- 계약 가능 기간 및 단기계약의 이번 조건
- 청소·도배·수리 상태
- 사진 촬영 상태, 광고 상태
- 이번 매물에만 해당하는 특이사항
- 마지막 확인일, 재확인 예정일

## 6. 핵심 사용자 흐름

### 6.1 흐름 A: 건물 신규등록 → 호실 신규등록 → 첫 매물 등록

**상황:** 시스템에 없는 건물의 매물이 처음 접수됐다.

1. 사용자가 건물명 또는 지번을 검색한다.
2. 검색 결과가 없으면 `새 건물 등록`을 선택한다.
3. 건물명과 지번을 입력한다. 공동현관 비밀번호와 건물 메모는 선택 입력이다.
4. 이어서 호수, 룸 형태를 입력한다.
5. 상태, 보증금, 월세, 입주 가능 시점만 입력한다.
6. 저장하면 건물·호실·첫 매물 회차가 함께 생성된다.

**필수 입력:** 건물명, 지번, 호수, 매물 상태, 보증금, 월세, 입주 가능 시점 또는 퇴실 예정일.

### 6.2 흐름 B: 기존 건물의 새 호실 등록

**상황:** 건물은 등록돼 있지만 해당 호실은 처음 나온다.

1. 건물명 또는 지번으로 기존 건물을 선택한다.
2. 건물 공통정보를 요약 표시한다.
3. 호수와 룸 형태를 입력한다.
4. 이번 매물의 상태·가격·입주일을 입력한다.
5. 저장하면 새 호실과 첫 매물 회차가 생성된다.

### 6.3 흐름 C: 같은 호실 재등록

**상황:** 과거에 등록한 호실이 다시 매물로 나왔다.

1. 건물 검색 후 기존 호실을 선택한다.
2. 건물·호실의 고정정보를 자동으로 불러온다.
3. 이전 보증금·월세·관리비를 참고값으로 보여준다.
4. 사용자는 이번 매물 상태, 가격, 입주 가능 시점만 새로 확인·입력한다.
5. 비밀번호·옵션·사진·관리비 등 변경 가능성이 높은 항목은 `기존값 유지 / 수정 / 확인 필요` 중 하나를 선택할 수 있다.
6. `새 매물 회차로 등록`을 누르면 과거 이력은 유지되고 새 매물 기록이 생성된다.

### 6.4 흐름 D: 오늘 해야 할 일 처리

1. 사용자가 `오늘의 매물 현황`을 연다.
2. 재확인 필요, 사진 필요, 퇴실 예정, 광고 준비 등 행동이 필요한 매물만 먼저 본다.
3. 행을 선택해 필요한 값 또는 상태를 수정한다.
4. 처리 완료한 항목은 목록에서 자동 제외되거나 상태가 갱신된다.

## 7. 화면 요구사항

### 7.1 화면 1: 오늘의 매물 현황

목적은 대시보드 장식이 아니라, 오늘 처리할 매물을 빠르게 찾는 것이다.

상단에는 아래 숫자만 간단히 표시한다.

- 오늘 새 접수
- 퇴실 예정
- 재확인 필요
- 사진 촬영 필요
- 광고 준비 필요

아래에는 표 형태의 목록을 제공한다.

| 상태 | 건물명 | 호수 | 구조 | 보증금 | 월세 | 입주 가능 | 해야 할 일 | 메모 |
|---|---|---|---|---:|---:|---|---|---|

필터: 상태, 룸 형태, 사진 필요 여부, 재확인 필요 여부, 입주 가능 시점, 건물명·지번 검색.

### 7.2 화면 2: 매물 등록·수정

한 화면에서 검색 → 자동 불러오기 → 저장이 이어져야 한다.

기본 입력 영역에는 아래만 노출한다.

- 건물 검색 또는 신규 입력
- 호실 선택 또는 신규 입력
- 매물 상태
- 보증금, 월세
- 입주 가능 시점
- 메모

`상세정보`를 펼쳤을 때만 관리비, 방향, 옵션, 주차, 반려동물, 계약기간, 청소·도배·수리, 사진·광고 상태 등을 표시한다.

버튼 명칭은 상황에 맞게 분명히 표시한다.

- `건물·호실·첫 매물 등록`
- `새 매물 회차로 등록`
- `호실 기본정보 수정`
- `이번 매물만 수정`

### 7.3 화면 3: 건물·호실 관리

건물 검색 후 다음을 한 화면에서 확인한다.

- 건물 공통정보
- 등록된 호실 목록
- 선택한 호실의 고정정보
- 해당 호실의 과거 매물 이력
- 비어 있거나 오래된 정보

매물 이력은 날짜, 상태, 보증금, 월세, 입주 가능일, 종료일 정도를 표로 보여준다.

## 8. 상태값

### 8.1 1차 매물 상태

- 확인 필요
- 퇴실 예정
- 공실
- 광고 가능
- 계약 진행 중
- 계약 완료
- 보류
- 종료

목록에서 매물이 사라졌다는 이유만으로 `계약 완료`로 자동 변경하지 않는다. 먼저 `확인 필요`로 표시하고 실제 상태를 확인한다.

### 8.2 정보 상태

- 기본등록: 최소정보만 있음
- 일부확인: 업무 중 일부 정보 보완
- 확인완료: 안내·광고에 필요한 정보가 충분함
- 재확인 필요: 오래됐거나 변경 가능성이 높음

## 9. 기능 요구사항

### FR-01. 건물 검색과 자동완성

- 건물명·지번·도로명주소 일부 입력으로 기존 건물을 찾을 수 있어야 한다.
- 검색 결과에는 건물명, 지번, 등록 호실 수를 보여준다.
- 기존 건물 선택 시 공통정보를 자동으로 불러온다.

### FR-02. 호실 검색과 자동 불러오기

- 선택한 건물 안에서 호실을 선택할 수 있어야 한다.
- 기존 호실 선택 시 구조·방향·옵션·사진 링크 등 고정정보를 불러온다.
- 이전 매물의 가격·입주일은 참고값으로만 보여주며, 현재 값으로 자동 확정하지 않는다.

### FR-03. 새 매물 회차 생성

- 기존 호실의 가격·상태·입주일을 수정할 때 과거 매물 기록을 덮어쓰지 않는다.
- `새 매물 회차로 등록`은 새 이력 행을 생성해야 한다.
- 새 회차에는 접수일과 생성일을 자동 기록한다.

### FR-04. 고정정보와 이번 정보의 수정 구분

- 사용자가 옵션, 비밀번호, 주차 등 기존값을 바꾸려 할 때 `호실/건물 기본정보 수정` 또는 `이번 매물에만 적용`을 선택할 수 있어야 한다.
- 매물 상태, 가격, 입주일은 기본적으로 이번 매물 회차에 기록한다.

### FR-05. 확인 필요 업무 표시

- 다음 조건의 매물을 `오늘 처리할 매물`에서 볼 수 있어야 한다.
  - 재확인 예정일 도래
  - 사진 촬영 필요
  - 퇴실 예정
  - 청소·도배·수리 확인 필요
  - 광고 준비 필요
  - 가격 또는 입주일 확인 필요

### FR-06. 표 중심 빠른 수정

- 현재 매물 목록에서 상태, 가격, 입주 가능일, 메모 등 자주 바뀌는 값은 빠르게 수정할 수 있어야 한다.
- 표는 기본적으로 한 화면에 충분한 행을 보여주고, 가로 스크롤을 최소화한다.
- 목록에서 내부 비밀번호는 기본 표시하지 않는다.

### FR-07. 사진 링크

- 건물 또는 호실별 Google Drive 사진 폴더 링크를 저장할 수 있어야 한다.
- 사진 파일 자체는 SQLite에 저장하지 않는다.

### FR-08. 엑셀 내보내기

- 기존 `구재현` 시트를 시스템으로 가져오는 기능은 만들지 않는다.
- 새 도구 사용 시점부터 필요한 건물·호실·매물을 직접 등록한다.
- 현재 매물, 건물, 호실, 매물 이력을 엑셀로 내보낼 수 있어야 한다.

### FR-09. 백업과 인수인계

- SQLite 원본 파일을 하루 1회 백업한다.
- 사람이 확인 가능한 엑셀 백업을 함께 생성한다.
- 프로그램 폴더와 SQLite 파일만으로 다른 PC에서 이어서 운영할 수 있어야 한다.

## 10. 정보보호 원칙

다음 정보는 내부정보로 분류한다.

- 공동현관 비밀번호
- 방문 비밀번호
- 열쇠 위치
- 임대인·세입자 연락처
- 내부 확인사항

요구사항:

- 내부정보는 매물 목록의 기본 열에 노출하지 않는다.
- 향후 광고 문구 생성이나 엑셀 외부공유 기능에서 내부정보를 제외한다.
- 프로그램은 사무실 내부망에서만 운영하며, 공개 인터넷에 배포하지 않는다.

## 13. 수용 기준

다음 시나리오가 실제로 가능하면 1차 버전의 핵심 목적을 달성한 것으로 본다.

1. 사용자가 `대성빌 / 북수리 1026 / 302호`를 처음 등록할 수 있다.
2. 다음번 `대성빌 302호`가 다시 나왔을 때 건물·호실 정보를 검색으로 불러올 수 있다.
3. 재등록 시 보증금·월세·입주일·상태만 바꿔 새 매물 회차로 저장할 수 있다.
4. 과거 302호의 가격과 상태 기록을 확인할 수 있다.
5. 사진 필요·재확인 필요 매물을 한 화면에서 찾을 수 있다.
6. 공동현관·방문 비밀번호는 기본 매물 목록에서 보이지 않는다.
7. 현재 매물 목록을 엑셀로 내려받을 수 있다.
8. 메인 PC의 프로그램 폴더와 데이터 파일을 다른 직원에게 넘겨 운영을 이어갈 수 있다.

## 14. 개발 순서

### 단계 1: 실제 등록 흐름 검증

- 대성빌 302호 한 건을 기준으로 건물 신규등록, 호실 신규등록, 재등록을 구현한다.
- 실제 입력 시간이 엑셀보다 줄어드는지 검증한다.

### 단계 2: 현재 매물 목록과 오늘 할 일

- 상태·입주일·사진 필요·재확인 필요 필터를 붙인다.
- 표에서 자주 쓰는 값의 빠른 수정을 구현한다.

### 단계 3: 백업과 내보내기

- 현재 데이터를 엑셀로 내보내는 기능을 추가한다.
- SQLite 일일 백업을 추가한다.

### 단계 4: 사용 후 보완

- 실제로 자주 쓰는 항목만 기본 화면에 남긴다.
- 거의 입력하지 않는 항목은 상세정보로 이동한다.
- 상담·계약 기능은 매물 운영 흐름이 안정된 뒤 붙인다.

## 15. 미결정 사항

아래 항목은 실제 사례를 검증한 후 확정한다.

- 최종 매물 상태값과 상태 전환 규칙
- 관리비 및 포함 항목의 입력 방식
- 단기계약 조건과 단기 가격 입력 방식

- 광고 상태를 1차에 포함할지 여부

## 부록: 1차 화면 설계 원칙

- 기본 화면은 흰 바탕 또는 낮은 대비의 단순 표를 사용한다.
- 행 간격과 글자 크기는 엑셀보다 읽기 쉽게 하되, 한 화면에 충분한 매물이 보이게 한다.
- 카드·차트·장식은 최소화한다.
- 중요한 것은 건물 검색, 호실 자동완성, 가격 입력, 상태 확인, 저장 버튼의 위치가 항상 일정한 것이다.
- 화면의 모든 요소는 “사용자가 다음에 어떤 업무를 처리할지”를 빠르게 결정하도록 돕는 경우에만 둔다.
